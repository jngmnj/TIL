# 1강. 컴파일러의 개요

- 학습일: 2026-08-23
- 과목: 컴파일러구성
- 주제: 컴파일러의 개념, 번역기 종류, 컴파일러 구조와 실행 예

## 핵심 요약

컴파일러는 사람이 작성한 고급 언어 프로그램을 컴퓨터가 실행할 수 있는 저급 언어로 번역하는 시스템 프로그램이다. 컴파일러를 정확하게 만들기 위해서는 어휘, 구문, 의미를 단계적으로 분석하고, 중간 코드 생성과 최적화, 목적 코드 생성을 거쳐야 한다.

컴파일러 구성 과목은 단순한 프로그래밍 실습이 아니라, 프로그램 언어를 정확하게 번역하기 위한 이론과 구현 방법을 다룬다.

## 학습 방향

컴파일러 구성은 정의와 정리가 수학적 기호로 제시되는 경우가 많아 어렵게 느껴질 수 있다. 강의에서는 다음 방식으로 공부하는 것이 좋다고 설명한다.

1. 정의와 정리를 바로 외우기보다 예제를 먼저 본다.
2. 예제를 이해한 뒤 정의와 정리를 다시 읽는다.
3. 출석 수업이나 질문을 통해 어려운 개념을 보완한다.
4. 시험 준비는 강의 흐름을 따라 학습한 뒤 워크북의 출제 유형을 확인한다.

## 컴파일러란

컴파일러는 고급 언어로 작성된 프로그램을 기계어나 어셈블리어 같은 저급 언어로 번역하는 시스템 프로그램이다.

| 구분 | 설명 |
| --- | --- |
| 고급 언어 | 사람이 이해하기 쉬운 프로그래밍 언어 |
| 저급 언어 | 컴퓨터 하드웨어에 가까운 언어 |
| 시스템 프로그램 | 컴퓨터 사용에 필요한 기본 소프트웨어 |

컴퓨터는 결국 0과 1로 된 기계어를 실행하므로, 사람이 작성한 프로그램은 실행 가능한 형태로 번역되어야 한다.

## 번역기의 종류

| 번역기 | 입력 | 출력 | 특징 |
| --- | --- | --- | --- |
| 컴파일러 | 고급 언어 | 저급 언어 | 번역 후 실행 |
| 어셈블러 | 어셈블리어 | 기계어 | 기계어에 가까운 언어를 변환 |
| 인터프리터 | 고급 언어 | 실행 결과 | 한 줄씩 번역하며 실행 |
| 프리프로세서 | 고급 언어 | 다른 고급 언어 | 기존 컴파일러가 처리할 수 있게 사전 변환 |

실제 컴파일러는 고급 언어를 바로 기계어로 바꾸기보다 어셈블리어 수준까지 번역하고, 이후 어셈블러가 기계어로 바꾸는 방식으로 구현되는 경우가 많다.

## 컴파일러와 인터프리터

| 구분 | 컴파일러 | 인터프리터 |
| --- | --- | --- |
| 실행 방식 | 전체를 먼저 번역한 뒤 실행 | 한 줄씩 번역하며 실행 |
| 실행 속도 | 빠른 편 | 상대적으로 느린 편 |
| 대화식 실행 | 어렵다 | 가능하다 |
| 융통성 | 낮은 편 | 높은 편 |
| 반복문 처리 | 효율적 | 반복마다 번역이 필요해 비효율적 |
| 예시 언어 | Fortran, COBOL, Pascal, C, Java | Lisp, BASIC 등 |

현대 언어는 컴파일러 방식과 인터프리터 방식을 혼합해서 사용하는 경우도 많다.

## 컴파일러가 어려운 이유

컴파일러는 프로그램 언어를 정확하게 번역해야 한다. 번역 과정에 작은 오류가 있으면 실행 결과 전체가 잘못될 수 있으므로, 단순 구현보다 이론적 기반이 중요하다.

초기 Fortran 컴파일러는 구현에 매우 큰 노력이 필요했다. 이후에는 문법 이론, 오토마타, 구문 분석 기법 등이 발전하면서 컴파일러 제작 방법이 체계화되었다.

## 컴파일러의 논리적 구조

컴파일러의 논리적 구조는 번역 과정을 개념적으로 나눈 것이다.

| 단계 | 역할 |
| --- | --- |
| 어휘 분석 | 프로그램을 토큰 단위로 나누고 각 어휘가 올바른지 확인 |
| 구문 분석 | 토큰들이 문법 규칙에 맞게 배열되었는지 확인 |
| 의미 분석 | 문장이 의미적으로 올바른지 확인 |
| 중간 코드 생성 | 기계와 독립적인 중간 표현 생성 |
| 코드 최적화 | 더 효율적인 코드로 개선 |
| 목적 코드 생성 | 실제 기계나 어셈블리어에 맞는 코드 생성 |

영어 문장을 번역할 때 단어를 확인하고, 문법 구조를 보고, 의미를 해석하는 것처럼 컴파일러도 프로그램을 단계적으로 분석한다.

## 어휘 분석

어휘 분석은 프로그램을 최소 구성 단위인 토큰으로 나누는 과정이다.

예를 들어 다음과 같은 문장이 있다고 하자.

```text
abc := 2 * 3.14 + abc / 2;
```

이 문장은 다음과 같은 토큰으로 나눌 수 있다.

| 토큰 | 종류 |
| --- | --- |
| `abc` | 식별자 |
| `:=` | 치환 연산자 |
| `2` | 정수 상수 |
| `*` | 곱셈 연산자 |
| `3.14` | 실수 상수 |
| `+` | 덧셈 연산자 |
| `/` | 나눗셈 연산자 |
| `;` | 구분자 |

식별자와 상수도 규칙을 가진다. 예를 들어 식별자는 보통 영문자로 시작하고 이후에는 문자나 숫자가 올 수 있다.

## 구문 분석

구문 분석은 토큰의 배열이 문법적으로 올바른지 검사한다. 위 예시는 치환문으로 볼 수 있다.

```text
식별자 := 식;
```

오른쪽의 식은 식별자, 상수, 연산자로 구성된다. 식과 식을 더하거나 곱해도 다시 식이 되므로, 문법 규칙에 따라 올바른 문장인지 판단할 수 있다.

## 의미 분석과 코드 생성

의미 분석은 문장이 실제로 무엇을 뜻하는지 확인한다. 예시 문장은 `2 * 3.14 + abc / 2`의 계산 결과를 `abc`에 저장하라는 의미다.

이 의미를 바탕으로 컴파일러는 중간 코드나 목적 코드를 만든다.

## 물리적 구조와 패스

물리적 구조는 컴파일러를 실제로 어떻게 구현할지에 대한 구조다. 구현 단위를 패스라고 한다.

| 구조 | 장점 | 단점 |
| --- | --- | --- |
| 1패스 컴파일러 | 번역 속도가 빠름 | 기계 의존적, 최적화 어려움, 백패칭 문제 |
| 2패스 컴파일러 | 기계 독립성, 이식성, 최적화에 유리 | 실행 속도가 상대적으로 느림 |

백패칭은 조건문이나 분기문처럼 나중에 목적지 주소를 알 수 있는 코드를 먼저 비워두고, 이후 다시 채워 넣는 과정을 말한다.

## 컴파일러 실행 예

다음 치환문을 어셈블리 코드로 번역한다고 가정한다.

```text
abc := 2 * 3.14 + abc / 2;
```

연산자 우선순위에 따라 곱셈과 나눗셈을 먼저 처리하고, 마지막에 덧셈 결과를 `abc`에 저장한다.

예시적인 목적 코드 흐름은 다음과 같다.

```text
LOAD 201
MULTIPLY 150
STORE 160
LOAD 200
DIVIDE 201
ADD 160
STORE 200
```

| 주소 | 의미 |
| --- | --- |
| `150` | 상수 `3.14`가 저장된 위치 |
| `160` | 임시 작업용 기억 장소 |
| `200` | 변수 `abc`의 위치 |
| `201` | 변수 또는 상수 `2`의 위치 |

이 과정에서 레지스터와 임시 기억 장소를 사용해 연산 결과를 보관한다.

## 기호표와 스택

컴파일러는 토큰을 처리하면서 기호표와 스택을 사용한다.

| 자료구조 | 역할 |
| --- | --- |
| 기호표 | 식별자, 상수, 주소 등 정보를 저장 |
| 피연산자 스택 | 식별자나 상수 같은 피연산자를 저장 |
| 연산자 스택 | `+`, `*`, `/`, `:=` 같은 연산자를 저장 |

연산자 스택에서는 우선순위를 비교해 어떤 연산을 먼저 코드로 생성할지 결정한다. 곱셈과 나눗셈은 덧셈보다 우선순위가 높으므로 먼저 처리된다.

## 최적화

최적화는 같은 의미를 유지하면서 더 효율적인 코드로 바꾸는 과정이다.

예를 들어 덧셈은 교환 법칙이 성립하므로 계산 순서를 조정할 수 있다. 이를 통해 불필요한 임시 기억 장소 사용이나 `LOAD`, `STORE` 명령을 줄일 수 있다.

최적화의 목표는 다음과 같다.

- 명령어 수 줄이기
- 기억 장소 사용 줄이기
- 실행 시간 줄이기
- 기계 특성에 맞는 효율적인 코드 생성

## 정리

컴파일러는 고급 언어를 저급 언어로 번역하는 시스템 프로그램이다. 컴파일러는 어휘 분석, 구문 분석, 의미 분석, 중간 코드 생성, 최적화, 목적 코드 생성의 논리적 단계를 거친다.

실제 구현에서는 1패스 또는 2패스 구조를 선택할 수 있으며, 기호표와 스택 같은 자료구조를 활용해 토큰과 연산자를 처리한다. 다음 강의부터는 이러한 분석을 가능하게 하는 문법과 오토마타를 본격적으로 다룬다.
