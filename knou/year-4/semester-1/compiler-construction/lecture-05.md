# 5강. 어휘분석기의 설계와 구현

- 학습일: 2026-08-27
- 과목: 컴파일러구성
- 주제: 어휘분석기 설계, 토큰 분류, Lex를 이용한 어휘분석기 생성

## 핵심 요약

어휘분석기는 원시 프로그램을 읽고 문법적으로 의미 있는 최소 단위인 토큰으로 분리한다. 앞에서 배운 정규문법, 정규 표현, 유한 오토마타는 어휘분석기를 설계하기 위한 이론적 기반이 된다.

어휘분석기는 직접 프로그래밍 언어로 구현할 수도 있지만, Lex나 Flex 같은 어휘분석기 생성기를 사용하면 정규 표현만으로 자동 생성할 수 있다.

## 어휘분석기의 역할

어휘분석기는 원시 프로그램을 입력으로 받아 토큰열을 출력한다.

```text
원시 프로그램 -> 어휘분석기 -> 토큰열
```

토큰은 프로그램 언어 문장을 구성하는 문법적으로 의미 있는 최소 단위다. 자연어에서 단어가 의미 단위가 되는 것처럼, 프로그래밍 언어에서는 식별자, 상수, 연산자, 구분자 등이 토큰이 된다.

## 토큰 분류 예

다음 치환문을 생각해보자.

```text
abc := x * 314 + abc / y;
```

어휘분석을 하면 다음과 같은 토큰으로 분리할 수 있다.

| 순서 | 어휘 | 토큰 종류 |
| --- | --- | --- |
| 1 | `abc` | 식별자 |
| 2 | `:=` | 치환 연산자 |
| 3 | `x` | 식별자 |
| 4 | `*` | 곱셈 연산자 |
| 5 | `314` | 상수 |
| 6 | `+` | 덧셈 연산자 |
| 7 | `abc` | 식별자 |
| 8 | `/` | 나눗셈 연산자 |
| 9 | `y` | 식별자 |
| 10 | `;` | 구분자 |

실제 컴파일러 내부에서는 토큰을 문자열 그대로 저장하기보다 토큰 번호와 토큰 값으로 표현한다.

```text
토큰 = (토큰 번호, 토큰 값)
```

토큰 번호는 식별자, 상수, 연산자처럼 토큰의 종류를 나타내고, 토큰 값은 심벌 테이블이나 상수 테이블에서의 위치를 나타낸다.

## 주요 토큰 종류

어휘분석기가 다루는 대표적인 토큰은 다음과 같다.

| 토큰 종류 | 예 |
| --- | --- |
| 예약어 | `if`, `then`, `else`, `while`, `do` |
| 식별자 | 변수명, 함수명 |
| 상수 | 정수, 실수, 문자열 |
| 연산자 | `+`, `-`, `*`, `/`, `:=` |
| 구분자 | `;`, `,`, `(`, `)` |

예약어는 식별자의 형태를 가질 수 있지만 언어에서 미리 의미가 정해져 있으므로 식별자와 구분해야 한다.

## 식별자 인식

식별자는 보통 다음 규칙을 따른다.

1. 첫 글자는 영문자다.
2. 두 번째 글자부터는 영문자나 숫자가 올 수 있다.

정규 표현으로 나타내면 다음과 같다.

```text
letter (letter | digit)*
```

어휘분석기는 먼저 이 규칙에 맞는 문자열을 식별자 후보로 인식한다. 그다음 예약어표를 검색해 예약어인지 확인한다.

```text
식별자 후보 -> 예약어표 검색 -> 예약어 또는 식별자
```

예를 들어 `if`가 입력되면 식별자 규칙에는 맞지만 예약어표에 존재하므로 예약어로 분류한다.

## 숫자 인식

숫자는 하나 이상의 digit이 반복되는 형태로 인식할 수 있다.

```text
digit+
```

정수만 다룬다면 digit 반복으로 충분하다. 실수까지 다루려면 소수점과 소수부를 포함하는 규칙을 추가해야 한다.

```text
digit+ "." digit+
```

숫자 토큰 역시 상수 테이블에 저장하고, 토큰 값으로 해당 위치를 가리키게 만들 수 있다.

## 연산자와 구분자 인식

연산자와 구분자는 식별자나 숫자보다 규칙이 단순하다. 대부분 고정된 기호를 비교해 인식한다.

| 어휘 | 토큰 |
| --- | --- |
| `+` | 덧셈 연산자 |
| `*` | 곱셈 연산자 |
| `/` | 나눗셈 연산자 |
| `:=` | 치환 연산자 |
| `;` | 문장 구분자 |

다만 `:`, `:=`, `<`, `<=`, `<>`처럼 한 글자와 두 글자 연산자가 섞이는 경우에는 다음 문자를 함께 확인해야 한다.

## 어휘분석기 설계 흐름

어휘분석기를 설계하는 일반적인 흐름은 다음과 같다.

1. 언어의 문법을 정의한다.
2. 토큰에 해당하는 부분을 정규문법으로 정리한다.
3. 정규문법을 정규 표현으로 바꾼다.
4. 정규 표현을 유한 오토마타로 바꾼다.
5. NFA가 있다면 DFA로 변환한다.
6. DFA를 최소화한다.
7. DFA를 프로그램으로 구현한다.

이 흐름은 다음 관계에 기반한다.

```text
정규문법 = 정규 표현 = 유한 오토마타
```

## 구현 전 고려사항

어휘분석기를 구현하기 전에는 다음 사항을 확인해야 한다.

| 고려사항 | 설명 |
| --- | --- |
| 문법의 명확성 | 토큰 규칙이 모호하지 않아야 함 |
| 상태 전이도의 순서 | 자주 등장하는 토큰을 빠르게 인식하도록 배치 |
| 구문분석기와의 연결 | 어휘분석기를 독립 실행할지 구문분석기가 호출할지 결정 |
| 수치 표현 | 정수와 실수의 내부 표현 방식 결정 |
| 처리 속도 | 문자 검사와 토큰 분석 시간을 줄이는 방법 고려 |

특히 많이 사용되는 토큰을 먼저 검사하도록 설계하면 평균 처리 시간을 줄일 수 있다.

## 직접 구현과 자동 생성

어휘분석기는 직접 구현할 수도 있고, 생성기를 사용할 수도 있다.

| 방식 | 설명 |
| --- | --- |
| 직접 구현 | C, C++, Java 같은 범용 언어로 DFA를 직접 코딩 |
| 자동 생성 | Lex, Flex 같은 도구에 정규 표현을 입력해 어휘분석기 생성 |

언어의 수가 `N`개이고 목적 기계가 `M`개라면 직접 구현할 때 이론적으로 `N × M`개의 조합이 생길 수 있다. 따라서 자동화 도구를 사용하면 개발 부담을 줄일 수 있다.

## Lex의 역할

Lex는 정규 표현으로 작성된 토큰 규칙을 입력받아 C 언어 기반의 어휘분석기 코드를 생성하는 도구다.

```text
Lex 입력 파일(.l) -> Lex -> C 코드 -> 컴파일 -> 어휘분석기 실행 파일
```

Lex는 어휘분석기를 생성하고, YACC는 구문분석기를 생성하는 도구로 함께 사용될 수 있다.

## Lex 입력 파일 구조

Lex 입력 파일은 보통 확장자 `.l`을 사용하며, 세 부분으로 구성된다.

```text
정의 부분
%%
규칙 부분
%%
사용자 부 프로그램 부분
```

| 부분 | 역할 |
| --- | --- |
| 정의 부분 | C 코드, 변수, 토큰 번호, 정규 표현 이름 정의 |
| 규칙 부분 | 정규 표현과 매칭될 때 수행할 동작 정의 |
| 사용자 부 프로그램 부분 | `main` 함수 등 보조 C 코드 작성 |

정의 부분에서는 `letter`, `digit`처럼 자주 쓰는 정규 표현을 이름으로 정의할 수 있다.

```lex
letter  [a-zA-Z]
digit   [0-9]
```

## Lex 규칙 예

식별자와 숫자 규칙은 다음처럼 작성할 수 있다.

```lex
{letter}({letter}|{digit})*  return T_IDENTIFIER;
{digit}+                    return T_NUMBER;
```

왼쪽은 정규 표현이고, 오른쪽은 해당 패턴이 인식되었을 때 실행할 C 코드다. 이 예에서는 식별자를 만나면 `T_IDENTIFIER`, 숫자를 만나면 `T_NUMBER`를 반환한다.

## Lex에서 자주 쓰는 변수

Lex가 생성한 어휘분석기에서는 다음 변수를 자주 사용한다.

| 변수 | 의미 |
| --- | --- |
| `yytext` | 현재 매칭된 문자열 |
| `yyleng` | 현재 매칭된 문자열의 길이 |
| `yylex()` | 입력에서 다음 토큰을 읽는 함수 |

예를 들어 식별자 규칙이 매칭되었을 때 `yytext`를 출력하면 실제로 인식한 식별자 이름을 확인할 수 있다.

## 예제 1: 치환문 토큰 분류

Lex로 다음 입력을 토큰별로 분류하는 어휘분석기를 만들 수 있다.

```text
abc := x * 314 + abc / y;
```

예상 출력은 다음과 같은 형태가 된다.

```text
identifier: abc
assign operator: :=
identifier: x
multiply operator: *
number: 314
add operator: +
identifier: abc
divide operator: /
identifier: y
semicolon: ;
```

이 예제는 원시 프로그램을 입력받아 식별자, 숫자, 연산자, 구분자를 구별하는 기본 어휘분석기의 구조를 보여준다.

## 예제 2: 라인, 단어, 문자 수 세기

Lex는 토큰 분류뿐 아니라 특정 패턴을 세는 프로그램도 만들 수 있다.

예를 들어 입력 문장에서 다음 값을 계산할 수 있다.

| 값 | 의미 |
| --- | --- |
| line count | 줄 수 |
| word count | 단어 수 |
| character count | 문자 수 |

공백, 탭, 줄바꿈이 아닌 연속된 문자열을 단어로 보고, 줄바꿈을 만나면 줄 수를 증가시키는 식으로 규칙을 작성한다.

## 정리

어휘분석기는 원시 프로그램을 토큰열로 바꾸는 컴파일러의 첫 단계다. 토큰 규칙은 정규문법과 정규 표현으로 정의하고, 이를 유한 오토마타로 바꾸어 직접 구현할 수 있다.

Lex 같은 생성기를 사용하면 정규 표현으로 작성한 토큰 규칙에서 어휘분석기 코드를 자동 생성할 수 있다. 따라서 직접 DFA를 일일이 구현하는 부담을 줄이고, 컴파일러 구현의 생산성을 높일 수 있다.
