## 강의 핵심 요약

1. **형식 언어**는 어떤 알파벳의 기호들로 만든 문자열들의 집합이다. 컴파일러는 이러한 언어의 규칙을 이용해 소스 코드를 분석한다.
2. **형식 문법**은 문자열을 생성하는 규칙 체계다. 문법이 생성하는 언어는 시작 기호에서 유도할 수 있는 종단 기호 문자열들의 집합이다.
3. 문법은 `G = (VN, VT, P, S)`로 표현한다. `VN`은 비종단 기호의 유한집합, `VT`는 종단 기호의 유한집합, `P`는 생성 규칙의 집합, `S`는 시작 기호다.
4. **종단 기호**는 완성된 문자열에 남는 기호이고, **비종단 기호**는 문자열 생성 과정에서 바꾸어 나가는 기호다. 소문자·숫자를 종단 기호로, 대문자를 비종단 기호로 쓰는 것은 표기 관례이며, 실제 구분은 문법의 정의를 따른다.
5. 언어학자 노엄 촘스키는 생성 규칙의 제약에 따라 문법을 Type 0, Type 1, Type 2(문맥 자유 문법), Type 3(정규문법)로 분류했다. 이를 **촘스키 계층**이라고 한다.
6. 문법을 나타내는 표기에는 BNF(Backus–Naur **Form**), EBNF(Extended BNF), 문법 도표 등이 있다. **정규 표현은 정규 언어를 표현하는 방법**이며, 모든 종류의 문법을 표현하는 것은 아니다.
7. 모든 정규문법이 생성하는 언어는 정규 표현으로 나타낼 수 있다. 이 예제에서는 규칙을 언어 방정식으로 바꾸고, 대입과 반복 공식으로 정리한다.

원문의 “영문학자”는 “언어학자”로, “Backus-Naur From”은 “Backus–Naur Form”으로 바로잡았다.

## 먼저 기호 읽는 법

| 기호 | 읽는 방법 | 예 |
| --- | --- | --- |
| `a`, `b` | 결과에 남는 실제 글자 | `ab`는 a 다음에 b |
| `S`, `A`, `B`, `C` | 규칙에 따라 바꿀 자리 | `S → aB` |
| `→` | 왼쪽을 오른쪽으로 바꿀 수 있다는 규칙 | `B → bC` |
| `⇒` | 실제로 규칙을 한 번 적용 | `aB ⇒ abC` |
| `⇒*` | 규칙을 0번 이상 적용 | `S ⇒* aba` |
| `\|` | 또는: 하나를 선택 | `S → aS \| aB` |
| `+` | 두 식 사이에서는 또는 | `a+b`는 a 또는 b |
| `ε` | 아무 글자도 없는 문자열 | `abε = ab` |
| `*` | 바로 앞의 식을 0번 이상 반복 | `(ab)*`는 ε, ab, abab, … |
| `aⁿ` | a를 n개 이어 붙임 | `a³ = aaa` |

**이미 나온 소문자는 그대로 두고, 대문자 자리에 규칙의 오른쪽을 넣는다. 대문자가 모두 사라지면 문자열이 완성된다.**

문법에서 `S → aS | aB`라고 쓰던 것을 방정식에서는 `S = aS + aB`로 쓴다. 방정식의 `S`는 S에서 만들 수 있는 문자열들의 집합을 나타낸다. 숫자 덧셈이나 곱셈을 하는 식은 아니다.

## 예제 1. 문법에서 실제 문자열 만들기

주어진 문법은 다음과 같다. 아래 연습문제 2~4번도 이 문법을 사용한다.

```text
G = ({S, B, C}, {a, b}, P, S)

S → aS | aB
B → bC
C → aC | a
```

### 1. 가장 짧은 문자열 만들기

```text
S
⇒ aB     S를 aB로 바꿈
⇒ abC    B를 bC로 바꿈
⇒ aba    C를 a로 바꿈
```

결과는 `aba`다. `B`를 바꿀 때는 앞에 있는 `a`를 지우지 않고 `B`만 `bC`로 바꾼다.

### 2. 앞의 a 늘리기

`S → aS`는 a를 하나 추가하고, 다시 S에서 선택하게 하는 규칙이다.

```text
S
⇒ aS       S → aS
⇒ aaS      S → aS
⇒ aaaB     S → aB
⇒ aaabC    B → bC
⇒ aaaba    C → a
```

`S → aS`를 두 번 골라 a 두 개를 만들고, B로 넘어가는 `S → aB`에서도 a 하나가 추가된다. 따라서 앞의 a는 총 세 개다.

반복을 한 번도 하지 않아도 `S → aB`에서 a가 붙으므로 **b 앞의 a는 최소 한 개**다.

### 3. 뒤의 a 늘리기

`C → aC`는 뒤에 a를 추가하고 계속 진행하는 규칙이다. `C → a`를 고르면 마지막 a를 쓰고 끝난다.

```text
S ⇒ aB ⇒ abC
          ⇒ abaC     C → aC
          ⇒ abaaC    C → aC
          ⇒ abaaa    C → a
```

따라서 **b 뒤의 a도 최소 한 개**다. `C → ε`라는 규칙은 없으므로 뒤의 a를 전부 생략할 수는 없다.

### 4. 전체 모양 정리

```text
앞: a가 1개 이상
중간: b가 정확히 1개
뒤: a가 1개 이상
```

이 모양을 `aⁿbaᵐ`이라고 쓰며, `n ≥ 1`, `m ≥ 1`이다. n과 m은 a의 개수이고, 서로 같을 필요는 없다.

| n | m | 완성된 문자열 |
| --- | --- | --- |
| 1 | 1 | `aba` |
| 3 | 1 | `aaaba` |
| 1 | 3 | `abaaa` |
| 2 | 3 | `aabaaa` |

### 5. 정규 표현으로 쓰기

최소 한 개의 a는 `a*a`로 표현할 수 있다.

```text
a* = a를 0개 이상
a*a = a를 0개 이상 쓴 뒤, a를 반드시 1개 추가
```

따라서 전체는 다음과 같다.

```text
(a*a) b (a*a)
= a*aba*a
```

괄호와 공백은 읽기 쉽게 넣은 것이며, 실제 문자열에 들어가는 글자가 아니다.

## 예제 2. 갑자기 α와 β가 나오는 이유

**α(알파)와 β(베타)는 긴 식의 일부에 붙인 이름이다. α는 소문자 a가 아니고, β는 소문자 b가 아니다.**

다음 공식에서 각 부분의 역할을 구분하려고 사용한다.

```text
X = αX + β

X: 지금 구하려는 문자열 집합
α: 다시 X로 돌아갈 때 앞에 붙는 부분
β: X의 반복을 끝내는 부분
```

### 1. 공식보다 반복부터 이해하기

`X = αX + β`에는 두 선택지가 있다.

```text
αX 선택 → α를 붙이고 다시 X에서 선택
β 선택  → β를 붙이고 X의 반복 종료
```

가능한 결과를 펼치면 다음과 같다.

```text
바로 끝냄:       β
한 번 반복:     αβ
두 번 반복:     ααβ
세 번 반복:     αααβ
...
```

즉 **α를 0번 이상 반복한 다음 β를 붙인다.** 이를 정규 표현으로 줄이면 `α*β`다.

```text
X = αX + β  →  X = α*β
```

이 공식은 Arden의 보조정리다. α가 나타내는 언어에 `ε`가 없을 때 유일한 해가 된다. 아래 예제의 α인 `a+b`, `aa+b`, `a`, `ab`는 모두 이 조건을 만족한다.

### 2. 주어진 세 식 확인

첫 번째 강의 화면의 예제는 다음과 같다. 예제 1과는 다른 문법이다.

```text
① S = aA + bS
② A = aS + bB
③ B = aB + bB + ε
```

목표는 시작 기호 S를 **소문자와 정규 표현 기호만으로 표현하는 것**이다. 먼저 B를 구하고, A를 대입해서 없앤 뒤, S를 정리한다.

### 3. B부터 정리하기

```text
B = aB + bB + ε
  = (a+b)B + ε
```

a를 쓰고 계속하거나, b를 쓰고 계속하거나, 아무것도 쓰지 않고 끝낼 수 있다.

```text
B ⇒ ε                 결과: ε
B ⇒ aB ⇒ a            결과: a
B ⇒ bB ⇒ baB ⇒ ba     결과: ba
```

따라서 a와 b를 원하는 만큼 반복할 수 있다.

```text
X = B
α = (a+b)
β = ε

B = (a+b)*ε
  = (a+b)*
```

마지막의 ε는 아무 글자도 추가하지 않으므로 생략한다.

### 4. A 자리에 두 번째 식 넣기

①의 A를 ②의 `aS+bB`로 바꾼다.

```text
S = aA + bS
  = a(aS+bB) + bS
  = aaS + abB + bS
```

괄호 앞의 a를 각 선택지 앞에 붙인 것이다.

```text
a(aS+bB) = a·aS + a·bB = aaS + abB
```

여기서 점은 글자를 이어 붙인다는 표시다. 연결 순서를 바꾸면 안 된다. `ab`와 `ba`는 다른 문자열이다.

### 5. S로 돌아가는 부분 묶기

`aaS`와 `bS`는 끝에 S가 있으므로 묶을 수 있다.

```text
S = aaS + abB + bS
  = aaS + bS + abB
  = (aa+b)S + abB
```

선택지의 나열 순서는 바꿀 수 있지만, 각 선택지 안의 글자 순서는 그대로 유지한다.

아까 구한 `B = (a+b)*`를 넣는다.

```text
S = (aa+b)S + ab(a+b)*
```

### 6. α와 β에 대응시키기

| 공식의 자리 | 실제 식의 해당 부분 | 역할 |
| --- | --- | --- |
| X | `S` | 구하려는 것 |
| α | `(aa+b)` | S로 돌아갈 때 붙는 aa 또는 b |
| β | `ab(a+b)*` | S를 더 반복하지 않을 때 만드는 부분 |

```text
공식: X = αX + β
실제: S = (aa+b)S + ab(a+b)*
```

α와 β를 다른 곳에서 구해온 것이 아니다. **이미 있는 식을 보고 “여기가 α 자리, 저기가 β 자리”라고 이름을 붙인 것이다.**

### 7. 반복 공식 적용

```text
X = α*β

S = (aa+b)*ab(a+b)*
```

세 덩어리로 나누어 읽는다.

```text
(aa+b)*       ab         (a+b)*
─────────     ──         ────────
aa 또는 b를   ab를       a 또는 b를
0번 이상      반드시     0번 이상
반복          한 번 붙임 반복
```

| 앞 반복 | 가운데 | 뒤 반복 | 완성된 문자열 |
| --- | --- | --- | --- |
| 없음 | `ab` | 없음 | `ab` |
| `aa` | `ab` | 없음 | `aaab` |
| `b` | `ab` | `a` | `baba` |
| `aa`, `b` | `ab` | `b` | `aababb` |

가장 짧은 문자열 `ab`는 원래 규칙으로도 확인할 수 있다.

```text
S ⇒ aA ⇒ abB ⇒ ab
```

## 연습문제 1. 문자열과 반복 기호

`T = {a, b, c}`일 때 틀린 설명을 고른다.

1. `aⁿ = abc`
2. `|abc| = 3`
3. `T* = {ε, a, b, c, aa, ab, ac, …}`
4. `T+ = {a, b, c, aa, ab, ac, …}`

**정답: ①**

`aⁿ`은 a를 n개 이어 붙인 문자열이다. b와 c가 새로 생기지 않는다.

```text
a⁰ = ε
a¹ = a
a² = aa
a³ = aaa    ← abc가 아님
```

②는 문자열 abc의 길이가 3이라는 뜻이다. ③의 `T*`는 공문자열을 포함하고, ④의 `T+`는 T의 기호를 한 개 이상 사용하므로 공문자열을 제외한다.

## 연습문제 2. 촘스키 문법 분류

예제 1의 문법을 사용한다.

```text
S → aS | aB
B → bC
C → aC | a
```

보기: ① Type 0, ② Type 1, ③ Type 2, ④ Type 3

**정답: ④ Type 3, 우선형 정규문법**

오른쪽이 모두 다음 둘 중 하나다.

```text
종단 기호 + 비종단 기호: aS, aB, bC, aC
종단 기호 하나:         a
```

비종단 기호가 있다면 항상 오른쪽 끝에 있으므로 우선형이다. 단순히 대문자가 하나라는 것뿐 아니라 **오른쪽의 배치 형태**를 확인한다.

Type 3 문법은 더 넓은 유형의 조건도 만족하지만, 이 문제는 가장 제한적인 해당 유형을 고르는 문제다.

## 연습문제 3. 생성할 수 없는 문자열

예제 1의 문법으로 생성할 수 없는 것을 고른다.

1. `aba`
2. `ababa`
3. `aabaaa`
4. `abaaa`

**정답: ② ababa**

이 문법은 b를 정확히 한 번만 만든다. b가 두 번 있는 ababa는 만들 수 없다.

| 보기 | 앞의 a 개수 | b 개수 | 뒤의 a 개수 | 판정 |
| --- | --- | --- | --- | --- |
| `aba` | 1 | 1 | 1 | 가능 |
| `ababa` | — | 2 | — | 불가능 |
| `aabaaa` | 2 | 1 | 3 | 가능 |
| `abaaa` | 1 | 1 | 3 | 가능 |

가능한 세 문자열은 직접 유도해 확인한다.

```text
① S ⇒ aB ⇒ abC ⇒ aba
③ S ⇒ aS ⇒ aaB ⇒ aabC ⇒ aabaC ⇒ aabaaC ⇒ aabaaa
④ S ⇒ aB ⇒ abC ⇒ abaC ⇒ abaaC ⇒ abaaa
```

B에서 b를 한 번 만든 뒤에는 C로 넘어가고, C에는 a를 만드는 규칙만 있다. 따라서 뒤에서 b를 다시 만들 방법이 없다.

## 연습문제 4. 정규 표현 선택

예제 1의 문법이 생성하는 언어를 나타내는 정규 표현을 고른다.

1. `a*ba*`
2. `a*aba*a`
3. `a*ab*a*a`
4. `a*+aba*a`

**정답: ② a*aba*a**

### C부터 차례로 풀기

```text
C = aC + a
```

공식에서 `X=C`, `α=a`, `β=a`다.

```text
C = a*a
```

이를 B에 넣는다.

```text
B = bC
  = ba*a
```

마지막으로 S에 넣는다.

```text
S = aS + aB
  = aS + aba*a
```

이번에는 `X=S`, `α=a`, `β=aba*a`다.

```text
S = a*(aba*a)
  = a*aba*a
```

### ③번이 틀린 이유

③은 중간이 b가 아니라 **b***다. b를 0개도, 여러 개도 허용한다.

```text
③ a*ab*a*a

b를 0개 선택 → aa도 허용
b를 2개 선택 → abba도 허용
```

원래 문법은 b가 정확히 한 개 있어야 하므로 둘 다 불가능하다. b가 하나 들어간다는 이유만으로 b*를 쓰면 생성하는 언어가 달라진다.

다른 오답도 반례로 확인할 수 있다.

| 보기 | 잘못 허용하는 문자열 | 틀린 이유 |
| --- | --- | --- |
| ① `a*ba*` | `b` | 앞뒤 a가 없어도 됨 |
| ③ `a*ab*a*a` | `aa`, `abba` | b가 없거나 여러 개여도 됨 |
| ④ `a*+aba*a` | `ε`, `a` | +가 선택이므로 a*만으로도 끝날 수 있음 |

## 연습문제 5. 반복한 뒤 aa로 끝나는 문법

시작 기호가 V0인 다음 문법에서 생성할 수 없는 것을 고른다.

```text
V0 → aV1
V1 → bV0 | a
```

1. `aa`
2. `aba`
3. `abaa`
4. `ababaa`

**정답: ② aba**

### 규칙의 두 경로 확인

```text
종료: V0 ⇒ aV1 ⇒ aa
반복: V0 ⇒ aV1 ⇒ abV0
```

반복 경로는 ab를 만든 뒤 V0로 돌아간다. 마지막에는 종료 경로를 골라 aa를 붙인다.

```text
반복 0번: aa
반복 1번: ab 뒤에 aa → abaa
반복 2번: ab 뒤에 ab, 그 뒤에 aa → ababaa
```

따라서 ab를 0번 이상 반복한 뒤 aa를 붙이는 정규 표현은 다음과 같다.

```text
(ab)*aa
```

aba를 만들려고 하면 `V0 ⇒ aV1 ⇒ abV0 ⇒ abaV1`까지는 갈 수 있지만, V1을 그냥 지우는 규칙이 없다. `V1 → a`를 적용하면 abaa가 된다.

### 방정식으로 확인

```text
V0 = aV1
V1 = bV0 + a

V0 = a(bV0+a)
   = abV0 + aa
```

`X=V0`, `α=ab`, `β=aa`이므로 `V0=(ab)*aa`다.

## 연습문제 6. BNF로 정의한 숫자 문자열

주어진 규칙에 대한 올바른 설명을 고른다.

```text
<절대정수> ::= <숫자> | <절대정수><숫자>
<숫자> ::= 0 | 1 | 2 | 3 | 4 | 5
```

1. `11`, `45`, `112`, `2315` 등이 허용된다.
2. 0을 포함하는 모든 수를 의미한다.
3. 1을 포함하는 모든 수를 의미한다.
4. `1`, `5`, `9`, `10`, `13` 등이 허용된다.

**정답: ①**

사용할 수 있는 글자는 **0~5**이고, 숫자를 한 개 이상 이어 붙일 수 있다. ①의 문자열은 모두 이 조건을 만족한다.

### 112를 만드는 과정

```text
<절대정수>
⇒ <절대정수><숫자>
⇒ <절대정수><숫자><숫자>
⇒ <숫자><숫자><숫자>
⇒ 1<숫자><숫자>
⇒ 11<숫자>
⇒ 112
```

`<절대정수> → <절대정수><숫자>`를 반복할 때마다 숫자 자리가 하나씩 늘어난다. 마지막에는 `<절대정수> → <숫자>`를 골라 반복을 끝낸다.

### 오답과 화면 해설의 오류

| 보기 | 판단 근거 |
| --- | --- |
| ② | 0을 반드시 포함해야 하는 규칙이 아니며, 0을 포함하더라도 60처럼 6이 있으면 생성 불가 |
| ③ | 1을 반드시 포함해야 하는 규칙이 아니며, 1을 포함하더라도 17처럼 7이 있으면 생성 불가 |
| ④ | 9는 허용된 숫자 기호가 아니므로 생성 불가 |

**화면 해설의 “숫자는 1부터 5까지”는 규칙과 불일치한다. 주어진 생성 규칙에는 0이 있으므로 0부터 5까지가 맞다.** 정답 번호 ①은 그대로다.

이 문법은 숫자의 수학적 의미보다 **문자열의 형태**를 정의한다. 0으로 시작하는 것을 금지하는 규칙도 없으므로 `0`, `00`, `012`도 생성할 수 있다. 공문자열이나 음수 기호는 생성할 수 없다.

일반 프로그래밍 정규식의 문자 클래스 표기로는 `[0-5][0-5]*`라고 쓸 수 있다.

## 풀이 순서 복습

1. 종단 기호와 비종단 기호를 구분한다.
2. 가장 짧은 문자열을 직접 만든다.
3. 자기 자신으로 돌아오는 규칙에서 무엇이 반복되는지 확인한다.
4. 반복을 끝낼 때 반드시 붙는 글자를 확인한다.
5. `X = αX + β` 꼴로 정리하고, α와 β에 해당하는 식을 적는다.
6. `X = α*β`를 적용한 뒤 가장 짧은 문자열과 오답 반례로 확인한다.
