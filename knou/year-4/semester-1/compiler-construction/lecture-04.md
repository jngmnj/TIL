# 4강. 유한 오토마타의 구현과 동치관계

- 학습일: 2026-08-26
- 과목: 컴파일러구성
- 주제: DFA 구현, DFA 최소화, 정규문법·정규표현·유한 오토마타의 동치관계

## 핵심 요약

유한 오토마타, 특히 DFA는 프로그램으로 구현할 수 있으며, 구현된 DFA는 어휘분석기의 핵심이 된다. 상태 전이도는 사람이 이해하기 좋지만, 실제 프로그램에서는 전이 함수를 2차원 배열이나 테이블로 표현하는 방식이 적합하다.

DFA는 상태 수가 많을수록 구현 규모와 실행 비용이 커질 수 있으므로, 같은 동작을 하는 상태들을 묶어 최소화할 수 있다. 또한 정규문법, 정규 표현, 유한 오토마타는 서로 변환 가능하므로 동치관계에 있다.

## DFA 구현

DFA는 현재 상태와 입력 기호가 정해지면 다음 상태가 하나로 결정된다. 따라서 전이 함수를 표로 만들고, 입력 문자열을 한 글자씩 읽으며 현재 상태를 갱신하면 프로그램으로 쉽게 구현할 수 있다.

```text
현재 상태 + 입력 기호 -> 전이표 조회 -> 다음 상태
```

입력을 모두 읽은 뒤 현재 상태가 종료 상태이면 문자열을 받아들이고, 그렇지 않으면 거부한다.

## 상태 전이도와 전이표

예를 들어 상태가 `S0`, `S1`, `S2`이고 입력 기호가 `a`, `b`, `c`인 DFA를 생각할 수 있다.

| 구성 | 의미 |
| --- | --- |
| `S0` | 시작 상태 |
| `S2` | 종료 상태 |
| `a`, `b`, `c` | 입력 기호 |
| 전이표 | 각 상태와 입력 기호에 따른 다음 상태 |

상태 전이도는 그림으로 흐름을 이해하기 좋다. 하지만 프로그램에서는 다음과 같은 전이표가 더 직접적이다.

| 현재 상태 | `a` | `b` | `c` |
| --- | --- | --- | --- |
| `S0` | `S1` | `S0` | `S2` |
| `S1` | `S2` | `S0` | `S1` |
| `S2` | `S2` | `S2` | `S2` |

전이표는 2차원 배열로 만들 수 있다. 행은 상태, 열은 입력 기호를 나타낸다.

## 문자열 인식 과정

입력 문자열이 `abc`라고 하면 다음 순서로 동작한다.

1. 시작 상태 `S0`에서 시작한다.
2. `a`를 읽고 `S1`로 이동한다.
3. `b`를 읽고 전이표에 따라 다음 상태로 이동한다.
4. `c`를 읽고 다음 상태로 이동한다.
5. 모든 입력을 읽은 뒤 종료 상태에 있으면 `accept`한다.

반대로 입력을 모두 읽은 뒤 종료 상태가 아닌 곳에 있으면 `reject`한다.

## 프로그램 구현 구조

DFA 구현은 보통 다음 요소로 구성된다.

| 요소 | 역할 |
| --- | --- |
| 입력 기호 집합 | DFA가 읽을 수 있는 문자 집합 |
| 상태 집합 | DFA의 가능한 상태 |
| 전이 테이블 | 상태와 입력 기호에 따른 다음 상태 |
| 시작 상태 | 입력을 읽기 시작하는 상태 |
| 종료 상태 | 문자열을 받아들이는 상태 |
| `accept` 함수 | 최종 상태가 종료 상태인지 판단 |
| `delta_bar` 함수 | 문자열 전체를 읽으며 상태를 갱신 |

`delta_bar`는 시작 상태에서 출발해 입력 문자열의 각 문자를 순서대로 읽고, 전이표를 조회해 현재 상태를 갱신한다. 최종 상태가 종료 상태와 같으면 `accept` 함수는 참을 반환한다.

## DFA 최소화가 필요한 이유

DFA의 상태 수가 많아지면 전이표가 커지고, 구현해야 할 코드나 데이터도 늘어난다. 따라서 같은 동작을 하는 상태들을 하나로 합치면 어휘분석기의 크기를 줄이고 실행을 단순하게 만들 수 있다.

DFA 최소화의 핵심은 서로 구별되지 않는 상태를 같은 동치류로 묶는 것이다.

```text
동작이 같은 상태들 -> 하나의 상태로 병합
```

## 동치류를 이용한 상태 최소화

상태 최소화는 먼저 종료 상태와 종료 상태가 아닌 상태를 구분하는 데서 시작한다.

| 분류 | 의미 |
| --- | --- |
| 종료 상태 | 입력을 받아들이는 상태 |
| 비종료 상태 | 입력을 받아들이지 않는 상태 |

종료 상태와 비종료 상태는 성질이 다르므로 같은 그룹에 둘 수 없다. 이후 각 상태가 입력 기호를 읽었을 때 어느 그룹으로 이동하는지 비교한다.

같은 그룹에 있던 상태라도 입력을 읽은 뒤 서로 다른 그룹으로 이동한다면 다시 나누어야 한다. 이 과정을 더 이상 분리할 수 없을 때까지 반복하면 최소화된 DFA를 얻는다.

## 최소화 절차

1. 상태들을 종료 상태와 비종료 상태로 나눈다.
2. 각 상태의 전이 결과가 어느 그룹으로 가는지 확인한다.
3. 같은 그룹 안에서 전이 결과가 다른 상태를 분리한다.
4. 새 그룹 번호를 기준으로 전이 결과를 다시 계산한다.
5. 더 이상 그룹이 나뉘지 않으면 같은 그룹의 상태를 하나로 합친다.

예를 들어 `A`와 `C`가 모든 입력에 대해 같은 그룹으로 이동한다면 두 상태는 같은 역할을 하므로 하나의 상태로 합칠 수 있다. 반면 `D`처럼 특정 입력에서 종료 상태 그룹으로 이동하는 상태는 다른 상태와 구별되어야 한다.

## 정규문법, 정규 표현, 유한 오토마타

어휘를 표현하고 구현하기 위해 세 가지 표현을 사용했다.

| 표현 | 역할 |
| --- | --- |
| 정규문법 | 어휘를 생성 규칙으로 표현 |
| 정규 표현 | 어휘 패턴을 간결하게 표현 |
| 유한 오토마타 | 어휘를 인식하는 수학적 모델 |

정규문법은 정규 표현으로 바꿀 수 있고, 정규 표현은 유한 오토마타로 바꿀 수 있다. 유한 오토마타도 다시 정규문법으로 바꿀 수 있으므로 세 표현은 서로 동치다.

```text
정규문법 -> 정규 표현 -> 유한 오토마타 -> 정규문법
```

한 방향의 순환 변환이 가능하면, 반대 방향의 변환도 중간 표현을 거쳐 가능해진다.

## 정규문법에서 정규 표현으로

정규문법을 정규 표현으로 바꿀 때는 생성 규칙을 방정식처럼 다룬다. 대표적으로 다음 형태를 이용한다.

```text
X = αX + β
X = α*β
```

여기서 `α`와 `β`는 정규 표현이다. 같은 논터미널이 자기 자신으로 되돌아오는 구조가 있으면 반복을 의미하므로 `*`를 사용해 정리할 수 있다.

## 정규 표현에서 유한 오토마타로

정규 표현의 기본 연산은 상태 전이도로 표현할 수 있다.

| 정규 표현 | 유한 오토마타 의미 |
| --- | --- |
| `a` | `a`를 읽고 다음 상태로 이동 |
| `a + b` | `a` 또는 `b`를 읽고 이동 |
| `a+` | `a`를 한 번 이상 반복 |
| `a*` | `a`를 0번 이상 반복, `ε` 포함 |
| `(a + b)*abb` | `a` 또는 `b`가 반복된 뒤 `abb`로 끝남 |

`*`는 공문자열 `ε`을 포함하므로 시작 상태 자체가 종료 상태가 될 수 있다. 다만 뒤에 다른 기호가 이어지는 경우에는 전체 문자열의 종료 조건을 고려해 종료 상태를 배치해야 한다.

## 유한 오토마타에서 정규문법으로

유한 오토마타를 정규문법으로 바꾸는 방법은 단순하다.

```text
상태 -> 논터미널 기호
입력 기호 -> 터미널 기호
전이 -> 생성 규칙
종료 상태 -> ε 생성 규칙
```

예를 들어 상태 `A`에서 입력 `a`를 읽고 상태 `C`로 간다면 다음 생성 규칙으로 표현한다.

```text
A -> aC
```

상태 `D`가 종료 상태라면 다음 규칙을 추가한다.

```text
D -> ε
```

이렇게 하면 유한 오토마타의 전이 구조가 정규문법의 생성 규칙으로 바뀐다.

## 동치관계의 의미

세 표현이 동치라는 것은 표현 방식은 다르지만 나타낼 수 있는 언어의 범위가 같다는 뜻이다.

```text
정규문법 = 정규 표현 = 유한 오토마타
```

따라서 어휘를 정규문법으로 정의해도 되고, 정규 표현으로 작성해도 되며, 최종적으로는 유한 오토마타로 구현해 어휘분석기를 만들 수 있다.

## 정리

DFA는 전이표를 이용해 프로그램으로 구현할 수 있고, 구현된 DFA는 입력 문자열을 읽어 `accept` 또는 `reject`를 판단한다. DFA의 상태가 많으면 동치류를 이용해 최소화할 수 있다.

정규문법, 정규 표현, 유한 오토마타는 서로 변환 가능한 동치 표현이다. 이 관계를 이해하면 어휘 규칙을 문법으로 정의하고, 정규 표현으로 간단히 나타내고, 유한 오토마타로 구현하는 전체 흐름을 연결해서 볼 수 있다.
