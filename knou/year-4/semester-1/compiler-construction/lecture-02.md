# 2강. 형식 언어와 형식 문법

- 학습일: 2026-08-24
- 과목: 컴파일러구성
- 주제: 형식 언어, 형식 문법, 촘스키 계층, 정규 표현

## 핵심 요약

컴파일러는 프로그래밍 언어를 번역하는 프로그램이다. 프로그래밍 언어는 자연어와 달리 명확한 규칙으로 정의되는 형식 언어이며, 이 형식 언어를 설명하기 위해 형식 문법이 필요하다.

2강에서는 어휘 분석을 이해하기 위한 기초로 알파벳, 문자열, 언어, 문법, 촘스키 계층, BNF/EBNF, 정규문법, 정규 표현을 다룬다.

## 어휘 분석과 문법

어휘 분석은 소스 코드의 문자들을 식별자, 숫자, 연산자 등의 토큰으로 묶는 단계다. 구문 분석은 이 토큰들이 문법에 맞는 순서와 구조로 배치되었는지 확인한다.

예를 들어 다음 치환문을 생각할 수 있다.

```text
abc := e + abc / 2;
```

여기서 `abc`, `e`는 식별자이고 `:=`, `+`, `/`, `2`, `;`도 각각 문장을 구성하는 어휘다. 식별자가 올바른지 판단하려면 식별자를 만드는 규칙이 필요하다.

실제 소스 코드에 나타난 문자열을 **렉심(lexeme)**, 그것을 분류한 단위를 **토큰(token)**이라고 한다.

| 렉심 | 토큰 종류의 예 |
| --- | --- |
| `abc`, `e` | 식별자 `IDENTIFIER` |
| `:=` | 대입 연산자 `ASSIGN` |
| `2` | 정수 리터럴 `INTEGER` |
| `+`, `/`, `;` | 각각의 연산자·구분자 토큰 |

`abc`와 `e`는 서로 다른 렉심이지만 같은 종류의 토큰이다. 어휘분석기는 토큰 종류와 함께 이름, 값, 소스 위치 등의 정보를 전달할 수 있다.

```text
문자열: abc := e + abc / 2;
토큰열: ID ASSIGN ID PLUS ID DIV INTEGER SEMICOLON
```

`abc + / 2`는 각각의 어휘를 인식할 수 있어도 일반적인 식 문법에는 맞지 않는다. 이런 배치 오류는 구문 분석에서 다룬다.

## 식별자 규칙 예

이 강의의 예제 언어에서는 식별자를 다음 규칙으로 정의한다. 실제 언어는 밑줄, 유니코드 문자 등의 허용 범위가 다를 수 있다.

1. 첫 글자는 영문자다.
2. 두 번째 글자부터는 영문자나 숫자가 올 수 있다.
3. 언어에 따라 길이 제한이 있을 수 있다.

이 규칙을 BNF/EBNF로 표현하면 컴파일러의 어휘분석기가 이를 기준으로 식별자를 인식할 수 있다.

## BNF와 EBNF

BNF는 Backus-Naur Form의 약자로, 문법 규칙을 표현하는 표기법이다. EBNF는 Extended BNF로, 반복과 선택 같은 표현을 더 편하게 나타낼 수 있도록 확장한 방식이다.

| 표기 | 의미 |
| --- | --- |
| `::=` | 왼쪽 기호가 오른쪽 형태로 정의됨 |
| `\|` | 또는 |
| `{ }` | 0회 이상 반복 |
| `[ ]` | 선택 항목 |

아래는 EBNF 예다. `{ }`와 `[ ]`의 의미는 표기 관례에 따라 다를 수 있으므로, 이 노트에서는 위 표의 규칙을 사용한다.

```text
<identifier> ::= <letter> { <letter> | <digit> }
<letter> ::= a | b | c | ... | z | A | B | C | ... | Z
<digit> ::= 0 | 1 | 2 | ... | 9
```

여기서 `...`는 나머지 문자를 생략한 설명용 표기다. 순수 BNF에서는 반복을 재귀 규칙으로 풀어 쓸 수 있다.

```text
<identifier> ::= <letter> <tail>
<tail> ::= <letter> <tail> | <digit> <tail> | ε
```

`<tail>`이 `ε`로 끝날 수 있으므로 글자 하나인 `a`도 식별자다. 두 표기법은 같은 규칙을 나타내며, EBNF가 더 강력한 언어를 표현한다는 뜻은 아니다.

## 형식 언어의 기본 용어

| 용어 | 의미 |
| --- | --- |
| 기호 | 문자열을 구성하는 최소 단위 |
| 알파벳 | 기호들의 유한하고 비어 있지 않은 집합 |
| 문자열 | 알파벳의 기호를 0개 이상 나열한 것 |
| 공문자열 | 기호가 0개인 문자열, `ε`로 표현 |
| 언어 | 문자열들의 집합 |

프로그래밍 언어는 특정 알파벳으로 만들 수 있는 모든 문자열 중에서 문법 규칙을 만족하는 문자열의 집합으로 볼 수 있다.

## 공문자열

공문자열은 아무 기호도 나열하지 않은 문자열이며 `ε`로 표현한다.

```text
aε = εa = a
```

즉 공문자열은 다른 문자열에 붙어도 결과를 바꾸지 않는다.

공문자열과 공집합은 구분해야 한다.

| 표기 | 무엇인가? | 크기·길이 |
| --- | --- | --- |
| `ε` | 비어 있는 문자열 | 문자열 길이 0 |
| `{ε}` | 공문자열 하나를 원소로 갖는 언어 | 원소 수 1 |
| `∅` | 어떤 문자열도 없는 언어 | 원소 수 0 |

문자열의 길이는 `|w|`로 쓰며, `|abc| = 3`, `|ε| = 0`이다. `ε`는 빈칸 문자 한 개와도 다르다.

## 클로저와 플러스

알파벳 `T = { a, b, c }`가 있을 때 다음처럼 표현한다.

| 표현 | 의미 |
| --- | --- |
| `T*` | `T`의 기호로 만들 수 있는 모든 문자열과 `ε` |
| `T+` | `T`의 기호로 만들 수 있는 모든 비어 있지 않은 문자열 |
| `a*` | `ε`, `a`, `aa`, `aaa`, ... |
| `(a \| b)*` | `a`와 `b`로 만들 수 있는 모든 문자열과 `ε` |

`*`에는 항상 공문자열이 포함된다. 알파벳에 대해서는 `T+ = T* - {ε}`다.

```text
T⁰ = {ε}
T¹ = {a, b, c}
T² = {aa, ab, ac, ba, bb, bc, ca, cb, cc}
T* = T⁰ ∪ T¹ ∪ T² ∪ ...
T+ = T¹ ∪ T² ∪ ...
```

언어 `L`에도 반복 연산을 적용할 수 있다. 단, `L` 자체에 `ε`가 들어 있으면 `L+`에도 `ε`가 포함된다. “플러스는 공문자열을 제외한다”는 설명은 알파벳의 기호를 반복하는 경우와 구분해야 한다.

## 형식 문법

형식 문법 `G`는 보통 다음 네 가지로 정의한다.

```text
G = (VN, VT, P, S)
```

| 구성 요소 | 의미 |
| --- | --- |
| `VN` | 비종단 기호의 집합 |
| `VT` | 종단 기호의 집합 |
| `P` | 생성 규칙의 집합 |
| `S` | 시작 기호 |

비종단 기호는 문장 구조를 나타내는 보조 기호이고, 종단 기호는 최종 문자열을 구성하는 기호다. `VN`과 `VT`는 서로 겹치지 않으며, 시작 기호 `S`는 `VN`에 속한다.

## 종단 기호와 비종단 기호

예를 들어 다음 생성 규칙을 보자.

```text
S -> 0AS | 0
A -> S1A | 10 | SS
```

| 기호 | 종류 | 이유 |
| --- | --- | --- |
| `S`, `A` | 비종단 기호 | 생성 규칙의 왼쪽에 등장하며 다른 형태로 유도 가능 |
| `0`, `1` | 종단 기호 | 더 이상 다른 기호로 유도되지 않음 |

시작 기호 `S`에서 유도되고, **종단 기호만 남은 문자열**이 해당 문법의 언어에 속한다. 예를 들어 다음과 같이 유도할 수 있다.

```text
S ⇒ 0AS ⇒ 010S ⇒ 0100
    S→0AS   A→10    S→0
```

`0AS`와 `010S`는 비종단 기호가 남아 있는 중간 형태인 **문장형**이다. `0100`은 종단 기호만 남은 **문장**이다.

```text
L(G) = { w ∈ VT* : S ⇒* w }
```

`⇒`는 규칙을 한 번 적용한 유도, `⇒*`는 0번 이상 적용한 유도를 뜻한다. 생성 규칙을 적는 `→`와 실제 유도 과정을 적는 `⇒`도 구분해 읽는다.

## 촘스키 계층

촘스키 계층은 문법을 제약 조건에 따라 네 가지 유형으로 나눈 것이다.

| 유형 | 이름 | 특징 | 컴파일러에서의 활용 |
| --- | --- | --- | --- |
| Type 0 | 무제약 문법 | 왼쪽에 비종단 기호가 하나 이상 포함됨 | 가장 일반적인 문법 유형 |
| Type 1 | 문맥 의존 문법 | 오른쪽 길이가 왼쪽보다 줄어들지 않음 | 비위축 문법 |
| Type 2 | 문맥 자유 문법 | 왼쪽이 하나의 비종단 기호 | 구문 분석 |
| Type 3 | 정규 문법 | Type 2보다 더 제한된 형태 | 어휘 분석 |

Type 0도 생성 규칙의 왼쪽에 비종단 기호가 있어야 한다는 기본 조건은 따른다. Type 1의 길이 조건에는 공문자열을 다루기 위해 `S → ε`를 예외로 허용하는 정의가 있으며, 이때 `S`가 어떤 규칙의 오른쪽에도 나오지 않도록 제한한다.

언어의 표현 범위는 다음과 같다. 포함 관계는 **각 유형이 생성하는 언어 집합**에 대한 것이다.

```text
정규 언어 ⊊ 문맥 자유 언어 ⊊ 문맥 의존 언어 ⊊ 재귀 열거 언어
  Type 3        Type 2          Type 1          Type 0
```

컴파일러 구성에서 특히 중요한 것은 Type 2와 Type 3이다. Type 3 정규문법은 어휘 분석에 사용되고, Type 2 문맥 자유 문법은 구문 분석에 사용된다.

## Type 2. 문맥 자유 문법

문맥 자유 문법은 생성 규칙의 왼쪽이 하나의 비종단 기호인 문법이다.

```text
A -> γ
```

오른쪽 `γ`에는 종단 기호와 비종단 기호로 이루어진 문자열 또는 `ε`가 올 수 있다. 프로그래밍 언어의 문장 구조를 표현하기에 적합해서 구문 분석에서 많이 사용된다.

예를 들어 다음 문법은 `a`와 `b`의 개수가 같은 문자열을 만든다.

```text
S → aSb | ε
S ⇒ aSb ⇒ aaSbb ⇒ aabb
L = { aⁿbⁿ : n ≥ 0 }
```

이 언어는 문맥 자유 언어이지만 정규 언어는 아니다. 개수 제한 없이 앞의 `a` 수와 뒤의 `b` 수를 맞추는 구조는 유한한 상태만으로 처리할 수 없다. 이 차이는 어휘를 정규 표현으로, 중첩된 문장 구조를 문맥 자유 문법으로 다루는 이유를 이해하는 데 도움이 된다.

## Type 3. 정규 문법

정규 문법은 더 제한된 형태의 문법이며, 어휘 분석에서 사용된다.

우선형 정규 문법:

```text
A -> tB
A -> t
```

좌선형 정규 문법:

```text
A -> Bt
A -> t
```

여기서 `A`, `B`는 비종단 기호이고 `t`는 종단 기호다. 정규문법으로 분류하려면 문법 전체가 우선형 또는 좌선형 중 한 방향을 따라야 한다. 공문자열을 생성할 때는 채택한 정의에 맞춰 `ε` 규칙도 허용한다.

우선형과 좌선형 규칙을 임의로 섞으면 정규 언어를 생성한다는 보장이 사라진다.

```text
S → aA | ε
A → Sb
```

각 규칙은 한쪽에 비종단 기호가 있지만, 함께 적용하면 `S ⇒ aA ⇒ aSb`가 되어 앞의 비정규 언어 `{aⁿbⁿ : n ≥ 0}`를 생성한다.

## 문법의 표현 방법

문법은 여러 방식으로 표현할 수 있다.

| 표현 방법 | 설명 |
| --- | --- |
| BNF | 문법 규칙을 기호로 표현 |
| EBNF | BNF에 반복과 선택 표현을 추가 |
| 문법 도표 | 문법을 그림으로 표현 |
| 정규 표현 | 정규 문법이 생성하는 문자열을 간결하게 표현 |

## 문법 도표

문법 도표는 문법 규칙을 흐름 그림처럼 표현하는 방법이다. 예를 들어 다음 문법이 있다고 하자.

```text
V0 -> aV1
V1 -> bV0 | a
```

시작 기호가 `V0`라면 `ab`가 반복되다가 마지막에 `aa`로 끝나는 형태의 문자열을 만들 수 있다.

```text
(ab)*aa
```

실제 유도를 보면 반복 부분과 종료 부분을 구분할 수 있다.

```text
반복 없이 종료: V0 ⇒ aV1 ⇒ aa
한 번 반복:    V0 ⇒ aV1 ⇒ abV0 ⇒ abaV1 ⇒ abaa
두 번 반복:    V0 ⇒* ababaa
```

`V1 → bV0`를 고르면 `ab`를 만들고 시작 지점으로 돌아간다. `V1 → a`를 고르면 마지막 `aa`를 만들고 끝난다. 따라서 `(ab)*aa`이며, `aa`, `abaa`, `ababaa` 등이 포함된다.

## 정규 표현

정규 표현은 정규 문법이 생성하는 문자열 집합을 간결하게 나타내는 표기법이다.

| 표현 | 의미 |
| --- | --- |
| `ε` | 공문자열 |
| `a` | 종단 기호 `a` |
| `p + q` | `p` 또는 `q` |
| `pq` | `p` 다음에 `q`가 이어짐 |
| `p*` | `p`가 0회 이상 반복 |

강의에서는 두 식 사이의 `+`를 OR의 의미로 사용한다. 일반 프로그래밍 정규식에서 `|`를 쓰는 것과 대응된다. 반면 식 뒤에 붙는 `a+`는 1회 이상 반복을 뜻하므로 위치를 구분해야 한다.

| 의미 | 강의의 표기 | 일반 프로그래밍 정규식의 표기 |
| --- | --- | --- |
| 선택 | `a + b` | `a\|b` |
| 0회 이상 반복 | `a*` | `a*` |
| 1회 이상 반복 | `a+` 또는 `aa*` | `a+` |

연산 우선순위는 반복, 연결, 선택 순이다. 따라서 `a + bc*`는 `a` 또는 `b` 뒤에 `c`가 0회 이상 오는 문자열을 뜻한다. `(a + b)c*`와는 다르다.

여기서 다루는 정규 표현은 형식 언어 이론의 정규 표현이다. 실제 정규식 엔진의 역참조 같은 확장 기능까지 모두 정규 언어의 범위에 들어가는 것은 아니다.

## 정규 표현 예

| 정규 표현 | 생성하는 문자열 |
| --- | --- |
| `a*` | `ε`, `a`, `aa`, `aaa`, ... |
| `(a + b)*` | `a`와 `b`로 만들 수 있는 모든 문자열 |
| `(a + b)*abb` | `a`와 `b`가 임의로 나온 뒤 `abb`로 끝나는 문자열 |

`*`는 0회 반복도 허용하므로 `(a + b)*abb`에는 `abb`도 포함된다.

## 정규 문법을 정규 표현으로 바꾸기

정규 문법은 정규 표현으로 변환할 수 있다. 강의에서는 다음 공식을 사용한다.

```text
X = αX + β
X = α*β
```

이 식은 **Arden의 보조정리**에 해당한다. 여기서 `X`, `α`, `β`는 문자열 집합인 언어를 나타내며, `+`는 합집합, 나란히 쓰는 것은 연결이다.

`α`가 나타내는 언어에 `ε`가 포함되지 않으면 `X = α*β`가 유일한 해다. `ε`가 포함되면 `α*β`는 최소 해이지만 유일한 해라고 단정할 수 없다. 예를 들어 `X = εX + {b}`는 `b`를 포함하는 여러 언어가 만족한다.

직관적으로는 `α`를 앞에 붙이는 규칙을 반복하다가 `β`로 끝내는 것이다.

```text
X = β + αβ + ααβ + ... = α*β
```

곱셈처럼 순서를 바꿀 수는 없다. `X = Xα + β`라면 대응하는 해는 `βα*`다.

예를 들어 다음 규칙이 있다고 하자.

```text
S -> aS | bS | b
```

이를 정규 표현 방정식으로 쓰면 다음과 같다.

```text
S = (a + b)S + b
```

공식을 적용하면 다음 정규 표현을 얻는다.

```text
(a + b)*b
```

즉 `a`나 `b`가 여러 번 나온 뒤 마지막은 반드시 `b`로 끝나는 문자열이다.

## 정리

형식 언어는 문법 규칙으로 정의되는 문자열의 집합이다. 컴파일러는 프로그래밍 언어를 정확히 분석하기 위해 형식 문법을 사용한다.

어휘 분석에서는 정규 문법과 정규 표현이 중요하고, 구문 분석에서는 문맥 자유 문법이 중요하다. 이후 강의에서는 정규 표현을 유한 오토마타로 바꾸고, NFA와 DFA의 관계를 살펴본다.
