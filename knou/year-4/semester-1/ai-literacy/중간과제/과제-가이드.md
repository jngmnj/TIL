## 1. 원문 요구사항

### 문항과 배점

| 문항 | 수행 내용 | 배점 |
| --- | --- | --- |
| 1번 | 직접 촬영한 사진의 스타일 변환, 두 방법의 원본 추정, 이미지·캡처 제출 | 10점 |
| 2번 | 변환 전후 정보 변화, 두 방법의 결과와 프롬프트 비교, 동일 이미지 재현 가능성에 대한 판단 | 20점 |

| 결과 선택 | 각 단계의 첫 번째 정상 결과 사용. 여러 이미지가 동시에 생성되면 첫 번째 이미지 사용 |
| 재시도 | 서비스 오류, 빈 이미지, 이미지 깨짐, 생성 실패 때만 가능. 더 비슷하거나 보기 좋은 결과를 얻기 위한 반복 생성 금지 |

### 제출 형식

- **한글 `.hwp` 또는 `.hwpx`, MS Word `.docx` 중 하나의 문서 파일**, **5MB 이하**.
- 모든 이미지·화면 캡처·답안을 문서 본문에 삽입한다. 별도 보조 파일은 제출하지 않는다.
- 캡처의 계정명·이메일·프로필 사진·다른 대화 등 개인정보는 자르거나 가린다. 프롬프트와 AI 응답은 판독 가능해야 한다.
- 2번의 세 문항 답안은 **합계 공백 제외 1,000~1,300자**, **각 문항 250자 이상**으로 작성한다.
- 사용한 생성형 AI 서비스명과 과제 수행일을 포함한다.
- PDF 2쪽의 제출 체크리스트를 답지에 포함한다.
- 참고문헌: 원문에는 ‘해당 없음’으로 기재되어 있다.

마감일, 제출 경로, 파일명, 표지, 글꼴·줄간격·페이지 수는 이 PDF에 지정되어 있지 않으므로 과목 공지를 확인한다. 다른 과목의 서식이나 PDF 제출 조건을 적용하지 않는다.

## 2. 수행 순서 제안

### 1단계: 직접 사진 촬영

촬영일을 적은 메모지를 대상과 함께 촬영한다. 개인정보가 없는 사물 등을 택하고, 날짜가 읽히는지 확인한다. 원본은 작업용으로 보관한다. 날짜를 나중에 합성하는 방식은 ‘메모지를 함께 촬영’하는 조건과 다르다.

### 2단계: 스타일 변환

무료로 사용할 수 있는 생성형 AI 서비스에 원본을 입력하고 일반적인 스타일을 지정한다. 첫 정상 결과를 저장하고, **변환 프롬프트와 변환 결과가 보이는 화면**을 캡처한다.

이 단계의 프롬프트, 서비스명, 수행일을 기록한다. 이미지 선택은 미적 완성도나 원본과의 유사성을 기준으로 다시 하지 않는다.

### 3단계: 방법 1에 쓸 AI 설명 확보

원본 사진과 스타일 변환 이미지를 AI에 보여주고 두 이미지의 차이점을 설명하도록 요청한다. 설명 전체를 판독 가능한 캡처로 보관한다.

이 과정은 **원본 추정 이미지를 생성하는 채팅과 분리**한다. 설명 단계에서는 두 이미지를 비교해야 하지만, 추정 단계에는 원본을 넣어서는 안 된다.

### 4단계: 두 방법의 프롬프트 준비

| 구분 | 방법 1 | 방법 2 |
| --- | --- | --- |
| 정보 출처 | AI가 작성한 차이 설명 | 본인이 원본과 변환 이미지를 직접 관찰한 내용 |
| 작성 방식 | 설명에 있는 정보만으로 프롬프트 구성 | 본인이 관찰하고 직접 프롬프트 작성 |
| 제외할 정보 | AI 설명에 없는 원본 정보 | 방법 1의 AI 설명에서 가져온 정보 |
| 남길 증거 | AI 설명 캡처와 작성한 프롬프트 캡처 | 직접 작성한 프롬프트 캡처 |

방법 1은 프롬프트의 각 세부 정보가 AI 설명 어디에 있는지 대조한다. 방법 2는 AI 설명을 옮겨 적거나 AI에게 관찰·프롬프트 작성을 대신 맡기지 않는다. 작업상 혼동을 줄이려면 본인의 관찰 메모를 별도로 작성해 둔다.

### 5단계: 각각 새 채팅에서 원본 추정

```text
설명 단계: 원본 사진 + 변환 이미지 → AI의 차이 설명

새 채팅 A: 변환 이미지 + 방법 1 프롬프트 → 방법 1 추정 이미지
새 채팅 B: 변환 이미지 + 방법 2 프롬프트 → 방법 2 추정 이미지
```

- 채팅 A와 B는 같은 AI 서비스를 사용한다.
- A와 B에는 각각 **변환 이미지와 해당 방법의 프롬프트만** 넣고 원본 사진을 넣지 않는다.
- A의 대화를 이어서 B를 수행하지 않는다.
- 각 채팅에서 첫 정상 결과를 저장하고 프롬프트 증거를 캡처한다.
- 오류로 재시도한 경우 오류와 재시도 사유를 작업 메모에 남기는 것을 권장한다.

### 6단계: 이미지와 캡처 정리

| 자료 | 제출 문서에서 확인할 내용 |
| --- | --- |
| 원본 사진 1장 | 직접 촬영한 대상과 촬영일 메모지 |
| 스타일 변환 이미지 1장 | 첫 정상 변환 결과 |
| 방법 1 추정 이미지 1장 | AI 설명 기반 프롬프트의 첫 정상 결과 |
| 방법 2 추정 이미지 1장 | 직접 관찰 프롬프트의 첫 정상 결과 |
| 스타일 변환 캡처 | 변환 프롬프트와 결과 |
| 방법 1 설명 캡처 | AI가 작성한 차이 설명 |
| 방법 1 프롬프트 캡처 | 설명만을 바탕으로 작성한 원본 추정 요청 |
| 방법 2 프롬프트 캡처 | 본인이 직접 작성한 원본 추정 요청 |

이미지는 **총 4장**이며, 위 화면 캡처도 별도로 본문에 포함한다. 캡처 장수 자체는 원문에 고정되어 있지 않으므로 긴 설명은 여러 장으로 나누되 빠짐없이 판독할 수 있게 준비한다.

## 3. 2번 분석 답안 작성 가이드

일반적인 AI 장단점 대신 제출한 이미지와 프롬프트의 구체적인 요소를 근거로 쓴다. 다음 표는 관찰 정리용이며 실제 결과를 본 뒤 채운다.

| 비교 요소 | 원본 | 스타일 변환 | 방법 1 | 방법 2 | 관련 프롬프트 정보 |

| 색상·질감 | 관찰 후 작성 |  |  |  |  |
| 형태·수량 | 관찰 후 작성 |  |  |  |  |
| 위치·배경 | 관찰 후 작성 |  |  |  |  |
| 글자·세부 요소 | 관찰 후 작성 |  |  |  |  |

### 2-1. 스타일 변환의 정보 변화

원본과 스타일 변환 이미지 사이에서 **유지·변형·누락·추가**된 정보를 구체적으로 설명한다. 실제로 없는 변화를 만들어 쓰지 말고, 확인되지 않는 범주는 그렇게 밝힌다.

### 2-2. 두 방법의 결과와 프롬프트 비교

방법 1과 방법 2를 각각 원본과 비교하여 잘 반영된 부분과 다르게 생성되거나 반영되지 않은 부분을 쓴다. 이어서 두 프롬프트에 포함된 정보의 차이가 결과에 어떻게 반영된 것으로 보이는지 설명한다. 관찰된 결과와 원인에 대한 추측을 구분한다.

### 2-3. 차이의 이유와 동일 이미지 재현 가능성

원본과 결과 사이에 차이가 있다면 그 이유를 설명한다. 원본 사진을 제공하지 않고 동일한 이미지를 재현할 수 있는지 본인의 판단과 근거를 쓴다. 결론을 미리 정하기보다 실제 누락·변형 정보와 결과를 근거로 판단한다.

**분량 배분 제안:** 2-1 약 330자, 2-2 약 450자, 2-3 약 350자로 잡으면 합계 약 1,130자다. 최종 답안에서 공백을 제외해 세 문항 각각과 합계를 다시 센다. 이미지 설명·체크리스트를 답안 글자 수에 섞어 맞추지 않는다.

## 4. 문서 구성 제안

1. 과목·과제명, 사용 서비스명, 수행일.
2. 1번 수행 자료: 원본, 변환 프롬프트·결과, 방법 1 설명·프롬프트·결과, 방법 2 프롬프트·결과.
3. 2번 답안: 2-1, 2-2, 2-3을 구분하여 작성.
4. 제출 체크리스트.

최종 문서에서 필요한 정보가 보이는 수준으로 이미지 크기·용량을 조절하고 5MB 이하인지 확인한다. 작업용 원본과 제출용 축소 이미지는 구분해 보관하는 것을 권장한다.
