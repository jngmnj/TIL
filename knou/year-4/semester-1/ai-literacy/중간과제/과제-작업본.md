# AI리터러시: 이미지 스타일 변환 및 원본 추정

> 상태: 실제 수행 자료를 넣기 위한 MD 작업본이다. 원본 사진·변환 결과·두 추정 이미지가 아직 없어 비교 답안은 작성하지 않았다. 아래의 요청문은 수행용 초안이며, 사용한 프롬프트로 기록하려면 실제 실행과 캡처가 필요하다.

## 1. 스타일 변환과 두 방법의 원본 추정

### 1.1. 원본 사진

**필요한 자료:** 본인이 촬영일을 적은 메모지를 사물·풍경 등과 함께 직접 촬영한 사진 1장. 현재 제공되지 않았다.

얼굴·이름·학번·주소·연락처·차량번호·신분증·우편물·영수증·컴퓨터나 휴대전화 화면 등 개인 식별 정보가 포함되지 않은 사진을 사용한다. 날짜를 나중에 이미지에 합성하지 않는다.

원본 사진 삽입 위치: **자료 대기**.

### 1.2. 스타일 변환

원본 사진을 첨부한 채팅에서 사용할 수 있는 요청문:

```text
첨부한 사진을 일반적인 수채화 스타일의 이미지로 변환해 주세요.
특정 작가, 작품, 제작사 또는 캐릭터의 스타일을 사용하지 말아 주세요.
이미지 한 장을 생성해 주세요.
```

- 실제 사용한 프롬프트: 실행 후 위 요청문과 일치하는지 확인하여 기록.
- 첫 번째 정상 변환 이미지: **자료 대기**.
- 프롬프트와 변환 결과가 함께 확인되는 화면 캡처: **자료 대기**.

원본과 달라지거나 마음에 들지 않아도 정상 결과라면 다시 생성하지 않는다. 서비스 오류·빈 이미지·깨짐·생성 실패 때만 재시도한다. 동시에 여러 이미지가 나오면 첫 번째 이미지를 사용한다.

### 1.3. 방법 1: AI 설명에 기반한 원본 추정

**설명 단계**에서는 원본과 변환 이미지를 함께 보여준다. 아래 요청문을 사용할 수 있다.

```text
첫 번째 이미지는 원본 사진이고 두 번째 이미지는 스타일 변환 이미지입니다.
두 이미지를 비교하여 원본과 변환 이미지의 차이를 설명해 주세요.
색상, 형태, 수량, 위치, 배경, 질감, 글자 등의 요소를 살펴보고,
유지되거나 변형·누락·추가된 내용을 실제로 확인되는 범위에서 설명해 주세요.
불분명한 내용은 추측으로 채우지 말고 확인하기 어렵다고 표시해 주세요.
```

AI 설명 전문과 화면 캡처: **자료 대기**.

AI 설명을 받은 후, **그 설명에 포함된 정보만** 사용해 원본 추정 프롬프트를 구성한다. 표현과 순서는 바꿀 수 있지만 설명에 없는 원본 세부사항을 추가하지 않는다.

| 원본 추정 프롬프트에 넣을 정보 | 근거가 되는 AI 설명의 해당 문장 |
| --- | --- |
| AI 설명 수신 후 작성 | 설명과 대조 후 기록 |

원본 추정 프롬프트와 캡처: **AI 설명 확보 후 작성·실행**.

**새 채팅 A**에 스타일 변환 이미지와 이 프롬프트만 넣는다. 원본 사진을 첨부하지 않으며, 원본을 보여준 설명 채팅을 그대로 이어 쓰지 않는다.

방법 1의 첫 정상 추정 이미지 삽입 위치: **자료 대기**.

### 1.4. 방법 2: 본인의 직접 관찰에 기반한 원본 추정

이 부분의 관찰과 프롬프트는 과제 조건상 **본인이 직접 작성**해야 한다. 방법 1의 AI 설명을 가져오지 않는다. 아래는 관찰 내용을 기록하는 빈 표이며 관찰 결과를 대신 제시한 것이 아니다.

| 관찰 항목 | 원본에서 직접 확인한 내용 | 변환 이미지와의 차이 |
| --- | --- | --- |
| 대상의 형태·수량 | 본인 작성 | 본인 작성 |
| 색상·질감 | 본인 작성 | 본인 작성 |
| 위치·배경 | 본인 작성 | 본인 작성 |
| 글자·작은 세부사항 | 본인 작성 | 본인 작성 |

본인이 직접 작성한 원본 추정 프롬프트와 화면 캡처: **본인 작성·실행 대기**.

**새 채팅 B**에 스타일 변환 이미지와 직접 작성한 프롬프트만 넣는다. 방법 1과 같은 AI 서비스를 사용하되 채팅 A와 분리하고, 원본 사진은 입력하지 않는다.

방법 2의 첫 정상 추정 이미지 삽입 위치: **자료 대기**.

## 2. 결과 비교·분석 답안

> 세 문항의 답안 합계는 공백 제외 1,000~1,300자, 각 문항은 250자 이상이어야 한다. 아래 빈 항목은 답안이 아니며 글자 수를 충족하지 않는다. 실제 결과를 확인한 후 구체적인 비교 문장으로 교체한다.

### 2-1. 스타일 변환에서 유지·변형·누락·추가된 정보

**답안 작성 대기:** 원본과 스타일 변환 이미지가 필요하다.

| 분류 | 실제 관찰 근거 |
| --- | --- |
| 유지 | 이미지 확보 후 작성 |
| 변형 | 이미지 확보 후 작성 |
| 누락 | 이미지 확보 후 작성 |
| 추가 | 이미지 확보 후 작성 |

### 2-2. 원본 추정 결과와 프롬프트 정보의 차이

**답안 작성 대기:** 두 추정 결과, 방법 1의 AI 설명, 두 프롬프트가 필요하다.

| 비교 항목 | 방법 1 | 방법 2 |
| --- | --- | --- |
| 원본 특징이 잘 반영된 부분 | 결과 확인 후 작성 | 결과 확인 후 작성 |
| 다르거나 누락된 부분 | 결과 확인 후 작성 | 결과 확인 후 작성 |
| 관련 프롬프트의 구체적인 정보 | 프롬프트 확인 후 작성 | 프롬프트 확인 후 작성 |

### 2-3. 차이가 발생한 이유와 동일 이미지 재현 가능성

**답안 작성 대기:** 실제 이미지 차이를 근거로 본인의 판단을 정리한다. 스타일 변환에서 사라진 정보, 프롬프트에서 전달된 정보, 추정 과정에서 새로 생긴 요소를 확인한 뒤 결론을 쓴다.

- [ ] 방법 2의 직접 작성한 프롬프트 캡처.

## 4. 최종 문서로 옮기기 전 확인

모든 이미지와 캡처는 본문에 넣고 개인정보가 보이는 화면 부분은 가린다. 캡처의 프롬프트·응답은 읽을 수 있어야 한다. 최종 제출은 `.hwp`, `.hwpx`, `.docx` 중 하나의 문서이며 5MB 이하다. 이 MD 작업본이나 별도 이미지 파일만 제출하는 것은 원문 제출 형식과 다르다.

다음에 필요한 첫 자료는 **촬영일 메모지가 함께 나온 본인 촬영 사진 1장**이다. 이후 스타일 변환과 방법 1의 설명·프롬프트 정리를 진행할 수 있다. 방법 2의 직접 관찰·프롬프트는 본인이 작성한 내용을 받아 기록한다.
