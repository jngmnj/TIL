# 5강. 머신러닝의 원리

- 학습일: 2026-09-23
- 과목: AI 리터러시
- 주제: 모델·특징·패턴, 인공신경망, 지도·비지도·준지도·강화학습, 상관관계와 인과관계

## 핵심 요약

**머신러닝은 데이터나 경험에서 관계를 학습하고, 이를 새로운 사례의 예측·분류·행동 선택 등에 활용하는 방법이다.** 학습에 쓰인 정보와 목표에 따라 무엇을 배우는지, 결과를 어떻게 평가해야 하는지가 달라진다.

| 개념 | 먼저 확인할 질문 |
| --- | --- |
| 모델 | 어떤 계산 구조와 학습 결과로 출력을 만드는가? |
| 특징 | 입력에서 무엇을 단서로 사용하는가? |
| 패턴 | 사례 사이에서 어떤 관계를 학습했는가? |
| 학습 방식 | 정답 라벨·자료의 구조·행동의 보상 중 무엇을 활용하는가? |
| 결과 해석 | 예측이 맞는 것과 원인을 설명하는 것을 구별했는가? |

이번 강의는 수학적 유도보다 기본 원리와 활용 시의 판단 기준에 초점을 둔다. 인공신경망과 딥러닝은 다음 6강에서 이어서 다룬다.

## 규칙 기반 방식과 학습 기반 방식

| 구분 | 규칙 기반 | 학습 기반 |
| --- | --- | --- |
| 기준을 만드는 방식 | 사람이 규칙을 명시 | 데이터·경험으로부터 관계를 학습 |
| 기본 흐름 | 규칙 작성 → 입력과 대조 → 결과 | 데이터·목표 준비 → 학습 → 새 입력 처리 |
| 장점 | 적용한 규칙을 추적하기 비교적 쉬움 | 일일이 규칙으로 쓰기 어려운 관계를 활용 가능 |
| 주요 한계 | 예외가 많아지면 작성·유지 부담 증가 | 데이터·목표의 영향과 일반화 성능을 검토해야 함 |

### 사람이 하는 일이 사라지는가?

학습 기반이라고 사람이 관여하지 않는 것은 아니다. 문제와 목표, 데이터, 모델 구조, 평가 방법 등을 사람이 선택한다.

모든 학습 기반 모델이 설명하기 어려운 것도 아니다. 모델의 종류와 복잡도에 따라 설명 가능성은 달라지며, 규칙 기반 시스템도 규칙이 복잡하게 얽히면 해석이 어려울 수 있다.

## 모델·특징·패턴 구분하기

### 모델: 학습한 관계를 사용하는 계산 구조

강의는 **모델(model)**을 ‘판단의 틀’에 비유한다. 학습된 매개변수나 구조를 이용해 새 입력의 결과를 계산한다는 뜻이다.

```text
학습 단계
데이터·경험 + 학습 방법·목표 → 학습된 모델

추론 단계
새 입력 + 학습된 모델 → 분류·추정값·추천 등의 결과
```

모델이 현실의 모든 정보와 맥락을 담는 것은 아니다. 그렇다고 본 사례와 똑같은 경우만 처리하는 것도 아니다. 학습하지 않은 사례로 관계를 확장하는 **일반화**가 중요하다.

### 특징: 모델이 사용하는 단서

**특징(feature)**은 입력을 설명하거나 예측에 사용하는 정보다.

| 자료 | 특징의 예 |
| --- | --- |
| 이미지 | 색·모양·윤곽 또는 학습된 이미지 표현 |
| 문장·이메일 | 단어의 등장, 문맥을 반영한 표현 |
| 학습 기록 | 접속 빈도, 진도, 시청 시간 |
| 판매 기록 | 요일, 행사 여부, 과거 판매량 |

특징은 사람이 설계할 수도 있고 모델이 학습할 수도 있다. 딥러닝은 표현을 학습하는 데 중요한 역할을 하지만, 데이터·입력 방식·구조를 정하는 사람의 역할까지 없어지는 것은 아니다.

### 패턴: 사례 사이의 반복되는 관계

**패턴(pattern)**은 여러 사례에서 나타나는 공통점이나 통계적 관계를 뜻한다. 특징은 개별 단서이고, 패턴은 그 단서들과 결과 등이 어떻게 연결되는지에 관한 것이다.

| 구분 | 스팸메일 예시 |
| --- | --- |
| 입력 데이터 | 이메일 제목·본문 등 |
| 특징 | 특정 표현의 등장, 링크 관련 정보 등 |
| 라벨 | 스팸 / 정상 |
| 패턴 | 일부 특징과 스팸 라벨이 함께 나타나는 경향 |
| 모델 | 학습한 관계를 이용해 새 메일의 결과를 계산하는 구조 |

모든 머신러닝 모델이 저장된 사례와의 거리만 비교하는 것은 아니다. 강의의 ‘기존 패턴에 더 가깝다’는 표현은 학습한 관계를 적용한다는 입문용 비유로 읽는다.

## 잘못된 단서를 학습할 수 있다

4강의 실내 고양이·야외 개 사례처럼, 사람이 의도한 단서와 모델이 실제로 활용한 단서는 다를 수 있다.

### 강의의 치와와·블루베리 머핀 사례

강의는 치와와의 눈·코 배치와 머핀의 블루베리 배치가 비슷해 보이는 이미지를 소개한다. 일부 시각적 단서만으로 판단하면 혼동할 수 있다는 설명이다.

다만 스크립트만으로 특정 모델이 실제로 눈·코의 위치를 학습해 오분류했다는 실험 결과를 확인할 수는 없다. **유사성을 보여 주는 예시와 모델의 실제 오류 원인을 입증한 분석을 구별**한다.

모델이 무엇을 단서로 삼았는지는 입력 조건을 바꾸거나 오류 사례를 분석하는 등 별도 확인이 필요하다.

## 인공신경망과 딥러닝

**인공신경망(artificial neural network)**은 여러 계산 단위를 연결해 입력으로부터 출력을 만드는 머신러닝 모델의 한 종류다.

```text
입력 특징 → 연결된 계산 단위 → 중간 표현 → 출력
```

강의의 ‘작은 판단 단위’는 계산을 설명하기 위한 비유다. 각 단위가 사람처럼 판단하거나 의미를 경험한다는 뜻은 아니다.

### 층을 거치며 표현을 학습하기

딥러닝은 여러 처리 층을 통해 데이터의 표현을 학습한다. LeCun·Bengio·Hinton의 2015년 논문도 여러 추상 수준의 표현 학습을 핵심으로 설명한다. [Deep learning](https://doi.org/10.1038/nature14539)

| 구분 | 의미 |
| --- | --- |
| 머신러닝 | 데이터·경험에서 학습하는 넓은 분야 |
| 인공신경망 | 머신러닝에서 사용하는 모델 계열 |
| 딥러닝 | 여러 처리 층을 활용하는 표현 학습 접근 |

‘작은 부분에서 점점 큰 부분을 본다’는 설명은 일부 이미지 모델을 이해하기에 유용하다. 모든 신경망이 같은 공간적 순서로 처리하거나, 층을 늘리기만 하면 성능이 좋아진다는 뜻은 아니다.

**신경망이라는 모델 종류와 지도·비지도·강화학습이라는 학습 방식은 서로 다른 분류 기준**이다. 신경망은 여러 학습 방식에서 활용될 수 있다.

## 학습 방식 한눈에 비교하기

| 방식 | 주로 사용하는 정보 | 배우려는 것 | 강의의 예 |
| --- | --- | --- | --- |
| 지도학습 | 입력과 목표 라벨·값 | 입력에서 목표값을 예측하는 관계 | 스팸 분류, 매출 예측 |
| 비지도학습 | 목표 정답 라벨이 없는 자료 | 자료의 구조·관계 | 고객 군집, 문서 묶기 |
| 준지도학습 | 라벨 있는 자료와 없는 자료 | 두 종류의 자료를 활용한 예측 관계 | 일부 라벨을 활용한 학습 |
| 강화학습 | 행동·환경 변화·보상 등의 경험 | 장기 보상을 높이는 행동 전략 | 게임, 로봇 제어 |

이는 대표적인 구분이다. 하나의 실제 시스템이 여러 방식을 함께 사용하기도 한다.

## 지도학습: 입력과 목표값의 관계 배우기

**지도학습(supervised learning)**은 입력과 그에 대응하는 목표 라벨·값을 이용하는 학습이다.

1. 사진과 고양이·개 라벨처럼 입력과 목표값을 준비한다.
2. 모델이 입력과 목표값 사이의 관계를 학습한다.
3. 학습에 쓰지 않은 새 사례를 입력한다.
4. 예측 결과를 실제 정답과 비교해 성능을 평가한다.

라벨이 있다는 사실만으로 모델이 올바른 특징을 학습하거나 새 사례를 정확히 맞힌다고 보장되지는 않는다.

### 분류와 회귀

| 문제 | 출력의 형태 | 예 |
| --- | --- | --- |
| 분류(classification) | 범주 | 고양이/개, 스팸/정상, 긍정/부정 |
| 회귀(regression) | 수치 | 기온, 매출액, 가격 등의 추정 |

‘예측’은 회귀만을 뜻하지 않는다. 분류도 예측에 포함된다. 또한 위험도를 높음·낮음의 범주로 구분하는지, 수치나 확률로 추정하는지에 따라 문제 설정이 달라진다. 출력이 숫자라는 이유만으로 모든 과제를 회귀라고 부르지 않는다.

### 스팸메일에서 생각할 두 오류

| 실제 상태와 예측 | 발생할 수 있는 문제 |
| --- | --- |
| 정상 메일을 스팸으로 판단 | 중요한 메일을 놓침 |
| 스팸메일을 정상으로 판단 | 원하지 않는 메일을 받음 |

두 오류의 영향은 다르다. 따라서 맞힌 비율만 아니라 어떤 오류가 발생했고 어떻게 처리할지도 검토한다. 강의의 스팸 사례는 특정 서비스의 내부 알고리즘을 확인한 설명은 아니다.

### 지도학습에서도 일반화가 중요하다

4강에서 배운 것처럼 라벨의 오류·모호함, 자료의 편중, 과적합과 데이터 누수 등을 점검한다.

일반화는 학습한 사례를 넘어 적용하는 능력이지만, **학습 환경과 전혀 다른 모든 상황에서도 성공한다는 보장은 아니다.** 실제 적용 대상과 조건에 맞는 평가가 필요하다.

## 비지도학습: 정답 라벨 없이 구조 찾기

**비지도학습(unsupervised learning)**은 정답 라벨 없이 자료의 구조나 관계를 찾는 접근이다. 강의는 그중 군집화에 초점을 둔다.

### 군집화와 분류의 차이

| 구분 | 분류 | 군집화(clustering) |
| --- | --- | --- |
| 기준 | 학습 때 주어진 목표 범주 | 선택한 특징과 유사성 등의 기준 |
| 목적 | 정해진 범주를 예측 | 비슷한 자료의 묶음을 탐색 |
| 해석 | 라벨의 정의와 오류를 확인 | 묶음이 무엇을 의미하는지 검토 |

군집은 사용하는 특징·거리·알고리즘·설정에 따라 달라질 수 있다. 비지도학습 전체가 군집화만을 뜻하는 것은 아니다. [scikit-learn: Clustering](https://scikit-learn.org/1.7/modules/clustering.html)

### 구매 기록을 묶는 강의 사례

| 관찰할 수 있는 경향 | 붙여 볼 수 있는 해석 | 추가로 확인할 것 |
| --- | --- | --- |
| 할인 상품 구매가 많음 | 가격에 민감한 집단 | 행사 노출이나 구매 기회 차이는 없는가? |
| 신상품 구매가 많음 | 신상품에 관심이 많은 집단 | 일부 기간에만 나타난 패턴은 아닌가? |
| 같은 브랜드를 반복 구매 | 브랜드 충성도가 높은 집단 | 다른 선택지가 없었던 것은 아닌가? |

집단의 이름은 데이터 묶음에서 자동으로 확정된 사실이 아니라 **검토할 해석**이다. 할인 쿠폰·신제품 홍보·구독 제안 같은 후속 활동도 그 효과를 따로 확인해야 한다.

### 문서를 주제별로 묶는 사례

기사·보고서의 단어와 문맥 표현 등을 이용해 유사한 문서를 묶을 수 있다. 이후 대표 문서를 읽고 이름과 의미를 검토한다.

같은 제품명이 반복되는 두 문서라도 하나는 광고이고 다른 하나는 제품 비판일 수 있다. 같은 묶음이라고 같은 입장이나 사회적 의미를 가진다고 단정하지 않는다.

AI가 군집 이름을 제안하게 할 수도 있지만, 그 이름 역시 내용과 목적에 맞는지 확인해야 한다.

## 준지도학습: 라벨 있는 자료와 없는 자료 함께 활용하기

**준지도학습(semi-supervised learning)**은 일부 사례에만 라벨이 있는 자료를 활용하는 접근이다. 소량의 라벨 있는 데이터와 더 많은 라벨 없는 데이터를 결합하는 상황이 대표적이다. [scikit-learn: Semi-supervised learning](https://scikit-learn.org/1.7/modules/semi_supervised.html)

### 왜 사용하는가?

라벨 작성에는 시간·비용·전문성이 필요할 수 있다. 라벨 없는 자료까지 활용하면 제한된 라벨로도 학습을 개선할 가능성이 있다.

강의는 이미 라벨이 있는 사례를 활용해 유사한 사례에 라벨을 부여하는 방식으로 설명한다. 실제로는 예측한 라벨을 학습에 활용하는 자기훈련이나 유사성 관계로 라벨을 전파하는 방법 등이 있다.

### 원문의 단정 보완

- 라벨이 있는 자료가 언제나 라벨 없는 자료보다 ‘정확하다’고 비교하지 않는다. 라벨의 존재와 데이터 품질은 다른 속성이다.
- 지도학습과 비지도학습은 목적과 평가 방식이 달라 일반적인 성능 순위를 매기기 어렵다.
- 라벨 없는 데이터를 추가했다고 성능이 반드시 좋아지지는 않는다. 자료의 분포와 학습 가정이 맞아야 한다.
- 모델이 추정한 라벨을 그대로 정답 취급하면 잘못된 예측을 학습에 다시 반영할 수 있다.

공식 문서도 준지도학습의 성능 향상에는 데이터 분포에 대한 가정이 필요함을 설명한다. [scikit-learn: 준지도학습의 가정과 자기훈련](https://scikit-learn.org/1.7/modules/semi_supervised.html)

## 강화학습: 행동의 결과에서 배우기

**강화학습(reinforcement learning)**은 환경과 상호작용하는 에이전트가 보상을 바탕으로 행동 전략을 학습하는 접근이다.

| 요소 | 의미 |
| --- | --- |
| 에이전트(agent) | 행동을 선택하는 학습 주체 |
| 환경(environment) | 행동에 따라 상태가 달라지고 관찰·보상이 발생하는 대상 |
| 관찰·상태 정보 | 행동 선택에 참고하는 상황 정보 |
| 행동(action) | 이동·점프·정지 등 선택 가능한 동작 |
| 보상(reward) | 행동의 결과를 평가하는 수치 신호 |
| 정책(policy) | 상황에 따라 행동을 선택하는 전략 |

```text
상황 관찰 → 행동 선택 → 환경의 변화
    ↑                       ↓
다음 상황에서 시도 ← 보상·경험으로 학습
```

보상은 사람이 매번 직접 주는 칭찬을 뜻하지 않는다. 설계한 기준에 따라 환경이나 평가 절차에서 계산할 수 있다.

### 보충: 당장의 점수와 장기 보상

강화학습의 목표는 일반적으로 당장의 보상 하나보다 **장기적으로 얻는 누적 보상**을 높이는 것이다. 지금 점수가 낮아지는 행동도 이후 더 큰 보상에 도움이 되면 선택할 수 있다. [Sutton·Barto: Reinforcement Learning, 2판 소개](https://mitpress.ublish.com/book/reinforcement-learning-an-introduction-2)

강의의 ‘점수를 잃은 행동은 하지 않는다’는 설명은 직관을 위한 단순화다. 보상이 늦게 주어질 수 있고, 더 좋은 행동을 찾기 위한 탐색도 필요하다.

### 게임 예시

| 단계 | 가상의 게임 상황 |
| --- | --- |
| 관찰 | 캐릭터 위치·장애물·점수 확인 |
| 행동 | 왼쪽 이동, 점프, 정지 등 선택 |
| 결과 | 장애물 통과 또는 충돌 |
| 보상 | 통과에 양의 점수, 충돌에 음의 점수 부여 |
| 학습 | 이후의 행동 전략에 경험 반영 |

이 예의 점수는 설명을 위한 설정이다. 모든 강화학습이 매 행동 직후 모델을 갱신하는 것도 아니며, 학습된 정책을 실제로 실행할 때 항상 계속 학습하는 것도 아니다.

## 보상 설계와 사람의 의도

**보상이 높다는 것과 사람이 실제로 원하는 결과가 같다는 것은 별도로 확인해야 한다.** 보상은 목적을 수치로 표현한 것이어서 중요한 조건을 빠뜨릴 수 있다.

| 보상 기준의 예 | 의도 | 놓칠 수 있는 요소 |
| --- | --- | --- |
| 클릭 수만 높임 | 관심 있는 콘텐츠 제공 | 유익함·다양성·선택권 |
| 이동 속도만 높임 | 빠르게 목적지 도착 | 안전·규칙 준수·주변 사람 |
| 생산량만 높임 | 효율적인 작업 | 품질·손상·사고 위험 |

강의의 추천 사례는 클릭만 최적화하면 자극적인 콘텐츠가 유리해질 가능성을 설명한다. 모든 추천 서비스가 강화학습을 사용하거나 반드시 같은 결과를 낸다는 사실 주장으로 확대하지 않는다.

### 로봇·자율주행 사례

로봇과 차량의 행동은 물리적 환경에 영향을 준다. 게임에서의 실패와 달리 사람이나 물체에 피해가 생길 수 있다.

따라서 보상뿐 아니라 적용 조건, 안전 제약, 감독과 중단 방법 등을 함께 설계해야 한다. 안전을 보상 항목으로 넣었다는 사실만으로 사고가 방지되는 것은 아니다.

이들은 강화학습을 연구·활용할 수 있는 분야의 예다. **모든 로봇과 자율주행 시스템이 강화학습만으로 작동하거나 실제 도로에서 무제한 시행착오로 학습한다는 뜻은 아니다.**

## 예측·상관관계·인과관계 구분하기

### 예측이 맞으면 원인도 밝혀진 것인가?

모델은 함께 나타나는 단서와 결과의 관계를 이용해 예측할 수 있다. 하지만 예측 성능만으로 어떤 단서를 바꾸면 결과가 어떻게 달라지는지 확정할 수는 없다.

| 개념 | 질문 |
| --- | --- |
| 예측 | 주어진 정보에서 어떤 결과가 나올 것으로 추정하는가? |
| 상관관계 | 두 현상이 함께 변하거나 나타나는가? |
| 인과관계 | 어떤 요인에 개입하면 결과가 달라지는가? |

함께 움직이는 현상에는 제3의 요인이나 다른 맥락이 작용할 수 있다. 원인과 결과의 방향이 생각과 다를 수도 있다.

### 보충 예제: 접속 시간과 성적

다음은 3~4강의 학습 기록 사례를 연결한 가정이다.

```text
강의 접속 시간이 긴 학생의 성적이 높게 나타남
≠ 접속 시간만 늘리면 반드시 성적이 높아짐
```

기존 학습 수준, 공부할 수 있는 시간, 교재 학습 등의 요인이 관련될 수 있다. 화면을 켜 두는 시간만 늘리는 처방이 실제 학습 효과를 만든다고 단정할 수는 없다.

이는 머신러닝이 원인 연구에 사용될 수 없다는 뜻이 아니다. **일반적인 예측 결과만으로 인과효과가 입증되지 않는다**는 뜻이다. 개입의 효과를 묻는다면 적절한 연구 설계와 가정, 근거를 추가로 검토해야 한다.

## 결과를 해석할 때의 네 가지 질문

| 질문 | 점검할 내용 |
| --- | --- |
| 무엇으로 배웠는가? | 데이터·라벨·보상·학습 목표 |
| 어떤 사례로 배웠는가? | 대상 집단·환경·기간·대표성 |
| 어떤 단서를 사용했는가? | 특징·학습된 관계·의도와 다른 단서 |
| 어디서 틀릴 수 있는가? | 새로운 조건, 자료의 누락, 오류의 영향 |

모델이 제시한 설명도 검토 대상이다. 자연어로 그럴듯한 이유를 출력했다고 해서 실제 내부 계산의 원인이나 현실의 인과관계를 정확히 설명했다고 가정하지 않는다.

강의가 강조하는 사람의 판단은 답을 임의로 참·거짓으로 정한다는 뜻이 아니다. 근거와 평가 결과를 확인하고, 사용 목적과 맥락에 비추어 채택 여부를 결정하는 것이다.

10. 예측 성능과 인과관계를 구별해야 하는 이유는 무엇인가?
