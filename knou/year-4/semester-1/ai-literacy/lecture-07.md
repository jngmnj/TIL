# 7강. 생성형 AI와 대규모 언어 모델

- 학습일: 2026-09-25
- 과목: AI 리터러시
- 주제: 생성형 AI, LLM, 토큰, 어텐션, 트랜스포머, 학습과 생성, 결과 검증

## 핵심 요약

**생성형 AI는 학습한 패턴을 바탕으로 글·이미지·음악·코드·영상 등의 콘텐츠를 만드는 기술이다.** 대규모 언어 모델은 그중 언어를 다루는 대표적인 모델이며, 자연스러운 출력이 사실성과 적절성을 보장하지는 않는다.

| 핵심 개념 | 의미 |
| --- | --- |
| 생성형 AI | 입력 조건과 학습된 패턴을 바탕으로 콘텐츠를 생성 |
| 대규모 언어 모델(LLM) | 많은 언어 자료에서 표현과 관계를 학습한 모델 |
| 토큰 | 모델이 텍스트를 처리하는 단위 |
| 어텐션 | 입력 표현 사이의 관계를 계산해 정보를 조합하는 방식 |
| 사전학습·미세조정 | 모델의 매개변수를 학습하는 과정 |
| 프롬프트 | 요청의 목적·자료·조건 등을 전달하는 입력 |
| 환각 | 사실과 다르거나 근거 없는 내용을 그럴듯하게 생성하는 오류 |
| 문맥창 | 한 번의 처리에서 모델이 다룰 수 있는 문맥의 범위 |

강의는 수학적 유도보다 작동 원리와 활용 시 검토할 사항을 중심으로 설명한다. 기술적 단순화로 오해가 생길 수 있는 부분은 아래 보충 설명에서 구분한다.

## 1. 생성형 AI의 개념

### 분류·예측과 콘텐츠 생성

| 구분 | 주된 작업 | 결과 예 |
| --- | --- | --- |
| 분류·예측 중심의 AI 활용 | 주어진 자료의 범주나 값을 추정 | 스팸 여부, 수요 예측 |
| 생성형 AI 활용 | 입력에 맞는 콘텐츠를 생성 | 설명문, 이미지, 코드 초안 |

강의의 ‘기존 AI’는 비교를 위한 표현이며 엄밀한 학술 분류가 아니다. 생성형 AI 역시 머신러닝·딥러닝을 활용할 수 있고, 하나의 서비스가 분류·검색·생성을 함께 수행할 수도 있다.

또한 **모델과 서비스는 구별해야 한다.** 모델이 출력을 계산한다면, 서비스는 여기에 사용자 화면, 검색, 파일 처리 등 여러 기능을 결합할 수 있다. 서비스가 수행한 모든 일을 하나의 언어 모델이 직접 수행했다고 가정하지 않는다.

### 검색·복사·생성의 차이

| 방식 | 기본 역할 | 확인할 점 |
| --- | --- | --- |
| 검색 | 기존 자료를 찾아 제시 | 출처, 작성 시점, 원문의 맥락 |
| 복사 | 기존 내용을 그대로 옮김 | 원문과의 일치, 인용과 사용 조건 |
| 생성 | 학습한 패턴과 입력 조건을 바탕으로 출력 구성 | 사실성, 기존 자료와의 유사성, 사용 목적 |

생성은 학습 자료를 단순히 잘라 붙이는 것과 같지 않으며, 검색 기능 자체도 아니다. 다만 기존 표현을 재현하거나 자료와 매우 비슷한 출력을 만들 가능성이 있으므로 **새로 생성되었다는 이유만으로 독창성이나 자유로운 사용이 보장되지는 않는다.**

강의의 ‘파생 콘텐츠’는 학습한 자료의 영향을 받는다는 설명으로 이해한다. 모든 생성 결과에 특정한 법적 지위를 부여하는 표현으로 사용하지 않는다.

### 학습에서 활용할 수 있는 작업

| 작업 | 활용 예 | 사용자가 확인할 일 |
| --- | --- | --- |
| 자료 탐색 | 검색어·조사 관점 제안 | 실제 자료와 출처가 존재하는지 확인 |
| 읽기와 요약 | 어려운 설명을 쉬운 말로 정리 | 원문의 의미와 예외가 보존됐는지 대조 |
| 과제·보고서 | 목차와 초안 작성 | 사실·논리 검토 후 자신의 설명으로 재구성 |
| 발표 준비 | 구성과 설명 순서 제안 | 청중, 목적, 근거에 맞게 수정 |
| 코딩 학습 | 예제와 오류 메시지 설명 | 원리 이해, 실행·테스트, 환경 적합성 확인 |

개인적인 학습에서도 잘못된 정보를 익힐 수 있으므로 검토가 필요하다. 과제에서 허용되는 AI 사용 범위와 표시 방법은 해당 과목의 지침을 확인한다.

## 2. LLM은 텍스트를 어떻게 생성하는가?

### 대규모 언어 모델이란?

**LLM(Large Language Model)**은 대규모 언어 자료에서 단어·표현의 관계, 문맥, 문체 등의 패턴을 학습한 모델이다. 학습 자료의 종류와 구성은 모델마다 다르다.

이 강의에서는 특히 **주어진 문맥을 바탕으로 다음 토큰을 생성하는 자기회귀 언어 모델**을 중심으로 살펴본다. 모든 언어 모델과 모든 생성형 AI가 동일한 방식으로 작동한다는 뜻은 아니다.

### 토큰과 토큰화

토큰은 모델이 텍스트를 처리하기 위해 사용하는 단위다. 토큰화는 문자열을 단위로 나누고, 모델이 처리할 수 있는 식별자 등으로 변환하는 과정이다.

```text
입력 문장 → 토큰화 → 수치 표현 → 모델의 계산
생성된 토큰 식별자 → 문자열로 변환 → 출력 문장
```

- 토큰은 단어 하나일 수도 있고, 단어의 일부나 문장부호 등에 해당할 수도 있다.
- 토큰 경계는 사람이 생각하는 단어·의미의 경계와 항상 같지 않다.
- 같은 문장도 언어와 토크나이저에 따라 토큰 수가 달라질 수 있다.
- **‘1토큰 = 4~5글자’를 한국어를 포함한 보편적인 규칙으로 사용하면 안 된다.**

강의의 ‘오늘 날씨가 춥다’를 여러 조각으로 나누는 예시는 개념 설명용이다. 특정 모델을 정하지 않은 상태에서 실제 토큰 개수나 분할 결과를 확정하지 않는다.

> 보충 출처: Hugging Face의 [Tokenizers](https://huggingface.co/learn/llm-course/chapter2/4)는 단어·문자·하위 단어 등 토큰화 방식의 차이와 식별자로의 변환을 설명한다.

### 문맥과 다음 토큰 예측

모델은 현재 제공된 문맥과 이미 생성한 부분을 바탕으로 다음 토큰 후보의 확률을 계산한다. 선택한 토큰을 덧붙이고 이 과정을 반복한다.

```text
현재 문맥 → 다음 토큰의 확률 계산 → 토큰 선택
         → 문맥에 추가 → 다음 토큰 생성 반복
```

예를 들어 ‘AI 결과는 빠르지만’ 뒤에 ‘검토가 필요합니다’라는 표현을 이어갈 수 있다. 이는 강의 내용을 설명하는 예시이며, 특정 모델이 실제로 계산한 확률을 제시한 것은 아니다.

**항상 확률이 가장 높은 토큰만 고르는 것은 아니다.** 최댓값을 고르는 방식도 있고, 확률분포에서 후보를 뽑는 샘플링 방식도 있다. 생성 설정 등에 따라 같은 요청에 다른 답이 나올 수 있다. [Hugging Face: Generation strategies](https://huggingface.co/docs/transformers/generation_strategies)

여기서 토큰의 선택 확률은 **그 내용이 현실에서 참일 확률과 같지 않다.** 문맥에 잘 어울리는 문장인지와 사실인지는 별도로 확인해야 한다.

### 어텐션과 트랜스포머

| 개념 | 역할 | 오해하지 말아야 할 점 |
| --- | --- | --- |
| 어텐션(attention) | 표현 사이의 관계를 바탕으로 정보를 가중하여 조합 | 사람이 의식적으로 주의를 기울이는 행위와 동일하지 않음 |
| 트랜스포머(Transformer) | 어텐션 등을 활용하는 신경망 구조 | 어텐션 자체와 구조 전체는 같은 말이 아님 |

강의의 예시인 ‘철수는 우산을 챙겼다. 비가 왔기 때문이다’에서는 인물·행동·이유 사이의 관계가 문맥 해석에 중요하다. 어텐션은 이런 관계를 반영하는 데 활용될 수 있지만, 특정 어텐션 값이 현실의 인과관계를 입증하는 것은 아니다.

트랜스포머는 여러 위치의 관계를 병렬적으로 계산할 수 있다. 다만 **학습·입력 처리의 병렬성과 답변 전체를 한 번에 생성한다는 주장은 다르다.** 일반적인 자기회귀 생성은 앞서 생성된 토큰에 이어 다음 토큰을 순차적으로 만든다.

> 보충 출처: Vaswani 외, [Attention Is All You Need](https://arxiv.org/abs/1706.03762). 트랜스포머는 어텐션을 중심으로 한 구조이며, 원 논문의 디코더도 출력을 자기회귀적으로 생성한다.

## 3. 모델을 학습하는 과정

### 사전학습

사전학습은 많은 자료로 모델의 기본적인 표현과 능력을 학습하는 단계다. 강의에서 다루는 다음 토큰 예측에서는 텍스트 자체에서 예측 대상이 만들어진다.

```text
텍스트의 일부 제공 → 다음 토큰 예측 → 실제 토큰과 비교
                 → 오차에 따라 매개변수 조정 → 반복
```

사람이 문장마다 정답을 직접 붙이지 않아도 학습 신호를 얻을 수 있다는 의미에서 자기지도학습으로 설명할 수 있다. ‘라벨 없이 학습한다’고 해서 목표나 정답 역할을 하는 정보가 전혀 없다는 뜻은 아니다.

사전학습 모델은 이후의 요약·번역·질의응답 등 다양한 작업의 출발점이 될 수 있다. 다음 토큰 예측은 대표적인 방식이며, 사전학습의 모든 목표가 이것으로 한정되는 것은 아니다.

### 미세조정

**미세조정(fine-tuning)**은 이미 학습된 모델을 추가 데이터와 목표에 맞춰 더 학습시키는 과정이다.

| 활용 방향 | 예시 |
| --- | --- |
| 과제 수행 | 특정 분류·요약 등의 작업에 맞춤 |
| 응답 방식 | 원하는 설명 수준이나 형식을 학습 |
| 분야 적합성 | 특정 분야의 자료와 표현에 맞춤 |
| 행동 기준 | 지시 준수나 바람직한 응답 방향을 학습 |

미세조정은 말투만 바꾸는 작업으로 제한되지 않는다. 작업 성능이나 사실성·안전성을 개선하는 데 사용될 수도 있다. 다만 **개선을 목표로 학습했다는 사실이 정확성이나 안전성을 보장하지는 않는다.** 별도의 평가가 필요하다. [Hugging Face: Fine-tuning](https://huggingface.co/docs/transformers/main/training)

### 인간 피드백 기반 강화학습

**RLHF(Reinforcement Learning from Human Feedback)**는 사람의 평가를 학습 신호로 활용해 모델의 행동을 조정하는 접근이다.

대표적인 절차의 한 예는 다음과 같다.

1. 사람이 모델의 여러 답변을 비교·평가한다.
2. 이 평가 자료로 선호를 예측하는 보상 모델을 학습한다.
3. 보상 신호를 활용해 언어 모델을 강화학습으로 조정한다.

이 방식은 사람이 선호하는 답변 방향을 학습하는 데 도움을 줄 수 있다. 평가자의 기준이나 자료의 한계도 영향을 미치므로, 선호도가 높다고 반드시 사실이거나 모든 사용자에게 적절한 것은 아니다. [Ouyang 외: Training language models to follow instructions with human feedback](https://arxiv.org/abs/2203.02155)

**화면에서 답변 하나를 선택했다고 그 순간 서비스의 모델 가중치가 바로 바뀐다고 단정할 수는 없다.** 비교 화면은 평가 자료를 수집하는 과정일 수 있으며, 실제 사용 여부와 학습 시점은 서비스마다 다르다. 모든 피드백 활용 방식이 RLHF인 것도 아니다.

### 학습과 사용 구별하기

| 구분 | 무엇이 달라지는가? |
| --- | --- |
| 사전학습 | 대규모 자료로 모델의 매개변수를 학습 |
| 미세조정·RLHF | 추가 목표와 자료를 이용해 모델을 조정 |
| 프롬프트 입력 | 현재 답변을 생성할 조건과 문맥을 제공 |

대화에서 예시나 조건을 추가하는 것은 일반적으로 현재 입력을 바꾸는 일이다. 이를 곧바로 모델의 매개변수를 바꾸는 미세조정과 동일시하지 않는다.

## 4. 프롬프트와 활용

### 목적·맥락·형식·제약 전달하기

프롬프트는 모델에게 요청과 필요한 정보를 전달하는 입력이다.

| 요소 | 예시 |
| --- | --- |
| 목적 | 강의 내용을 복습하려고 함 |
| 대상과 수준 | 대학 1학년이 이해할 수 있는 설명 |
| 자료 | 제공한 강의 원문 |
| 형식 | 핵심 개념 비교표와 복습 질문 |
| 제약 | 원문에 없는 통계는 만들지 않고 불확실한 내용은 표시 |

아래는 강의 내용을 바탕으로 구성한 연습용 예시다.

```text
제공한 강의 원문을 대학 1학년 수준으로 정리해 줘.
핵심 개념을 비교표로 만들고 복습 질문 5개를 덧붙여 줘.
원문에 없는 사실이나 수치는 만들지 말고,
보충 설명이 필요하면 원문 내용과 구분해 줘.
```

목적과 조건을 명확하게 적으면 원하는 결과를 얻는 데 도움이 된다. 다만 길거나 세세한 요청이 항상 더 좋은 것은 아니며, 모순된 조건은 피해야 한다. ‘사실만 써 달라’는 지시도 검증을 대신하지 않는다.

### 코드 생성과 학습

코드 초안 작성, 오류 메시지 해설, 기능 구현 예시 등에 활용할 수 있다. 적용 전에는 다음을 확인한다.

- 코드의 입력·출력과 처리 흐름을 설명할 수 있는가?
- 자신의 언어·라이브러리·실행 환경에서 작동하는가?
- 정상 입력과 예외 상황을 테스트했는가?
- 프로젝트에 미치는 영향과 보안상 문제를 검토했는가?
- 외부 코드가 포함되었다면 출처와 사용 조건을 확인했는가?

이해 없이 붙여 넣으면 오류를 찾기 어렵고 학습 효과도 줄어들 수 있다. AI가 ‘문제없다’고 다시 답한 것만으로 검토가 끝나지는 않는다.

### 멀티모달 AI

**멀티모달 AI**는 텍스트·이미지·음성·영상 등 여러 종류의 자료를 함께 다루는 AI다.

| 입력·작업 예 | 활용 방향 |
| --- | --- |
| 강의 영상 | 내용을 요약하고 핵심 구간 정리 |
| 문서와 이미지 | 도표나 그림을 문서 맥락과 함께 질문 |
| 회의 음성 | 발언을 텍스트로 옮기고 정리 |
| 사진과 질문 | 시각 정보에 관한 설명 생성 |

자료를 수치적 표현으로 바꾸고 여러 정보의 관계를 활용한다는 점이 중요하다. 다만 **모든 모델이 모든 형식을 지원하거나 반드시 하나의 시퀀스로 통합하는 것은 아니다.** 처리 구조, 지원 입력, 출력 범위는 모델과 서비스마다 확인해야 한다.

## 5. 생성형 AI의 한계

### 환각: 그럴듯함과 사실성의 차이

환각은 사실과 다르거나 제공된 근거로 뒷받침되지 않는 내용을 그럴듯하게 생성하는 현상이다. 없는 논문·틀린 날짜·잘못된 통계·존재하지 않는 출처 등이 예가 될 수 있다.

> 강의의 ‘어떤 연구에서 정확도가 98.7%로 입증되었다’는 문장은 **환각을 설명하기 위한 가상 사례**다. 실제 연구 결과나 성능 수치로 인용하지 않는다.

학습 자료의 공백, 모호한 질문, 생성 과정의 한계 등이 오류에 영향을 줄 수 있다. 자연스러운 문장이 생성되는 과정과 사실 확인 과정은 같지 않다. 이를 사람의 의도적인 거짓말과 동일시할 필요도 없다.

### 최신 정보의 한계

학습 이후에 새로 생기거나 바뀐 정보는 모델의 매개변수에 반영되지 않았을 수 있다. 따라서 현재 사건이나 조건은 공식 최신 자료와 대조해야 한다.

검색이나 외부 자료 조회 기능이 결합된 서비스는 최근 자료를 답변에 사용할 수 있다. 하지만 **최신 자료에 접근한 것과 정확하게 답한 것은 별개**다. 자료의 날짜·원문·인용된 맥락을 확인한다. 모든 모델이 정해진 주기로 재학습된다고 가정하지 않는다.

### 문맥창의 한계

문맥창(context window)은 모델이 한 번에 처리할 수 있는 문맥의 범위를 뜻하며, 텍스트 모델에서는 주로 토큰 수로 나타낸다. 강의의 ‘조건 몇 개까지 반영한다’는 설명은 비유이며 실제 용량 단위가 아니다.

| 상황 | 생길 수 있는 문제 | 대응 |
| --- | --- | --- |
| 입력이 허용 범위를 초과 | 요청 거절, 일부 생략·요약 등 서비스별 처리 | 입력 범위와 처리 방식을 확인 |
| 범위 안이지만 내용이 길고 복잡 | 중요한 조건을 놓치거나 관계를 잘못 연결 | 작업을 나누고 핵심 조건을 명시 |
| 자료를 나누어 처리 | 부분 사이의 관계나 예외가 빠짐 | 마지막에 원문과 통합 결과를 대조 |

범위 안에 들어간 내용도 모두 정확하게 활용된다고 보장되지는 않는다. 반대로 긴 자료를 나누기만 하면 정확성이 보장되는 것도 아니다.

## 6. 결과를 검증하는 세 가지 관점

| 관점 | 확인할 질문 | 문제가 있을 때 |
| --- | --- | --- |
| 사실 검증 | 출처·통계·날짜·인용이 실제 자료와 일치하는가? | 원문을 찾고 확인되지 않은 주장은 제외하거나 불확실성 표시 |
| 논리 검증 | 주장과 근거가 연결되는가? 전제·반례를 빠뜨리지 않았는가? | 비약·모순·과장을 수정하고 추가 근거 확인 |
| 가치 검증 | 특정 집단에 불리하거나 피해를 유발할 수 있는가? | 영향을 검토하고 필요하면 사용 보류·전문가 확인 |

AI에게 ‘이거 진짜야?’라고 다시 묻는 것은 검증의 보조가 될 수 있지만 독립적인 사실 확인을 대신하지 못한다. 링크가 있다는 것만으로도 부족하며, 연결된 원문이 실제 주장을 뒷받침하는지 읽어야 한다.

건강·법률·안전처럼 오류의 피해가 큰 영역은 더 신중한 검토가 필요하다. 개인정보나 민감한 자료를 입력하기 전에는 사용 권한과 서비스의 자료 처리 조건을 확인한다.

### 좋은 활용과 주의할 활용

| 좋은 활용 방향 | 주의할 활용 |
| --- | --- |
| 어려운 개념의 설명을 받아 원문과 비교 | 그럴듯한 설명을 확인 없이 암기 |
| 여러 목차 후보를 비교하고 목적에 맞게 선택 | 생성된 보고서를 그대로 제출 |
| 자신의 글에서 논리의 빈틈을 찾는 데 활용 | 출처를 확인할 수 없는 인용·통계 사용 |
| 코드를 이해하고 테스트한 뒤 적용 | 동작과 영향을 모른 채 프로젝트에 삽입 |

강의는 AI의 산출물을 **검토할 초안이나 후보**로 다루는 태도를 강조한다. 제출·배포 전에는 목적에 맞게 확인하고 수정해야 하며, 단순히 문장을 바꿨다는 이유로 내용이 사실이 되거나 사용상의 문제가 해결되는 것은 아니다.
