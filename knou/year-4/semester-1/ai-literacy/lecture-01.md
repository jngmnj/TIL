# 1강. AI 리터러시란 무엇인가

- 학습일: 2026-09-19
- 과목: AI 리터러시
- 주제: 이해·활용·평가·윤리, 학습 환경의 변화, AI를 바라보는 세 가지 관점

## 핵심 요약

**AI 리터러시는 AI를 사용할 줄 아는 것을 넘어, 원리와 한계를 이해하고 결과를 평가하며 책임 있게 활용하는 능력이다.**

AI가 만든 문장이 자연스럽다는 이유만으로 사실이라고 판단하지 않는다. 산출물을 출발점으로 삼아 근거·논리·맥락을 확인하고, 자신의 이해를 바탕으로 수정·재구성하는 것이 이번 강의의 핵심이다.

| 구분 | 기능 사용에 머무르는 경우 | AI 리터러시를 갖춘 활용 |
| --- | --- | --- |
| 질문 | 원하는 답을 출력하게 함 | 목적과 조건을 분명히 정함 |
| 읽기 | 자연스러우면 그대로 받아들임 | 주장·근거·누락된 관점을 구분 |
| 활용 | 출력물을 그대로 제출·공유 | 확인하고 수정한 내용을 자신의 말로 구성 |
| 책임 | AI가 만든 결과라고 넘김 | 입력 자료와 활용 결과의 영향을 검토 |

## 과목 오리엔테이션

### 강의의 네 가지 목표

1. **기본 원리와 한계 이해**: AI가 무엇을 할 수 있고 어디에서 오류가 생길 수 있는지 파악한다.
2. **비판적 검토 능력 형성**: AI가 제시한 사실·논리·출처를 확인한다.
3. **학습과 전공 활동의 활용 역량 강화**: 산출물을 이해하고 목적에 맞게 가공한다.
4. **책임 있는 태도 함양**: 개인정보·저작권·데이터 편향과 타인에게 미치는 영향을 고려한다.

이 과목은 복잡한 가중치 계산이나 오차함수 유도보다 AI를 사용하는 데 필요한 기초 소양에 초점을 둔다. 수학적 구현을 깊이 다루는 인공지능·머신러닝·딥러닝 과목과 학습 목적을 구별한다.

### 전체 강의의 흐름

오리엔테이션에서 예고한 내용을 세 영역으로 묶으면 다음과 같다. 개별 주차가 명시되지 않은 주제에 임의로 강의 번호를 붙이지 않는다.

| 영역 | 다룰 내용 |
| --- | --- |
| 이해·평가 | AI 리터러시, AI 역사, 인간지능과 기계지능, 데이터 리터러시, 머신러닝·딥러닝, 생성형 AI·LLM |
| 활용 | 프롬프트, 인간과 AI의 협업, AI 서비스의 전체 구조, 인문사회·과학·문화콘텐츠 분야의 활용 |
| 윤리 | AI 윤리, 개인정보·저작권, 가짜뉴스·딥페이크, 학습 내용 종합 |

## AI 리터러시의 정의와 네 가지 축

**리터러시(literacy)**는 기본적으로 글을 읽고 쓰는 문해력을 뜻한다. 강의는 이를 AI의 결과와 작동 맥락을 읽고 판단하는 능력으로 확장한다.

| 축 | 핵심 질문 | 학습자의 행동 |
| --- | --- | --- |
| 이해 | 어떤 원리로 작동하며 어떤 한계가 있는가? | 모델·데이터·서비스의 역할 파악 |
| 활용 | 이 작업에서 어떻게 도움을 받을 수 있는가? | 목적 설정, 질문, 초안·대안 활용 |
| 평가 | 결과를 믿고 사용할 근거가 있는가? | 사실·논리·출처·맥락 확인 |
| 윤리 | 입력과 사용이 누구에게 어떤 영향을 미치는가? | 개인정보·권리·편향·피해 검토 |

네 축은 순서대로 한 번씩 끝내는 단계가 아니다. 활용 중에도 이해·평가·윤리를 함께 고려한다.

### 보충: 분류 틀은 하나만 있는 것이 아니다

UNESCO의 2024년 학생 AI 역량 프레임워크는 인간 중심 사고, AI 윤리, AI 기술과 응용, AI 시스템 설계라는 네 차원을 제시한다. 강의의 네 축과 명칭이 같은 분류는 아니지만, 기술 사용뿐 아니라 판단과 책임을 함께 다룬다는 점이 연결된다. [UNESCO: AI competency framework for students](https://www.unesco.org/en/articles/ai-competency-framework-students)

## AI는 데이터·모델·서비스가 결합된 시스템

AI를 무엇이든 해결하는 상자로 보기보다, 여러 구성 요소와 사람의 선택이 결합된 시스템으로 이해한다.

| 요소 | 역할 |
| --- | --- |
| 데이터 | 학습·평가·입력에 활용되는 자료와 기록 |
| 모델 | 입력을 처리해 예측·분류·생성 등의 결과를 만드는 계산 구조 |
| 서비스 | 모델을 사용자 기능으로 제공하는 인터페이스와 운영 체계 |
| 인프라 | 학습과 실행을 위한 연산·저장·통신 기반 |
| 개발자·운영 기관 | 데이터 선택, 설계, 제공 방식과 기준 결정 |
| 사용자·사회적 환경 | 사용 목적, 행동, 규범과 제도를 통해 결과와 영향에 관여 |

**모델과 서비스는 같은 말이 아니다.** 하나의 서비스가 여러 모델이나 검색·계산 도구를 결합할 수도 있다.

### 강의 설명의 적용 범위

강의의 “데이터를 학습하고 확률적으로 출력한다”는 설명은 주로 학습 기반 AI, 특히 생성형 언어모델을 이해하기 위한 설명이다. 규칙을 명시적으로 사용하는 AI까지 모두 같은 방식으로 작동한다고 일반화하지 않는다.

또한 “AI가 대신 학습해 주지 않는다”는 말은 **사용자가 산출물을 받았다고 그 내용을 이해하게 되는 것은 아니다**라는 학습상의 의미다. AI 모델의 기술적인 학습 과정 자체를 부정하는 표현이 아니다.

## 유창함과 정확성은 다르다

| 개념 | 의미 | 확인할 질문 |
| --- | --- | --- |
| 유창함 | 문장이 자연스럽고 매끄러움 | 읽기 쉽고 표현이 잘 이어지는가? |
| 정확성 | 내용이 사실과 근거에 부합함 | 원자료로 확인할 수 있는가? |

생성형 AI는 그럴듯하지만 틀린 설명, 존재하지 않는 출처, 근거 없는 수치를 만들 수 있다. 흔히 **환각(hallucination)**이라고 부르는 문제다. NIST의 생성형 AI 위험관리 문서도 자신 있게 제시되는 잘못된 내용을 주요 위험으로 다룬다. [NIST: Generative AI Profile, §2.2 Confabulation](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.600-1.pdf)

### 강의의 ‘세종대왕과 노트북’ 예시

강의는 ‘세종대왕의 맥북 프로 던짐 사건’처럼 **질문 자체에 거짓 전제가 들어간 사례**를 소개한다. 실제 역사적 사건으로 읽지 않는다.

여기서 배울 점은 잘못된 전제를 가진 질문에 그럴듯한 이야기가 붙을 수 있다는 것이다. 해당 출력이 발생한 정확한 모델·시점·설정이나 “사용자 만족도를 높이기 위한 설계 때문에 발생했다”는 원인은 스크립트만으로 확인할 수 없으므로 단정하지 않는다.

## AI 산출물을 확인하는 네 가지 기준

| 기준 | 확인할 내용 |
| --- | --- |
| 사실 | 이름·날짜·수치·정의가 실제 자료와 일치하는가? |
| 논리 | 주장과 근거가 연결되는가? 앞뒤가 모순되거나 과도하게 일반화하지 않는가? |
| 출처 | 자료가 실제로 존재하며 해당 주장을 뒷받침하는가? |
| 영향 | 특정 사람·집단의 관점을 누락하거나 피해·권리 침해를 일으킬 가능성이 있는가? |

출처처럼 보이는 링크가 있다고 검증이 끝난 것은 아니다. 직접 열어 내용·작성 시점·적용 범위를 확인한다.

### 비판적으로 읽는 세 단계

1. **주장 파악**: 무엇을 말하고 있는지 자신의 말로 요약한다.
2. **근거 확인**: 주장을 뒷받침하는 자료가 존재하고 적절한지 살핀다.
3. **빠진 관점 점검**: 어떤 사람·상황·반론·조건이 누락되었는지 찾는다.

‘비판적’이라는 말은 무조건 부정한다는 뜻이 아니다. 근거에 따라 받아들일 부분과 수정할 부분을 구별하는 태도다.

### 보충 예제: 강한 주장을 검토하기

다음 문장은 실제 통계가 아니라 검토 연습을 위한 가상 문장이다.

> 생성형 AI를 쓰면 모든 학생의 성적이 오른다.

| 단계 | 검토 질문 |
| --- | --- |
| 주장 파악 | ‘모든 학생’에게 성적 향상이 생긴다는 주장인가? |
| 근거 확인 | 어떤 학생·과목·기간을 조사했으며 비교 대상이 있는가? |
| 빠진 관점 | 사용 방식과 기존 학습 수준에 따른 차이는 없는가? |

**같은 AI에 여러 번 확인하는 것만으로 독립적인 검증이 되지는 않는다.** 재질문은 검토할 쟁점을 찾는 데 활용하고, 사실 확인은 교재·원문·공식 자료 등과 대조한다.

## 인공지능의 일상화

| 일상적 기능 | AI가 활용될 수 있는 역할 | 살펴볼 점 |
| --- | --- | --- |
| 검색 | 정보 탐색·정렬·요약 | 순위와 요약이 원문의 의미를 잘 반영하는가? |
| 추천 | 관심사에 맞는 콘텐츠 제시 | 어떤 정보가 반복 노출되고 무엇이 빠지는가? |
| 번역 | 언어 간 표현 변환 | 문맥·전문용어·말투가 유지되는가? |
| 챗봇 | 질문 응답·초안·아이디어 제공 | 사실과 출처를 확인했는가? |

모든 검색·추천 기능이 같은 AI 기술을 사용한다는 뜻은 아니다. 익숙하거나 편리하다는 이유만으로 정확성과 중립성을 가정하지 않는 것이 중요하다.

## 학습 환경의 변화와 학습자의 역할

### 자료 탐색에서 검토·재구성으로

```text
전통적인 학습 흐름의 예
자료 탐색 → 원문 읽기 → 이해·정리 → 작성·발표

AI를 활용하는 학습 흐름의 예
목적·질문 설정 → AI 초안·대안 생성
→ 원문·근거 확인 → 수정·재구성 → 설명·제출
```

AI는 초안 작성과 탐색에 드는 시간을 줄일 수 있다. 대신 산출물을 검토하는 일이 중요해지며, **AI를 쓴다고 원문을 읽는 과정이 없어지는 것은 아니다.** 오류를 확인하고 고치는 시간도 전체 작업 시간에 포함된다.

### 혼자 공부할 때의 활용

방송대처럼 혼자 학습하는 시간이 많을 때는 자신의 이해를 점검하는 데 AI를 활용할 수 있다.

- 어려운 개념의 다른 설명이나 예시를 요청한다.
- 비교표·복습 질문·반론을 만드는 데 활용한다.
- 답을 보기 전에 스스로 설명하거나 문제를 풀어 본다.
- AI의 설명·채점도 교재와 대조하고, 틀린 부분을 자신의 말로 고친다.

판단의 기준은 결과물을 얼마나 빨리 얻었는지뿐 아니라, **그 내용을 스스로 설명할 수 있는지**다.

### 전공별로 강조할 검토 요소

| 분야 | 특히 살펴볼 요소 |
| --- | --- |
| 인문사회 | 해석의 근거, 역사·사회적 맥락, 누락된 관점 |
| 자연과학 | 조건·단위·실험 근거, 검증 가능성과 재현성 |
| 예술 | 표현 의도, 창작 과정, 저자성·권리 문제 |
| 컴퓨터과학 | 설계의 타당성, 코드의 동작·한계, 시스템의 영향 |

비전공자도 사례·비유·흐름도를 통해 기본 원리와 한계를 이해할 수 있다. AI 개발자가 되는 것과 AI를 판단하며 사용하는 것은 다른 학습 목표다.

## 입력 자료와 책임 있는 활용

강의는 결과뿐 아니라 **입력하는 자료도 점검**해야 한다고 강조한다.

- 이름·연락처·학습 기록 등 개인을 식별할 수 있는 정보가 있는지 살핀다.
- 비공개 연구·업무 자료를 외부 서비스에 제공할 권한이 있는지 확인한다.
- 파일을 한꺼번에 올릴 때도 각 파일의 내용을 확인한다.
- 과제에서 허용하는 AI 사용 범위와 출처·사용 사실 표시 지침을 확인한다.

구체적인 허용 범위는 소속 기관의 규정과 서비스의 적용 조건에 따라 확인한다. 특정 서비스가 입력 자료를 언제나 공개하거나 언제나 학습에 사용한다고 일괄적으로 단정하지 않는다.

AI가 만들었다는 이유로 사용자의 검토가 면제되지는 않는다. 동시에 사회적 책임을 사용자 한 명에게만 돌리는 것도 적절하지 않다. 개발·제공·도입·활용에 관여하는 사람과 기관의 역할을 함께 살펴야 한다.

## AI를 바라보는 세 가지 관점

| 관점 | 무엇에 주목하는가? | 사람에게 필요한 역할 |
| --- | --- | --- |
| 도구 | 요약·번역·초안·반복 작업을 돕는 기능 | 목적·기준 설정, 결과의 적합성 판단 |
| 협업자 | 대화와 반복 수정을 통해 아이디어를 발전시키는 방식 | 대안 선택, 검토, 수정과 최종 결정 |
| 사회기술적 시스템 | 기술·데이터·기업·사용자·제도가 연결된 구조 | 설계 기준과 사회적 영향 파악 |

### 도구로서의 AI

도구의 성능뿐 아니라 사용할 목적과 한계를 알아야 한다. 계산 결과나 초안을 제공받는 것과 그것을 어떤 상황에 사용할지 판단하는 것은 구별한다.

AI가 세부 작업을 계획하도록 할 수 있더라도, 사용 목적과 허용 범위, 평가 기준을 정하고 감독하는 사람의 역할은 중요하다.

### 협업자로서의 AI와 의인화

대화하면서 대안을 만들고 수정하는 작업 방식을 인간과 AI의 협업으로 표현할 수 있다. 이는 AI가 인간과 같은 책임 주체라는 뜻은 아니다.

사과·공감·자신감 있는 표현은 사람처럼 느껴지게 할 수 있다. 하지만 **그 표현만으로 실제 감정·의도·이해의 존재나 답변의 정확성을 판단할 수는 없다.** 표현의 친숙함과 결과의 신뢰성을 구별한다.

### 사회기술적 시스템으로서의 AI

출력 뒤에는 데이터 선정, 모델 설계, 서비스 목표, 운영 정책과 사용자의 행동이 있다. 따라서 결과만 보는 데서 그치지 않고 누가 어떤 기준으로 시스템을 만들고 운영하는지도 살핀다.

## 추천 알고리즘의 편리함과 정보 편중

강의는 추천을 통해 사용자 행동과 이후의 노출이 서로 영향을 줄 수 있음을 설명한다.

```text
사용자의 시청·클릭·선호 기록
→ 관심사에 맞춘 추천
→ 추천된 콘텐츠 소비
→ 새로운 행동 기록
→ 이후 추천에 반영
```

| 기대할 수 있는 편익 | 함께 점검할 가능성 |
| --- | --- |
| 찾는 시간을 줄임 | 특정 주제·관점만 반복해서 접함 |
| 관심 있는 콘텐츠 발견 | 새로운 분야를 만날 기회가 줄어듦 |
| 선택을 도움 | 무엇을 보여 주는지 결정하는 기준을 알기 어려움 |

이는 가능한 피드백 구조의 설명이다. 모든 추천 시스템이 같은 방식으로 작동하거나 반드시 정보 편중을 일으킨다는 뜻은 아니다. 모델이 매 클릭마다 즉시 재학습된다고 가정하지도 않는다.

강의의 ‘데이터 편향’은 이 대목에서 정보 소비의 편중과 행동 기록의 피드백을 함께 가리킨다. 학습 데이터의 대표성 문제와 사용자에게 노출되는 정보의 다양성 문제는 구별해 본다.
