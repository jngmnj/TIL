# 4강. 데이터 리터러시

- 학습일: 2026-09-22
- 과목: AI 리터러시
- 주제: 데이터의 종류와 라벨, 학습·검증·테스트, 과적합, 품질·대표성·편향, 개인정보

## 핵심 요약

**AI 결과를 평가하려면 모델뿐 아니라 무엇을, 누구에게서, 어떤 기준으로 수집하고 학습했는지 살펴야 한다.** 데이터는 현실 전체가 아니라 선택된 기록이며, 누락과 해석의 문제가 있다.

| 질문 | 핵심 개념 |
| --- | --- |
| 어떤 형태의 자료인가? | 정형·비정형 데이터 |
| 무엇을 정답으로 정했는가? | 라벨·라벨링 |
| 학습과 평가는 어떻게 구분했는가? | 학습·검증·테스트 데이터 |
| 새로운 사례에서도 잘 작동하는가? | 일반화·과적합 |
| 누구와 어떤 상황을 반영하는가? | 품질·대표성·편향·누락 |
| 사용할 권한과 보호 조치는 적절한가? | 개인정보·가명처리·목적과 범위 |

이번 강의는 머신러닝·딥러닝을 배우기 전, 데이터의 역할과 해석 기준을 익히는 입문 내용이다.

## 데이터는 학습 기반 AI의 재료

학습 기반 AI는 기록과 사례에서 패턴을 학습하고, 이를 새 입력에 적용한다.

```text
자료 수집 → 정리·필요한 라벨 부여
→ 모델 학습 → 검증·평가 → 새로운 사례에 적용
```

모델이 정교해도 데이터가 부정확하거나 목적과 맞지 않으면 좋은 결과를 기대하기 어렵다. 반대로 데이터가 좋아도 모델과 학습·평가 방식이 부적절하면 충분히 활용하지 못한다.

### 데이터의 범위

| 형태 | 예 |
| --- | --- |
| 숫자·문자 | 성적, 설문 응답, 문서 |
| 이미지·음성·영상 | 사진, 녹음, 강의 영상 |
| 행동 기록 | 클릭, 검색, 구매, 서비스 접속 |
| 위치·활동 기록 | 이동 경로, 운동 코스, 시각별 활동 |

데이터를 숫자표로만 한정하지 않는다. 컴퓨터로 기록·처리할 수 있는 여러 자료가 학습에 활용될 수 있다.

다만 **수집할 수 있다는 것과 학습에 사용해도 된다는 것은 다르다.** 실제 활용 여부는 수집 목적·권한·서비스 조건 등을 확인해야 한다. 모든 서비스가 같은 정보를 수집하거나 모든 기록을 AI 학습에 사용하는 것은 아니다.

## 정형 데이터와 비정형 데이터

| 구분 | 특징 | 예 | 점검할 요소 |
| --- | --- | --- | --- |
| 정형 데이터 | 미리 정한 항목과 구조로 정리 | 성적표, 수치형 설문 결과 | 항목 정의, 단위, 잘못된 값, 결측 |
| 비정형 데이터 | 내용이 고정된 표의 항목만으로 표현되기 어려움 | 자유 서술문, 사진, 음성, 영상 | 문맥, 해석, 형식 차이, 전처리 |

정형 데이터는 비교·정렬·집계에 편리하다. 비정형 데이터는 내용에서 필요한 특징을 추출하거나 처리 가능한 표현으로 바꾸는 과정이 중요하다.

### ‘비정형’은 파일 규칙이 없다는 뜻이 아니다

사진과 음성에도 파일 형식과 저장 규칙이 있다. 여기서 정형·비정형의 구분은 **내용이 고정된 항목과 관계로 얼마나 조직되어 있는가**에 관한 것이다.

강의는 대표적인 두 유형에 집중한다. 또한 설문도 객관식 응답은 정형으로, 자유 서술 응답은 비정형으로 다룰 수 있다. 자료의 이름보다 실제 구조를 본다.

## 데이터는 현실 자체가 아니라 기록된 일부

현실에는 사건뿐 아니라 그 배경과 관계, 사람의 의도와 사정이 함께 존재한다. 데이터에는 그중 수집 대상으로 정한 정보가 남는다.

```text
현실의 사람·활동·상황
→ 수집 대상·항목·기간·방식 선택
→ 기록된 데이터
→ 모델이 학습하는 자료
```

수집 기준은 무엇이 보이고 무엇이 빠질지를 결정한다. 데이터가 객관적인 숫자 형태라고 해서 현실을 빠짐없이 담고 있는 것은 아니다.

### 강의 사례: 학습 기록

| 시스템에 남기 쉬운 기록 | 해당 시스템에서 빠지기 쉬운 활동 |
| --- | --- |
| 접속 시각·횟수 | 교재 읽기 |
| 영상 시청 시간·진도 | 종이 노트 정리 |
| 온라인 과제 제출 | 다른 앱에서의 정리·복습 |
| 시스템 안의 문제 풀이 | 오프라인 스터디·연습문제 풀이 |

접속과 시청 기록은 학습 참여의 **단서**가 될 수 있지만, 이해도·노력·학습 의지 전체를 뜻하지 않는다. 3강의 학습 위험 예측 사례와 연결된다.

이 예시는 기록의 한계를 설명하는 것이다. 방송대의 실제 성적 산정 규정이나 특정 AI 시스템의 운영 사실을 설명하는 것은 아니다.

## 라벨: 학습 사례에 붙이는 목표 정보

**라벨(label)**은 지도학습에서 입력과 함께 제공하는 목표값이다. 강의는 이를 이름표나 정답표로 설명한다.

| 입력 사례 | 라벨의 예 |
| --- | --- |
| 동물 사진 | 고양이 / 개 |
| 이메일 | 스팸 / 정상 |
| 댓글 | 긍정 / 부정 |

모델은 입력과 목표값의 관계를 학습한다. 라벨이 잘못되거나 기준이 일관되지 않으면 학습과 평가에도 영향을 준다.

### 라벨과 지도학습의 범위

- 분류에서는 고양이·개처럼 범주를 라벨로 사용할 수 있다.
- 수치를 예측하는 과제에서는 목표값이 숫자일 수 있다.
- **모든 AI 데이터에 사람이 붙인 정답 라벨이 필요한 것은 아니다.** 강의의 이름표 설명은 지도학습의 대표적인 예다.
- 라벨을 부여하는 작업을 **라벨링(labeling)**이라고 한다.

### 사람이 붙인 라벨도 해석이 필요하다

강의의 댓글 예는 “정말 대단하네요”다.

| 해석자 | 읽은 의미 | 가능한 라벨 |
| --- | --- | --- |
| A | 칭찬 | 긍정 |
| B | 비꼼 | 부정 |
| C | 앞뒤 상황이 없어 판단하기 어려움 | 판단 보류 |

감정·혐오 표현·예술 스타일처럼 경계가 모호한 과제에서는 라벨이 달라질 수 있다. 이때 작업자를 무조건 오답 처리하기보다 기준이 명확한지, 필요한 문맥이 있는지 살핀다.

정리 과정에서는 라벨 기준을 문서화하고, 판단이 어려운 사례를 구분하며, 불일치를 검토할 수 있다. ‘정답표’라는 이름만으로 라벨을 절대적인 사실로 받아들이지 않는다.

## 학습·검증·테스트 데이터를 나누는 이유

같은 자료로 공부하고 같은 문제로만 평가하면 새로운 문제를 풀 수 있는지 알기 어렵다. 모델도 학습한 사례와 별도로 남겨 둔 사례에서 성능을 확인해야 한다.

| 구분 | 주요 용도 | 강의의 비유 |
| --- | --- | --- |
| 학습 데이터(training set) | 패턴을 익히고 모델의 매개변수를 학습 | 문제집 |
| 검증 데이터(validation set) | 개발 중 성능을 확인하고 모델·학습 설정 선택 | 모의고사 |
| 테스트 데이터(test set) | 최종적으로 선택한 모델의 성능 평가 | 실제 시험 |

강의에서 말하는 세 가지는 파일 형식의 분류가 아니라 **사용 목적에 따른 구분**이다. 같은 수집 자료를 나눌 수 있으며, 필요에 따라 다른 시기·기관에서 평가 자료를 별도로 수집할 수도 있다. [Google: 데이터셋 분리](https://developers.google.com/machine-learning/crash-course/overfitting/dividing-datasets)

### 학습과 평가의 흐름

```text
학습 데이터 → 모델 학습
                  ↓
검증 데이터 → 개발 중 평가 → 설정·모델 선택을 반복
                                  ↓
                           최종 모델 결정
                                  ↓
테스트 데이터 ─────────────→ 최종 성능 평가
```

### 보완: 매개변수와 학습 설정의 구분

강의의 ‘검증으로 파라미터를 조정한다’는 표현은 다음처럼 구별하면 정확하다.

- **매개변수(parameter)**: 신경망의 가중치처럼 학습 데이터로 학습하는 값이다.
- **하이퍼파라미터(hyperparameter)**: 학습률·모델 크기 등 학습 방식과 모델 구성을 정하는 설정이다.
- 일반적인 개발 절차에서 검증 결과는 설정 비교, 모델 선택, 학습 중단 시점 결정 등에 쓰인다.

검증 결과가 모델 선택에 영향을 주므로, 검증 데이터도 반복 사용에 따라 과도하게 맞춰질 수 있다. 테스트 결과를 보며 계속 수정하면 테스트 데이터까지 사실상 개발 과정에 사용하게 된다. [scikit-learn: 교차검증과 모델 평가](https://scikit-learn.org/stable/modules/cross_validation.html)

### 보충: 파일만 나누면 충분한가?

**데이터 누수(data leakage)**는 평가 때만 알아야 할 정보나 실제 예측 시점에는 없는 정보가 학습·개발 과정에 들어가는 문제다. 실제보다 성능이 좋아 보일 수 있다.

- 같은 자료나 사실상 같은 사례가 학습과 평가 양쪽에 들어가지 않았는지 확인한다.
- 평균·표준편차 등 전처리에 필요한 값을 전체 데이터에서 먼저 계산하면 평가 자료의 정보가 섞일 수 있다.
- 학습 데이터에서 정한 변환을 검증·테스트 데이터에도 적용하는 것이 기본 원칙이다.

이는 공식 문서에서도 강조하는 평가상의 주의점이다. [scikit-learn: 데이터 누수와 전처리](https://scikit-learn.org/1.7/common_pitfalls.html#data-leakage)

같은 사람의 반복 기록으로 새 사람에 대한 성능을 평가하려면 사람 단위 분리를 고려한다. 미래 예측을 평가하려면 시간 순서를 고려해야 한다. 무작위로 섞는 방식이 모든 문제에 적합하지는 않다. [scikit-learn: 그룹·시계열 데이터 분할](https://scikit-learn.org/stable/modules/cross_validation.html)

## 일반화와 과적합

**일반화(generalization)**는 학습에서 보지 않은 사례에도 학습한 관계를 적절하게 적용하는 것이다.

**과적합(overfitting)**은 모델이 학습 데이터의 특수한 패턴이나 잡음에 지나치게 맞춰져 새로운 사례에서 성능이 떨어지는 문제다. [Google: Overfitting](https://developers.google.com/machine-learning/crash-course/overfitting/overfitting)

| 관찰 | 해석 |
| --- | --- |
| 학습 성능도 좋고 적절히 분리한 평가 성능도 좋음 | 평가한 조건에서 일반화가 잘될 가능성 |
| 학습 성능은 좋지만 평가 성능은 나쁨 | 과적합 등을 점검할 필요 |
| 학습 성능과 평가 성능이 모두 나쁨 | 데이터·모델·학습 방법 등 다른 원인도 점검 |

### 원문의 혼용 바로잡기

스크립트에는 과적합을 설명하며 “테스트 데이터로는 잘 작동한다”는 표현이 섞여 있다. 기본 대비는 **학습 데이터에는 잘 맞지만 보지 않은 데이터에는 잘 맞지 않는 상태**다.

테스트 성능이 좋았는데 실제 서비스에서 나빠졌다면 과적합만 단정하지 않는다. 테스트 자료가 실제 환경을 반영하는지, 평가 정보가 누수되었는지, 이후 환경이 달라졌는지도 확인해야 한다.

## 잘못된 단서를 학습하는 문제

강의는 고양이와 개 사진을 다음처럼 모았다고 가정한다.

| 학습 데이터 | 의도한 단서 | 모델이 대신 이용할 수 있는 단서 |
| --- | --- | --- |
| 실내에 있는 고양이 사진 | 동물의 얼굴·귀·형태 | 실내 배경 |
| 야외에 있는 개 사진 | 동물의 얼굴·귀·형태 | 야외 배경 |

동물을 구별하기를 기대했지만, 모델은 배경만으로도 학습 자료에서 정답을 맞힐 수 있다. 그러면 야외의 고양이를 개로 판단하는 오류가 생길 수 있다.

### 라벨이 정확해도 안심할 수 없는 이유

고양이·개 라벨은 맞더라도, 수집된 자료에서 배경과 라벨이 함께 움직이면 기대하지 않은 단서가 학습될 수 있다.

검증·테스트에도 같은 배경 패턴만 있다면 평가 점수만으로 이 문제를 발견하기 어렵다. 배경과 촬영 조건이 달라진 사례를 통해 실제로 필요한 구분을 하는지 점검해야 한다.

이 예는 가능한 실패를 설명하는 가정이다. 실제 모델이 배경을 사용했는지는 별도 분석 없이 단정하지 않는다.

## 데이터 품질: 많고 깨끗한 것만으로 충분하지 않다

| 기준 | 확인할 질문 |
| --- | --- |
| 정확성 | 값·단위·라벨이 실제 내용에 맞는가? |
| 일관성 | 같은 항목을 같은 정의와 기준으로 기록했는가? |
| 적시성 | 사용하려는 시기와 상황에 적절한가? |
| 중복·오류 관리 | 중복 집계나 잘못 입력된 값이 있는가? |
| 완전성 | 필요한 항목·사례가 빠져 있지 않은가? |
| 목적 적합성 | 해결하려는 문제에 필요한 정보를 담고 있는가? |

최신 데이터가 언제나 가장 좋은 것은 아니다. 과거의 변화를 분석하는 목적이라면 과거 기록이 필요하다. 반복 기록도 실제로 반복된 사건인지, 잘못 복제된 자료인지 구별한다.

## 대표성: 실제 적용 대상을 반영하는가?

**대표성(representativeness)**은 자료가 관심 있는 대상 집단과 적용 상황을 얼마나 적절히 반영하는지에 관한 개념이다.

강의의 A·B·C 집단 예에서 A는 충분히 수집되고 B는 적게, C는 전혀 수집되지 않았다면 전체 대상에 대한 성능을 자신하기 어렵다.

### ‘골고루’는 항상 같은 수라는 뜻이 아니다

대표성은 모든 집단의 자료 수를 기계적으로 같게 만드는 것과 다르다. 실제 사용자의 구성, 드문 상황의 중요성, 집단별 성능을 평가할 자료가 충분한지 함께 본다.

어떤 집단이 누락되었다고 반드시 모든 예측이 실패하는 것은 아니지만, 그 집단에서도 잘 작동한다고 가정할 근거는 약해진다.

### 강의 사례: 음성인식

| 수집한 환경 | 실제 사용에서 추가로 만날 수 있는 조건 |
| --- | --- |
| 표준어 중심 | 방언·다양한 발음 |
| 조용한 녹음실 | 거리·교통수단·생활 소음 |
| 제한된 화자 구성 | 다양한 연령·말하기 속도·음량 |

깨끗한 녹음도 유용하지만 실제 사용 환경을 충분히 반영하는지는 다른 문제다. 학습 환경과 사용 환경의 차이는 오류를 키울 수 있다.

강의의 “방언은 당연히 인식되지 않는다”는 표현은 절대적인 결과로 외우지 않는다. 실제 성능은 모델과 데이터·환경에 따라 평가해야 한다.

## 데이터 편향과 누락

**데이터 편향**은 수집·측정·라벨링 등의 방식 때문에 특정 집단이나 상황이 체계적으로 치우쳐 표현되는 문제와 관련된다.

| 발생 경로 | 예 |
| --- | --- |
| 수집 대상의 편중 | 특정 플랫폼 사용자만 조사 |
| 수집 환경의 편중 | 같은 장소·장비·조건의 자료만 확보 |
| 측정의 한계 | 접속 시간을 학습 의지의 대리 지표로 사용 |
| 라벨 기준의 편향 | 특정 관점만 정답으로 분류 |
| 과거 관행의 반영 | 과거의 불균등한 기회를 중립적인 결과로 취급 |

의도적인 조작이 없어도 편향은 생길 수 있다. NIST는 AI 편향을 통계·계산뿐 아니라 인간의 인지와 사회·제도적 요인까지 포함해 설명한다. [NIST: SP 1270, AI 편향의 식별과 관리](https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.1270.pdf)

### 데이터가 많으면 편향이 사라지는가?

그렇지 않다. 같은 수집 방식으로 같은 집단의 기록만 더 모으면 누락과 치우침이 유지될 수 있다.

```text
같은 출처·비슷한 이용자·같은 환경에서만 추가 수집
→ 전체 자료 수는 증가
→ 빠진 집단과 상황은 여전히 빠질 수 있음
```

양의 증가는 충분히 대표되는 자료를 확보하는 데 도움이 될 수 있지만, 수집 구조의 문제를 자동으로 해결하지는 않는다. 다양성과 대표성, 측정·라벨 기준을 함께 점검한다.

### 기록에 없는 활동도 현실에는 존재한다

플랫폼의 클릭 기록은 그 플랫폼 사용자의 행동을 보여 준다. 플랫폼 비사용자, 오프라인 활동, 기록하지 않은 사정까지 자동으로 대변하지는 않는다.

| 구분 | 의미 |
| --- | --- |
| 기록 안의 결측 | 수집 대상에 들어왔지만 일부 항목의 값이 비어 있음 |
| 수집 범위의 누락 | 사람·활동·상황 자체가 자료에 포함되지 않음 |

둘 다 빠진 정보의 문제지만 처리 방법은 다를 수 있다. 빈칸을 채웠다는 이유만으로 자료에 등장하지 않은 집단까지 대표하게 되는 것은 아니다.

## 개인정보와 데이터 활용

개인정보는 이름·전화번호만을 뜻하지 않는다. 위치·검색·구매·얼굴·음성·건강·학습 기록도 개인을 알아볼 수 있는 정보가 될 수 있다.

개인정보 보호법 제2조는 다른 정보와 쉽게 결합해 개인을 알아볼 수 있는 경우도 개인정보의 범위에 포함한다. [국가법령정보센터: 개인정보 보호법 제2조](https://law.go.kr/LSW/lsLawLinkInfo.do?chrClsCd=010202&lsJoLnkSeq=900040612)

강의의 기본 원칙은 다음과 같다.

- 수집·이용 목적과 범위를 분명하게 정한다.
- 목적에 필요한 자료인지 검토한다.
- 사용할 권한과 적용 기준을 확인한다.
- 접근·보관·공유 과정에서 정보를 보호한다.

‘데이터가 많을수록 좋다’는 이유만으로 수집 범위를 무제한 넓히지 않는다.

### 가명처리의 의미와 한계

가명처리는 개인정보의 일부를 삭제하거나 대체하는 등의 방법으로, 추가 정보 없이는 특정 개인을 알아볼 수 없도록 처리하는 것이다. 가명정보도 개인정보 보호법상 개인정보에 포함된다. [국가법령정보센터: 가명정보·가명처리 정의](https://law.go.kr/LSW/lsLawLinkInfo.do?chrClsCd=010202&lsJoLnkSeq=900040612)

이름을 지웠더라도 시간·장소·활동 기록을 다른 자료와 결합하면 개인이 드러날 위험이 남을 수 있다. 따라서 이름 삭제나 가명처리를 **재식별 가능성이 완전히 사라진 상태**와 동일시하지 않는다.

강의의 수업 시간표 예는 단서의 결합으로 후보 범위가 줄어들 수 있다는 설명이다. 시간표 하나만으로 언제나 특정 개인을 식별할 수 있다는 뜻은 아니다.

## 데이터 중심 AI의 관점

**데이터 중심 AI(data-centric AI)**는 모델 변경뿐 아니라 데이터의 품질을 체계적으로 개선하는 데 주목하는 관점이다.

| 개선할 부분 | 가능한 작업 |
| --- | --- |
| 값과 기록 | 입력 오류·중복·단위 불일치 확인 |
| 라벨 | 기준 정리, 잘못된 라벨과 불일치 검토 |
| 시기와 목적 | 오래되었거나 목적에 맞지 않는 자료 점검 |
| 대표성 | 부족한 집단·환경·상황의 사례 보완 |
| 평가 | 분할 방식과 누수, 집단·상황별 성능 확인 |

강의의 논점은 좋은 데이터와 적절한 모델이 함께 필요하다는 것이다. 데이터만 고치면 모든 문제가 해결된다거나 모델 선택이 중요하지 않다는 뜻은 아니다.

## 데이터 리터러시의 네 가지 점검 축

| 축 | 질문 |
| --- | --- |
| 출처 | 누가, 언제, 어디서, 어떤 목적으로 수집했는가? |
| 품질 | 값과 라벨을 믿을 수 있으며 현재 용도에 적합한가? |
| 대표성 | 누구와 어떤 상황이 포함되거나 누락되었는가? |
| 권리 보호 | 수집·이용·공유의 권한과 보호 조치가 적절한가? |

데이터가 의미를 스스로 설명해 주지는 않는다. 접속 기록을 학습 지원에 쓸지 감시·불이익 판단에 쓸지에 따라 필요한 검토도 달라진다.

상용 AI의 학습 자료 전체를 확인하기 어려울 때도, 공개된 설명과 평가 범위·제약을 확인하고 결과가 자신의 목적에 맞는지 검토할 수 있다. 모르는 학습 출처를 추측해 사실처럼 설명하지 않는다.

## 복습 질문

1. 정형·비정형 데이터의 차이를 파일 형식의 유무와 혼동하면 안 되는 이유는 무엇인가?
2. 접속 시간과 시청 기록만으로 학습 의지를 판단하기 어려운 이유는 무엇인가?
3. 라벨은 어떤 역할을 하며, 사람이 붙인 라벨도 왜 검토해야 하는가?
4. 학습·검증·테스트 데이터의 역할은 각각 무엇인가?
5. 검증 결과에 따른 모델 선택과 학습 데이터에 의한 매개변수 학습은 어떻게 다른가?
6. 데이터 누수는 왜 실제보다 성능이 좋아 보이게 만들 수 있는가?
7. 과적합과 실제 사용 환경의 변화로 인한 성능 저하를 왜 구별해야 하는가?
8. 고양이·개 라벨이 정확한데도 배경을 기준으로 잘못 학습할 수 있는 이유는 무엇인가?
9. 데이터의 양·다양성·대표성은 어떻게 다른가?
10. 가명처리했다고 개인정보와 재식별 위험을 더 이상 고려하지 않아도 되는가?
