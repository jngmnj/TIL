# 9강. 생성형 AI 기반 리서치 활용

- 학습일: 2026-08-30
- 과목: AI네이티브가되기위한기초소양
- 주제: LLM의 환각, 임베딩, RAG, NotebookLM, Perplexity, GenSpark

## 핵심 요약

LLM은 다음 단어를 확률적으로 예측해 문장을 생성하기 때문에 사실이 아닌 내용을 그럴듯하게 말하는 환각 문제가 발생할 수 있다. 이를 줄이기 위해 질문과 관련된 자료를 먼저 검색하고, 그 자료를 근거로 답변을 생성하는 RAG 기술이 활용된다.

RAG는 문서를 작은 단위로 나누고, 각 문장을 임베딩해 벡터 데이터베이스에 저장한 뒤, 질문과 의미가 가까운 자료를 찾아 LLM에 제공하는 방식이다. NotebookLM은 사용자가 업로드한 문서 안에서 검색하는 서비스이고, Perplexity와 GenSpark는 웹 전체를 검색해 최신 정보를 바탕으로 답변하는 서비스다.

## LLM의 환각 문제

환각은 AI가 사실이 아닌 정보를 사실처럼 생성하는 현상이다.

LLM은 학습 데이터에서 발견된 패턴을 바탕으로 다음에 올 단어를 예측한다. 따라서 문장이 자연스럽고 그럴듯해 보여도, 실제 사실 여부가 검증된 것은 아닐 수 있다.

예를 들어 다음 질문을 생각해보자.

```text
1910년에 한국방송통신대학교의 등록금은 얼마였나요?
```

한국방송통신대학교는 1972년에 설립되었으므로 1910년에는 존재하지 않았다. 하지만 LLM은 이를 검증하지 못하고 그럴듯한 금액을 만들어낼 수 있다. 이것이 환각의 핵심이다.

## 환각을 줄이는 방향

환각을 줄이려면 LLM이 학습된 패턴만으로 답하지 않고, 참고할 수 있는 자료를 먼저 확보해야 한다.

| 방식 | 특징 | 위험 |
| --- | --- | --- |
| 일반 LLM 답변 | 학습된 패턴만으로 생성 | 사실 검증이 어려워 환각 가능 |
| 검색 기반 LLM 답변 | 관련 자료를 검색한 뒤 근거로 사용 | 출처 확인 가능, 환각 감소 |

검색된 자료를 LLM 입력에 함께 넣으면, AI는 해당 자료를 바탕으로 답변을 생성할 수 있다.

## 키워드 검색의 한계

기존 키워드 검색은 입력한 단어와 문서 안의 단어가 정확히 일치해야 잘 동작한다.

예를 들어 사용자가 다음처럼 질문했다고 하자.

```text
휴가는 어떻게 신청하나요?
```

하지만 회사 문서 제목이 `연차 신청 절차 안내`라면, `휴가`와 `연차`는 의미가 비슷해도 단어가 다르기 때문에 키워드 검색은 문서를 찾지 못할 수 있다.

이 한계를 보완하기 위해 의미 기반 검색이 필요하다.

## 임베딩

임베딩은 텍스트를 숫자 배열, 즉 벡터로 바꾸는 기술이다.

```text
텍스트 -> 임베딩 모델 -> 벡터
```

컴퓨터는 단어의 의미를 직접 이해하지 못하지만, 숫자 사이의 거리는 계산할 수 있다. 따라서 텍스트를 벡터로 바꾸면 두 문장이나 단어의 의미가 얼마나 가까운지 수학적으로 비교할 수 있다.

예를 들어 `강아지`와 `개`는 의미가 가까우므로 벡터 공간에서 가까운 위치에 놓인다. 반면 `강아지`와 `주식`은 의미가 멀기 때문에 벡터 거리도 멀다.

## 의미 기반 검색

의미 기반 검색은 단어가 정확히 일치하지 않아도 의미가 가까운 문서를 찾는 방식이다.

질문과 문서를 모두 임베딩한 뒤 벡터 거리를 비교한다.

```text
질문: 휴가는 어떻게 신청하나요?
문서: 연차 신청 절차 안내

질문 벡터와 문서 벡터의 거리가 가까움 -> 관련 문서로 판단
```

이 방식은 동의어, 유사 표현, 자연어 질문을 처리하는 데 유리하다.

## RAG의 개념

RAG는 Retrieval Augmented Generation의 약자로, 한국어로는 검색 증강 생성이라고 한다.

| 구성 | 의미 |
| --- | --- |
| Retrieval | 질문과 의미가 유사한 자료를 검색 |
| Augmented | 검색 결과를 LLM 입력에 추가 |
| Generation | LLM이 검색 자료를 근거로 답변 생성 |

즉 RAG는 의미 기반 검색으로 관련 자료를 찾고, 그 자료를 바탕으로 LLM이 답변하게 하는 전체 흐름이다.

## RAG 파이프라인

RAG는 보통 다음 단계로 동작한다.

1. 문서를 검색하기 좋은 단위로 나눈다.
2. 나눈 문서 조각을 임베딩해 벡터로 변환한다.
3. 변환된 벡터를 벡터 데이터베이스에 저장한다.
4. 사용자의 질문도 임베딩해 저장된 문서 조각과 유사도를 비교한다.
5. 가장 관련 있는 문서 조각을 LLM에 전달해 답변을 생성한다.

앞의 1~3단계는 질문이 들어오기 전에 준비하는 과정이고, 4~5단계는 질문이 들어올 때마다 실행되는 과정이다.

## 청크

RAG에서 문서를 나눈 작은 단위를 청크라고 한다.

문서를 너무 크게 나누면 검색된 조각에 관련 없는 내용이 섞일 수 있고, 너무 작게 나누면 답변에 필요한 맥락이 부족해질 수 있다.

```text
청크가 너무 큼 -> 검색 정밀도 하락
청크가 너무 작음 -> 맥락 부족
적절한 청크 크기 -> 검색 정밀도와 맥락의 균형
```

따라서 문장, 문단, 장처럼 의미가 이어지는 단위로 나누는 것이 중요하다.

## 벡터 데이터베이스

벡터 데이터베이스는 임베딩된 문서 조각을 저장하고, 질문 벡터와 가장 가까운 벡터를 빠르게 찾아주는 저장소다.

일반 데이터베이스가 정확한 값이나 키를 기준으로 검색한다면, 벡터 데이터베이스는 의미적 유사도를 기준으로 검색한다.

| 검색 기준 | 예 |
| --- | --- |
| 키워드 검색 | 같은 단어가 들어 있는 문서 찾기 |
| 벡터 검색 | 의미가 가까운 문서 찾기 |

## RAG 답변 생성

RAG의 마지막 단계에서는 검색된 청크를 LLM에 컨텍스트로 제공한다. 이때 시스템 메시지로 “제공된 컨텍스트만 근거로 답하라”고 지시하면 근거 없는 답변을 줄일 수 있다.

예를 들어 회사 복무 규정에서 출장 여비 관련 청크가 검색되었다면, LLM은 그 청크에 적힌 교통비, 숙박비, 일비, 정산 기한 등을 근거로 답변한다.

답변의 장점은 다음과 같다.

| 장점 | 설명 |
| --- | --- |
| 근거 기반 답변 | 실제 문서 조각을 참고함 |
| 출처 확인 가능 | 답변이 어느 문서에서 왔는지 확인 가능 |
| 환각 감소 | 자료에 없는 내용은 모른다고 답하도록 설계 가능 |

## RAG 활용 사례

RAG는 다양한 분야에서 활용된다.

| 분야 | 활용 예 |
| --- | --- |
| 임직원 업무 지원 | 사내 규정, 인사 매뉴얼, 연차 신청 절차 검색 |
| 전문 업무 보조 | 법률 판례, 의학 논문, 기술 문서 기반 질의응답 |
| 금융 리서치 | 실적 보고서, 시장 분석 자료 검색과 요약 |
| 교육 | 강의 자료 기반 질의응답, 퀴즈 생성 |

공통점은 신뢰할 수 있는 자료를 먼저 찾고, 그 자료를 근거로 답한다는 점이다.

## RAG 서비스 유형

RAG 기반 서비스는 검색 범위에 따라 크게 두 가지로 나눌 수 있다.

| 유형 | 검색 범위 | 대표 서비스 |
| --- | --- | --- |
| 문서 기반 RAG | 사용자가 업로드한 문서 안에서 검색 | NotebookLM |
| 웹 검색 기반 RAG | 웹 전체에서 최신 정보 검색 | Perplexity, GenSpark |

문서 기반 RAG는 내가 제공한 자료에 한정해 답하므로 출처 검증이 쉽다. 웹 검색 기반 RAG는 최신 정보를 반영할 수 있다는 장점이 있다.

## NotebookLM

NotebookLM은 Google이 제공하는 문서 기반 AI 리서치 도구다. 사용자가 업로드한 자료를 소스로 삼아 질문에 답하고, 답변의 근거를 원문 출처로 표시한다.

지원하는 소스 유형은 다음과 같다.

| 소스 | 예 |
| --- | --- |
| 파일 | PDF, 문서 파일 |
| Google 문서 | Google Docs |
| 웹 자료 | 웹 URL |
| 영상 | YouTube |
| 오디오 | 음성 자료 |

NotebookLM의 핵심은 검색 범위를 사용자가 제공한 문서로 제한한다는 점이다. 따라서 AI가 임의로 정보를 만들어낼 가능성을 구조적으로 줄일 수 있다.

## NotebookLM의 주요 기능

NotebookLM은 크게 세 가지 기능을 제공한다.

| 기능 | 설명 |
| --- | --- |
| 소스 관리 | PDF, URL, YouTube, 오디오 등 자료 추가 |
| 질의응답 | 업로드한 자료에서만 답변하고 출처 번호 표시 |
| 콘텐츠 변환 | 퀴즈, 플래시카드, 마인드맵, 보고서, 오디오 오버뷰 생성 |

답변 옆의 인용 번호를 클릭하면 원본 문서의 해당 구절로 이동할 수 있다. 이를 통해 사용자는 답변이 실제 자료에 근거하는지 직접 확인할 수 있다.

## NotebookLM 실습 흐름

NotebookLM을 사용하는 기본 흐름은 다음과 같다.

1. 새 노트를 만든다.
2. 리서치할 PDF나 웹 자료를 소스로 추가한다.
3. 업로드가 끝나면 채팅창에서 질문한다.
4. 답변에 표시된 출처 번호를 클릭해 원문을 확인한다.
5. 필요하면 퀴즈, 요약, 오디오 오버뷰 같은 산출물로 변환한다.

예시 질문은 다음과 같다.

```text
RAG가 뭔지 쉽게 설명해줘.
RAG에서 임베딩은 어떤 역할을 해?
```

소스에 없는 내용을 질문하면 NotebookLM은 제공된 자료에 관련 정보가 없다고 답할 수 있다. 이 점이 일반 챗봇과의 중요한 차이다.

## Perplexity

Perplexity는 웹 검색 기반 AI 검색 서비스다. 사용자가 질문을 입력하면 웹에서 최신 정보를 검색하고, 관련성이 높고 신뢰할 만한 정보를 선별해 답변을 생성한다.

Perplexity의 특징은 다음과 같다.

| 특징 | 설명 |
| --- | --- |
| 실시간 웹 검색 | 최신 뉴스, 논문, 블로그, 공식 자료 반영 |
| 인라인 출처 | 문장별 출처 번호 제공 |
| 후속 질문 | 검색 맥락을 이어가며 리서치 가능 |
| 전문 영역 확장 | 금융, 시장 동향, 기술 리서치 등에 활용 |

시장 조사, 경쟁사 분석, 최신 기술 동향 파악처럼 여러 웹사이트를 비교해야 하는 업무에서 유용하다.

## Perplexity 실습 흐름

예시 질문은 다음과 같다.

```text
2025년에서 2026년 글로벌 생성형 AI 시장의 주요 트렌드와 산업별 도입 사례를 표 형태로 정리해줘.
```

답변에는 최신 웹 자료와 함께 출처 번호가 표시된다. 사용자는 출처 번호를 클릭해 실제 웹페이지를 확인하고, 필요한 경우 후속 질문으로 리서치를 확장할 수 있다.

```text
2026년 생성형 AI 시장 규모와 CAGR은?
```

이처럼 검색 결과를 기반으로 질문을 이어가며 조사 범위를 좁히거나 넓힐 수 있다.

## GenSpark

GenSpark는 검색 기능과 생산성 도구를 결합한 AI 플랫폼이다. 검색 결과를 단순 답변으로 제공하는 데서 더 나아가 보고서, 페이지, 슬라이드 같은 산출물 제작까지 연결한다.

주요 기능은 다음과 같다.

| 기능 | 설명 |
| --- | --- |
| AI Slides | 리서치 결과를 편집 가능한 PPT로 변환 |
| Spark Page | 출처와 차트가 포함된 구조화 페이지 생성 |
| Super Agent | 리서치, 이메일, 일정 관리 등 멀티스텝 작업 수행 |
| Fact Check Agent | 검색 결과나 텍스트의 사실 여부 검증 |

GenSpark는 리서치부터 산출물 제작까지 한 곳에서 처리하는 통합 플랫폼을 지향한다.

## GenSpark 실습 흐름

GenSpark에서는 웹 검색과 에이전트 기능을 함께 사용할 수 있다.

예를 들어 다음 질문을 입력할 수 있다.

```text
2026년 한국방송통신대학교의 등록금을 알려줘.
```

답변에는 출처가 표시되며, 사용자는 공식 페이지와 대조해 사실 여부를 확인할 수 있다. 이후 Fact Check Agent를 활용하면 제시된 내용이 공식 자료와 일치하는지도 검증할 수 있다.

## NotebookLM, Perplexity, GenSpark 비교

| 서비스 | 강점 | 적합한 상황 |
| --- | --- | --- |
| NotebookLM | 내가 올린 문서 안에서 출처 기반 답변 | 강의자료, 보고서, 내부 문서 분석 |
| Perplexity | 최신 웹 정보 검색과 인라인 출처 | 시장 조사, 최신 동향, 경쟁사 분석 |
| GenSpark | 검색 결과를 산출물로 변환 | 리서치 보고서, 발표 자료, 팩트체크 |

세 서비스 모두 검색 기반 답변을 제공하지만, 검색 범위와 산출물 형태가 다르므로 목적에 맞게 선택해야 한다.

## 리서치 도구 사용 시 주의점

RAG 기반 서비스도 완벽하지는 않다.

| 주의점 | 설명 |
| --- | --- |
| 출처 확인 | 답변에 표시된 출처가 실제 내용을 뒷받침하는지 확인 |
| 검색 범위 인식 | 업로드 문서 기반인지 웹 전체 검색인지 구분 |
| 최신성 확인 | 웹 검색 결과라도 게시일과 기준일 확인 |
| 권한과 보안 | 내부 문서 업로드 시 민감 정보 여부 검토 |
| 질문 구체화 | 필요한 결과 형식과 범위를 명확히 지정 |

특히 업무 리서치에서는 답변 자체보다 출처와 근거를 함께 확인하는 습관이 중요하다.

## 정리

LLM의 환각 문제는 모델이 사실을 검증하기보다 확률적으로 문장을 생성한다는 구조에서 비롯된다. RAG는 관련 자료를 먼저 검색하고 그 자료를 근거로 답변하게 하여 환각을 줄인다.

RAG의 핵심은 임베딩을 통한 의미 기반 검색이다. 텍스트를 벡터로 바꾸면 단어가 정확히 일치하지 않아도 의미가 가까운 문서를 찾을 수 있다. NotebookLM, Perplexity, GenSpark는 이러한 검색 기반 접근을 실제 리서치 업무에 적용한 대표적인 서비스다.
