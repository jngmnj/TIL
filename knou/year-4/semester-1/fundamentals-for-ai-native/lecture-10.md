# 10강. 생성형 AI의 API에 대한 이해

- 학습일: 2026-09-01
- 과목: AI네이티브가되기위한기초소양
- 주제: API, 구조화된 출력, 시스템 프롬프트, Temperature, API 키, Gemini API, OpenRouter

## 핵심 요약

API는 프로그램이 다른 프로그램의 기능이나 데이터를 정해진 방식으로 요청하고 사용할 수 있도록 만든 인터페이스다. 생성형 AI API를 활용하면 웹사이트에서 직접 질문하는 대신, 내가 만든 프로그램 안에서 텍스트·이미지·음성 생성 기능을 호출할 수 있다.

강의에서 다루는 주요 설정은 구조화된 출력, 시스템 프롬프트, Temperature다. 각각 응답의 데이터 구조, 역할과 지침, 생성 과정의 무작위성을 조절한다. API를 실제 업무에 연결하려면 이 설정뿐 아니라 키 보안, 사용량과 비용, 응답 검증, 오류 처리도 함께 고려해야 한다.

## API의 개념

API는 Application Programming Interface의 약자다. 다른 프로그램의 내부 구현을 몰라도 정해진 규칙에 맞춰 요청하면 기능을 실행하거나 데이터를 받을 수 있다.

식당에 비유하면 다음과 같다.

| 식당의 요소 | 프로그램에서의 의미 |
| --- | --- |
| 손님 | 기능을 요청하는 클라이언트 프로그램 |
| 메뉴와 주문 방식 | 요청할 수 있는 기능과 요청 규격 |
| 주문을 전달하는 직원 | API를 통한 요청·응답 과정 |
| 주방 | 실제 요청을 처리하는 서버 |
| 완성된 음식 | 처리 결과인 응답 |

```text
클라이언트 프로그램 -> 정해진 형식의 요청 -> 서버
클라이언트 프로그램 <- 처리 결과인 응답 <- 서버
```

직원 비유는 동작을 이해하기 위한 것이다. 정확히는 API 자체가 별도의 직원이나 서버라기보다 프로그램 사이의 접점과 사용 규칙을 뜻한다. API에는 같은 컴퓨터 안의 라이브러리 API도 있지만, 이번 강의는 네트워크로 외부 AI 서비스를 호출하는 웹 API를 중심으로 다룬다.

## 여러 API를 조합한 서비스

배달 앱을 만든다고 해서 지도, 결제, 알림, AI 모델을 모두 직접 개발할 필요는 없다.

| API | 배달 앱에서의 활용 |
| --- | --- |
| 지도 API | 주소 검색, 위치 표시 |
| 결제 API | 주문 금액 결제 |
| 알림 API | 주문 완료와 배달 상태 안내 |
| 날씨 API | 현재 날씨 정보 조회 |
| 생성형 AI API | 날씨와 주문 이력을 참고한 메뉴 추천 문구 생성 |

예를 들어 날씨 API에서 비가 온다는 정보를 얻은 뒤, AI API에 전달하면 “비 오는 날에는 따뜻한 국물 요리는 어떠신가요?” 같은 문구를 만들 수 있다. 외부 데이터 조회와 문장 생성은 서로 다른 단계다.

## 웹서비스 이용과 API 호출의 차이

| 구분 | 채팅형 웹서비스 이용 | API 호출 |
| --- | --- | --- |
| 주된 이용 주체 | 사람이 화면에서 사용 | 프로그램이 요청을 전송 |
| 입력과 결과 활용 | 질문 입력 후 답변을 확인하거나 복사 | 입력 수집과 결과 저장을 코드로 연결 |
| 반복 작업 | 사용자의 조작에 의존하기 쉬움 | 일정·이벤트에 따른 자동 실행 가능 |
| 설정 | 서비스 화면에서 제공하는 범위 | API와 모델이 지원하는 매개변수 |
| 활용 예 | 일회성 질문, 초안 작성 | 리뷰 분류, 메일 요약, 서비스 내 챗봇 |

이 구분은 일반적인 사용 방식의 차이다. 웹서비스에도 자동화 기능이 있을 수 있고, API도 호출 한도와 비용 때문에 무제한으로 실행할 수 있는 것은 아니다.

강의에서는 직접 코드를 작성하는 방식 외에 Make, n8n 같은 자동화 도구와 AI에게 코드 작성을 맡기는 바이브 코딩도 소개한다. 후속 강의에서는 이를 업무 자동화와 서비스 제작으로 확장한다.

## 생성형 AI API의 종류

강의에 등장하는 대표적인 제공사와 모델 계열은 다음과 같다. 아래 목록은 전체 제공사를 뜻하지 않는다.

| 제공사 | 개발자 환경 | 강의에서 소개한 모델·기능 |
| --- | --- | --- |
| OpenAI | OpenAI 개발자 플랫폼 | GPT 계열 텍스트 생성, GPT Image 계열 이미지 생성 |
| Google | Google AI Studio, Gemini API | Gemini 텍스트 생성, Nano Banana 이미지 생성, TTS |
| Anthropic | Anthropic Console | Claude 계열 텍스트 생성 |

텍스트를 이해하는 모델이라고 해서 이미지나 음성을 생성할 수 있는 것은 아니다. 입력으로 받을 수 있는 형식과 출력으로 만들 수 있는 형식을 각각 확인해야 한다.

## API 호출의 기본 구성

AI API 호출에서는 인증 정보, 모델, 입력, 생성 설정을 지정하고 응답을 받는다.

| 구성 요소 | 의미 | Gemini 강의 실습의 예 |
| --- | --- | --- |
| API 키 | 요청의 인증과 프로젝트 식별에 사용하는 비밀 값 | 별도 보관한 키 |
| 모델 | 요청을 처리할 모델의 식별자 | 해당 모델의 정확한 API 이름 |
| 사용자 입력 | 질문이나 처리할 데이터 | `contents` |
| 시스템 지시 | 역할, 말투, 작업 규칙 | `system_instruction` |
| 생성 설정 | 출력 형식, 샘플링, 출력 길이 등 | `config` |
| 응답 | 생성 결과와 사용량 등의 정보 | 텍스트, 이미지, 오디오 등 |

이름은 API마다 다르다. 강의의 Gemini `generate_content` 호출 방식에서는 `model`, `contents`, `config`를 사용한다. 다른 API의 코드를 옮길 때는 인자 이름과 응답 구조를 확인해야 한다. [Gemini API 호출 규격](https://ai.google.dev/api/generate-content)

## 답변을 제어하는 세 가지 설정

| 설정 | 조절 대상 | 예 |
| --- | --- | --- |
| Structured Output | 응답의 데이터 구조 | 감정, 별점, 키워드를 정해진 자료형으로 반환 |
| System Prompt | 역할과 지침 | 정중한 존댓말로 두 문장 이내에 답변 |
| Temperature | 다음 토큰 선택의 무작위성 | 같은 입력에서 생성 결과가 달라지는 정도 조절 |

세 가지는 강의에서 집중해서 다루는 설정이며, API 설정이 이 세 가지뿐인 것은 아니다. 출력 길이, 도구 사용, 안전 설정 등도 API와 모델에 따라 제공된다.

## 구조화된 출력

구조화된 출력은 응답을 미리 정의한 스키마에 맞춰 생성하게 하는 기능이다. 스키마는 항목 이름, 자료형, 허용되는 값 등 데이터의 규격을 뜻한다.

리뷰 분석 결과를 다음과 같이 받을 수 있다.

```json
{
  "sentiment": "긍정",
  "estimated_rating": 5,
  "keywords": ["음식", "친절"]
}
```

| 항목 | 자료형·조건 | 의미 |
| --- | --- | --- |
| `sentiment` | 긍정·부정·중립 중 하나 | 리뷰 감정 분류 |
| `estimated_rating` | 1~5의 정수 | 리뷰 내용에서 추정한 점수 |
| `keywords` | 문자열 배열 | 주요 키워드 목록 |

JSON은 데이터를 표현하는 형식이고, JSON Schema는 그 데이터가 따라야 할 규칙이다. 단순히 “JSON으로 답해줘”라고 요청하는 것과 API의 스키마 기능을 사용하는 것은 구분해야 한다.

> 보충: 구조화된 출력은 데이터 처리에 유리한 형식을 제공하지만, 값의 사실성까지 보장하지 않는다. 위의 추정 점수는 고객이 실제로 입력한 별점과도 다르다. 프로그램에서 값의 범위와 업무상 의미를 검증해야 한다. [Google 구조화된 출력 문서](https://ai.google.dev/gemini-api/docs/structured-output)

## 실습: 영화 추천 결과의 구조화

강의에서는 영화 추천을 다음 네 항목으로 받도록 지정한다. 원문의 “총 3가지”는 전사상 오류로 보고 네 가지로 정리한다.

| 항목 | 자료형 | 확인할 내용 |
| --- | --- | --- |
| 제목 | 문자열 | 실제 존재하는 영화인가? |
| 개봉연도 | 정수 | 요청한 기간에 포함되는가? |
| 장르 | 문자열 | 어떤 분류 기준인가? |
| 평점 | 숫자 | 어느 사이트의 언제 기준 평점인가? |

```text
최근 5년 안에 개봉한 한국 영화 3편을 추천해줘.
제목, 개봉연도, 장르, 평점을 지정한 데이터 구조로 반환해줘.
```

이 요청에는 기간과 평점 기준이 모호하다. 실무에서는 개봉일의 시작·종료 날짜, 평점 출처와 조회 기준일을 명시하고, 확인하지 못한 평점은 누락 또는 null로 표현할 수 있도록 스키마를 설계하는 것이 좋다.

강의에서 출력된 특정 평점은 외부 출처가 확인되지 않은 생성 예시이므로 실제 평점으로 암기하지 않는다. 또한 Pydantic으로 `MovieRec` 같은 스키마를 선언한다면 이는 일반적으로 함수가 아니라 데이터 모델 클래스다.

## 시스템 프롬프트

시스템 프롬프트는 모델의 역할과 답변 규칙을 지정하는 지시다. Gemini에서는 System Instruction이라는 표현을 사용한다.

```text
당신은 한국 전통 음식을 전문으로 하는 요리 선생님입니다.
모든 답변은 정중한 존댓말로 두 문장 이내로 작성합니다.
외래어보다 우리말 표현을 우선합니다.
```

이 지시를 적용한 상태에서 “오늘 저녁에 뭐 먹을까요?”와 “간식으로는 뭐가 좋을까요?”를 입력하면 같은 역할과 말투를 유지하도록 유도할 수 있다.

같은 질문도 역할에 따라 설명 관점이 달라질 수 있다.

| 역할 | 기대하는 답변 방식 |
| --- | --- |
| 교수 | 개념, 이론, 참고자료 중심 |
| 현업 개발자 | 실습 순서와 적용 사례 중심 |
| 초등학생 튜터 | 쉬운 표현과 비유 중심 |

시스템 지시는 모델 행동을 유도하지만, 모든 응답에서 규칙 준수를 완벽히 보장하는 장치는 아니다. [Google 텍스트 생성 문서](https://ai.google.dev/gemini-api/docs/text-generation)

## 사실확인: 시스템 지시의 유지와 비용

강의의 “한 번 등록하면 모든 대화에 적용된다”는 설명은 사용 중인 도구가 설정을 유지해 준다는 의미로 이해해야 한다. 일반적인 개별 API 호출에서는 프로그램이 지시를 요청에 포함하거나, 해당 API가 제공하는 상태 관리 방식을 사용해야 한다. 모델이 모든 독립 요청에 걸쳐 지시를 영구 기억하는 것은 아니다. [Gemini 요청의 시스템 지시와 대화 이력](https://ai.google.dev/api/generate-content)

또한 시스템 프롬프트로 분리했다고 입력 토큰 비용이 자동으로 없어지는 것은 아니다. 시스템 지시도 입력 토큰에 포함된다. 반복 입력의 비용 절감은 별도의 캐싱 지원과 적용 조건에 달려 있다. [Google 토큰 계산 문서](https://ai.google.dev/gemini-api/docs/tokens), [OpenAI 공식 Prompt Caching 문서](https://developers.openai.com/api/docs/guides/prompt-caching)

```text
지시를 한 곳에서 관리 -> 코드와 프롬프트 관리가 쉬워짐
시스템 지시로 전달 -> 자동으로 무료가 되는 것은 아님
캐싱 조건 충족 -> 제공사 정책에 따라 비용 절감 가능
```

## Temperature

Temperature는 모델이 다음 토큰을 선택하는 확률 분포를 조절하는 설정이다. 토큰은 모델이 처리하는 단위로, 단어 하나와 항상 일치하지는 않는다.

| 설정 경향 | 일반적인 효과 | 주의점 |
| --- | --- | --- |
| 낮게 설정 | 확률이 높은 후보를 선택하는 경향이 강해짐 | 정답이나 완전한 재현성을 보장하지 않음 |
| 높게 설정 | 상대적으로 확률이 낮은 후보도 선택될 가능성이 커짐 | 내용이 산만하거나 일관성이 떨어질 수 있음 |

강의에서는 “여행 인사말 한 줄 만들어줘”라는 동일한 질문으로 결과를 비교한다. 낮은 값에서는 흔한 인사말이, 높은 값에서는 비유적인 표현이 나올 수 있지만, 특정 문장이 반드시 나온다는 뜻은 아니다.

> 정정: Temperature는 말투만 바꾸는 설정이 아니다. 선택되는 토큰이 달라지면 답변의 내용과 결론도 바뀔 수 있다. 또한 0으로 설정해도 항상 같은 결과가 나온다고 보장할 수 없다. 허용 범위와 기본값은 사용하는 모델의 규격을 확인해야 한다. [Gemini 생성 설정](https://ai.google.dev/api/generate-content)

정확성이 중요한 작업이라고 무조건 0을 선택하거나, 창작 작업이라고 무조건 최대값을 선택하기보다 모델의 기본 설정에서 시작해 실제 작업 결과를 비교하는 것이 좋다. 사실 정확성은 출처 확인과 결과 검증으로 별도로 평가해야 한다.

## API 키의 역할과 관리

API 키는 강의 실습에서 서비스 접근에 사용하는 비밀 인증 정보다.

| 역할 | 설명 |
| --- | --- |
| 식별 | 요청이 속한 프로젝트 등을 구분 |
| 인증·접근 통제 | 키의 유효성과 허용된 접근 확인 |
| 사용량 추적 | 관련 프로젝트의 사용량·할당량·과금 관리에 활용 |

키를 발급받은 사람의 개인 계정에만 비용이 묶인다고 일반화할 수는 없다. Gemini API 키는 Google Cloud 프로젝트와 연결되고, 과금은 프로젝트의 결제 설정에 영향을 받는다. API 인증 방식도 서비스에 따라 키 외의 방식이 존재한다. [Google API 키 문서](https://ai.google.dev/gemini-api/docs/api-key)

키를 관리할 때는 다음을 지킨다.

1. 코드에 실제 키를 직접 적지 않고 보안 비밀 저장소나 환경변수로 분리한다.
2. GitHub, 블로그, 화면 캡처, 실행 로그에 키가 포함되지 않도록 확인한다.
3. 브라우저에 배포하는 프런트엔드 코드에 비밀 키를 넣지 않는다.
4. 키가 노출되면 해당 키를 폐기하고 새 키를 발급받는다.
5. 가능한 키 제한을 적용하고 사용량을 확인한다.

별도 파일로 옮기는 것만으로 안전해지는 것은 아니다. 그 파일을 함께 공개하거나 키를 출력하면 여전히 유출될 수 있다. [Google API 키 보안 지침](https://ai.google.dev/gemini-api/docs/api-key)

## 보충: 토큰과 API 비용

텍스트 API 비용은 보통 입력 토큰과 출력 토큰을 구분해서 계산한다. 입력에는 질문뿐 아니라 시스템 지시, 전달한 대화 이력과 참고 자료도 포함될 수 있다. [Google 토큰 계산 문서](https://ai.google.dev/gemini-api/docs/tokens)

```text
기본적인 텍스트 호출 비용
= 입력 토큰 수 × 입력 단가
+ 출력 토큰 수 × 출력 단가
```

실제 청구에는 모델별 캐싱, 추론 토큰, 도구 사용 등의 조건이 추가될 수 있다. 이미지·오디오도 텍스트와 과금 기준이 같다고 가정하면 안 된다. 무료 사용 범위, 유료 전환 조건, 모델별 요금은 실행 전에 확인한다. [Gemini API 요금표](https://ai.google.dev/gemini-api/docs/pricing)

## 실습 도구: Google AI Studio와 Colab

| 도구 | 역할 | 강의에서 하는 일 |
| --- | --- | --- |
| Google AI Studio | 웹에서 모델과 프롬프트를 시험하는 환경 | 모델 선택, 지시와 생성 설정 변경, API 키 발급 |
| Google Colab | 브라우저에서 Python 코드를 실행하는 노트북 환경 | API 호출 코드를 셀 단위로 실행 |

```text
AI Studio에서 설정 실험
-> API 키 발급
-> Colab 보안 비밀에 저장
-> SDK 준비
-> 코드로 모델 호출
-> 결과 확인
```

SDK는 API를 언어별 코드에서 편리하게 호출하도록 돕는 개발 도구 모음이다. 강의에서 사용하는 Python 패키지 이름은 `google-genai`다. 화면의 메뉴 위치와 지원 모델은 변경될 수 있다. [Google 시작 가이드](https://ai.google.dev/gemini-api/docs/get-started)

## 실습: AI Studio에서 설정 비교

1. 텍스트 생성 모델을 선택한다.
2. 같은 질문으로 시스템 지시가 있을 때와 없을 때의 답변을 비교한다.
3. 구조화된 출력을 지원하는 모델에서 영화 추천 스키마를 지정한다.
4. Temperature를 지원하는 모델에서 값을 바꾸고 결과를 여러 번 비교한다.
5. 이미지·음성 생성 모델로 바꿔 입력과 출력의 차이를 확인한다.

Temperature만 비교하려면 모델, 질문, 시스템 지시, 대화 이력 등 다른 조건을 동일하게 맞춰야 한다. 한 번의 출력만으로 특정 설정이 항상 더 좋다고 결론 내리지는 않는다.

## 실습: Colab에서 API 호출 준비

강의의 준비 순서는 다음과 같다.

1. AI Studio에서 프로젝트를 선택하거나 생성하고 API 키를 발급받는다.
2. Colab의 보안 비밀에 `GEMINI_API_KEY`라는 이름으로 키를 저장한다.
3. 해당 노트북에서 보안 비밀에 접근할 수 있도록 허용한다.
4. `google-genai` 패키지를 설치한다.
5. 코드에서 이름으로 키를 읽어 클라이언트를 생성한다.

```text
보안 비밀의 이름: GEMINI_API_KEY
보안 비밀의 값: 실제 발급받은 키
코드에서 참조하는 이름: GEMINI_API_KEY
```

보안 비밀을 사용해도 읽어 온 값을 출력하거나 외부로 전송하는 코드를 실행하면 유출될 수 있다. 노트북 공유 전에는 코드뿐 아니라 셀의 출력도 확인한다.

## 실습: 텍스트 생성과 역할 변경

기본 호출에서 먼저 확인할 부분은 모델 이름과 입력 내용이다.

```text
모델: 사용 가능한 텍스트 생성 모델의 API 식별자
입력: 인공지능이란 무엇인지 한 문장으로 설명해줘.
결과: 프로그램에서 응답 텍스트 확인
```

이후 사용자 입력은 유지하고 시스템 지시만 바꾸면 역할의 영향을 비교할 수 있다.

```text
사용자 입력: 머신러닝을 처음 배우려면 어떻게 해야 해?

시스템 지시 A: 교수의 관점에서 개념과 학습 순서를 설명해줘.
시스템 지시 B: 현업 개발자의 관점에서 실습 중심으로 설명해줘.
시스템 지시 C: 초등학생도 이해할 수 있는 비유로 설명해줘.
```

텍스트 생성이 동작하면 구조화된 출력 설정을 추가해 영화 추천처럼 여러 항목으로 된 데이터를 받아본다. 핵심은 코드 전체를 외우기보다 모델, 입력, 지시, 출력 규격이 각각 어디에 들어가는지 구분하는 것이다.

## 실습: 이미지 생성과 음성 생성

강의에서는 다음 모델과 입력을 사용한다.

| 구분 | 강의의 모델·설정 | 입력 예 |
| --- | --- | --- |
| 이미지 생성 | Gemini 2.5 Flash Image | 한국 전통 한옥 마당의 매화꽃, 봄날 오후의 따뜻한 햇살, 사진 스타일 |
| 음성 생성 | Gemini 3.1 Flash TTS Preview, 음성 옵션 Kore | 안녕하세요. 오늘은 봄꽃이 만개한 좋은 날입니다. |

이미지 모델의 API 식별자는 `gemini-2.5-flash-image`이며, Nano Banana라는 이름으로 소개된 모델이다. 현재는 Nano Banana 계열에 여러 모델이 있으므로 표시 이름만 보고 모델을 정하지 않는다. [Google 이미지 생성 문서](https://ai.google.dev/gemini-api/docs/image-generation)

음성 모델의 정확한 표기는 `gemini-3.1-flash-tts-preview`다. 음성 옵션은 `KORE`가 아닌 `Kore`로 표기한다. 이는 미리 제공되는 합성 음성 옵션의 이름으로, 실제 성우의 신원이나 성별을 뜻하는 이름은 아니다. [Google TTS 문서](https://ai.google.dev/gemini-api/docs/speech-generation)

> 보충: 텍스트·이미지·음성 API는 호출의 큰 흐름은 비슷하지만, 모델 이름만 바꾸면 모든 코드가 그대로 작동하는 것은 아니다. 출력 형식 설정과 이미지·오디오 데이터의 저장·재생 처리가 달라진다. Preview 모델과 기존 모델은 실행 시점의 제공 여부도 확인한다.

## OpenRouter의 역할

OpenRouter는 여러 제공사의 모델을 하나의 API 인터페이스로 사용할 수 있게 연결하는 서비스다. 하나의 OpenRouter 키로 해당 서비스가 지원하는 모델을 호출할 수 있다.

| 구성 | 직접 제공사 API 이용 | OpenRouter 이용 |
| --- | --- | --- |
| 접속 대상 | 각 제공사의 API | OpenRouter API |
| 키 | 각 제공사에서 발급 | OpenRouter에서 발급 |
| 모델 선택 | 제공사별 모델 식별자 | OpenRouter 모델 식별자 |
| 활용 | 특정 제공사의 기능을 직접 사용 | 여러 제공사 모델을 공통 형식으로 비교·호출 |

OpenAI SDK를 사용할 수 있지만, 처음 연결할 때는 OpenRouter의 키와 `base_url`도 설정해야 한다. 그 이후 지원되는 모델 사이에서 모델 식별자를 바꿔 호출할 수 있다. 모든 모델과 모든 기능이 동일하게 지원되는 것은 아니다. [OpenRouter 공식 시작 가이드](https://openrouter.ai/docs/quickstart)

## 실습: 여러 모델의 답변 비교

강의에서는 같은 나들이 추천 질문을 서로 다른 세 모델에 보낸다.

```text
                    -> 모델 A -> 답변 A
동일한 사용자 입력 -> 모델 B -> 답변 B
                    -> 모델 C -> 답변 C
```

한 화면에서 실행하더라도 모델별 생성 작업과 사용량은 구분된다. 비교할 항목은 다음과 같다.

| 비교 기준 | 확인할 내용 |
| --- | --- |
| 정확성 | 장소와 정보가 실제로 맞는가? |
| 질문 적합성 | 사용자가 제시한 조건을 반영했는가? |
| 표현 방식 | 길이, 어조, 구성은 적절한가? |
| 응답 시간 | 필요한 시간 안에 결과를 받는가? |
| 사용량 | 결과 품질에 비해 비용이 적절한가? |

강의에서 특정 모델이 먼저 응답한 것은 해당 시연의 결과다. 응답 시간은 모델 외에도 출력 길이, 추론량, 서버 상태 등에 영향을 받으므로 고정된 속도 순위로 외우지 않는다.

## 실습: Fusion을 통한 답변 통합

강의의 Fusion 시연은 질문을 다듬고, 여러 모델의 답변을 받은 다음, 비교·분석해 최종 답변을 구성하는 흐름이다.

```text
질문 정제 -> 여러 모델 호출 -> 답변 비교·분석 -> 최종 답변 통합
```

강의에서는 공통 의견, 의견 차이, 일부 모델이 다룬 항목, 고유한 관점, 누락된 내용을 비교한다. 이는 강의 화면의 처리 흐름이며, 모든 Fusion 호출이 항상 같은 단계와 호출 수로 실행된다는 뜻은 아니다.

공식 문서에서도 Fusion을 여러 모델의 결과를 비교하고 종합하는 방식으로 설명한다. 다만 추가 호출에 따른 비용과 지연이 발생할 수 있고, 품질 향상 정도는 작업에 따라 다르다. 여러 모델이 같은 오류를 낼 수도 있으므로 의견 일치 자체를 사실확인의 근거로 삼아서는 안 된다. [OpenRouter Fusion 설명](https://openrouter.ai/blog/insights/fusion-explainer/)

## 보충: 업무 자동화와 오류 처리

API를 호출할 수 있으면 기존 업무 사이에 AI 처리 단계를 넣을 수 있다.

```text
이메일 수신 -> AI 요약·분류 -> 결과 검증 -> 담당자 배정 또는 저장
```

AI가 생성한 문장이 실제 메일 발송이나 데이터베이스 저장을 자동으로 실행하는 것은 아니다. 프로그램이나 자동화 도구가 응답을 읽고 후속 API를 호출하도록 연결해야 한다.

실제 운영에서는 성공한 응답뿐 아니라 실패도 처리해야 한다.

| 상황 | 확인하거나 처리할 내용 |
| --- | --- |
| 잘못된 요청 | 필수 입력, 자료형, 지원하지 않는 설정 확인 |
| 인증·권한 오류 | 키와 프로젝트의 접근 권한 확인 |
| 요청 한도 초과 | 호출 빈도 조절, 대기 후 제한된 횟수로 재시도 |
| 서버 장애 | 일정 간격을 두고 재시도하며 실패 기록 |
| 응답 차단·빈 결과 | 완료 상태를 확인하고 후속 작업 중단 또는 대체 처리 |
| 구조는 맞지만 값이 틀림 | 사실과 업무 규칙을 검증한 뒤 사용 |

재시도를 무한 반복하면 비용과 부하가 늘 수 있으므로 횟수와 대기 시간을 제한한다. [Google API 문제 해결 가이드](https://ai.google.dev/gemini-api/docs/troubleshooting)

## 정리

생성형 AI API는 AI 기능을 내가 만든 프로그램과 업무 흐름에 연결하는 수단이다. 구조화된 출력은 데이터의 규격을, 시스템 프롬프트는 역할과 지침을, Temperature는 생성 과정의 무작위성을 조절한다.

AI Studio에서 설정을 실험하고 Colab에서 호출 흐름을 익히면, 이후 자동화 도구나 서비스 개발에도 같은 개념을 적용할 수 있다. 다만 구조화된 출력이나 낮은 Temperature가 사실 정확성을 보장하지 않으며, 시스템 지시 역시 입력 비용에서 자동으로 제외되지 않는다. 결과 검증과 키·비용 관리까지 포함해야 안정적으로 활용할 수 있다.
