# 5강. 프롬프트 엔지니어링과 컨텍스트 엔지니어링

- 학습일: 2026-08-20
- 과목: AI네이티브가되기위한기초소양
- 주제: LLM 생성 원리, 프롬프트 작성 기법, 컨텍스트 설계

## 핵심 요약

LLM은 누적된 문맥을 바탕으로 다음 토큰의 확률을 계산하며 텍스트를 생성한다. 답변 품질은 생성 파라미터와 프롬프트에 의해 크게 달라진다. 일회성 질문을 잘 설계하는 것은 프롬프트 엔지니어링이고, 반복 업무를 위해 지시, 지식, 예시, 도구를 작업 환경으로 묶는 것은 컨텍스트 엔지니어링이다.

## 생성 파라미터

생성 파라미터는 같은 프롬프트에 대해 답변이 어떤 방식으로 생성될지를 조정하는 설정값이다.

| 파라미터 | 의미 | 활용 |
| --- | --- | --- |
| Temperature | 답변의 무작위성과 다양성 조절 | 낮으면 일관적, 높으면 창의적 |
| Top-K | 확률이 높은 상위 K개 토큰만 후보로 사용 | 후보 개수를 고정 |
| Top-P | 누적 확률이 P에 도달할 때까지 후보로 사용 | 확률 분포에 따라 후보 수가 달라짐 |

정확성이 중요한 계약서 검토나 코드 생성에는 낮은 Temperature가 적합하고, 마케팅 카피나 스토리 작성처럼 창의성이 필요한 작업에는 상대적으로 높은 Temperature가 유용하다.

## 프롬프트의 구성 요소

프롬프트는 AI에게 작업을 지시하는 입력이다. 좋은 프롬프트는 보통 다음 요소를 포함한다.

| 요소 | 의미 |
| --- | --- |
| 지시 | 무엇을 수행해야 하는지 |
| 예시 | 원하는 결과물의 패턴 |
| 맥락 | 누가, 왜, 어떤 상황에서 필요한지 |

프롬프트가 모호하면 답변도 일반적이 되고, 구체적이면 결과의 방향과 품질을 더 잘 통제할 수 있다.

## 프롬프트 엔지니어링 기법

### 1. 명확하고 구체적인 지시

무엇을, 어떤 형식으로, 어느 수준까지 생성할지 분명하게 지정한다. 예를 들어 회의록 요약을 요청할 때는 핵심 결론, 액션 아이템, 담당자, 마감일처럼 필요한 항목을 명시하는 것이 좋다.

### 2. 예시 제시

프롬프트 안에 원하는 입력과 출력의 예시를 제공하면 모델이 패턴을 따라 작업한다.

| 방식 | 의미 |
| --- | --- |
| Zero-shot | 예시 없이 지시만 제공 |
| One-shot | 예시 1개 제공 |
| Few-shot | 예시 2개 이상 제공 |

특수한 판단 기준이나 고정된 출력 형식이 필요할 때 Few-shot 방식이 특히 효과적이다.

### 3. 풍부한 맥락 제공

사용자의 상황, 목적, 제약 조건을 알려주면 더 적합한 답변을 얻을 수 있다. 예를 들어 공부법을 물을 때 시험까지 남은 기간, 학습량, 원하는 전략을 함께 전달하면 현실적인 계획을 받을 수 있다.

### 4. 출력 형식 지정

표, 목록, JSON, 보고서 형식 등 원하는 결과물의 구조를 명시한다. 업무에서 바로 활용해야 하는 결과물일수록 출력 형식을 구체적으로 지정하는 것이 중요하다.

### 5. 페르소나 부여

AI에게 특정 역할을 부여하면 해당 역할에 맞는 관점과 표현을 사용할 가능성이 높아진다. 예를 들어 면접관, 영어 튜터, 마케팅 컨설턴트, 임상영양사 같은 역할을 줄 수 있다.

## 프롬프트 개선 사이클

좋은 프롬프트에는 정답이 하나로 정해져 있지 않다. 작업 목적에 맞게 반복적으로 개선해야 한다.

1. 설계: 목표, 조건, 예시, 평가 기준을 정한다.
2. 실험: 프롬프트를 실제로 입력해 결과를 확인한다.
3. 평가: 원하는 답변인지, 부족한 부분은 무엇인지 분석한다.
4. 개선: 프롬프트를 수정하고 다시 실험한다.

## 컨텍스트 엔지니어링

프롬프트 엔지니어링이 한 번의 대화에서 질문을 잘 설계하는 일이라면, 컨텍스트 엔지니어링은 반복적으로 사용할 작업 환경을 설계하는 일이다.

컨텍스트에는 다음 요소가 포함될 수 있다.

| 요소 | 의미 |
| --- | --- |
| 지시 | LLM이 따라야 할 역할과 규칙 |
| 지식 | 참고해야 할 문서, 매뉴얼, 기준표 |
| 예시 | 원하는 결과물의 샘플 |
| 도구 | 외부 서비스나 파일, API와의 연결 |

예를 들어 채용 평가 업무에서는 직무기술서, 평가 기준표, 출력 양식, 이력서 저장 위치를 프로젝트에 미리 등록해두면 매번 같은 기준으로 평가할 수 있다.

## MCP의 필요성

LLM이 Gmail, Google Drive, Calendar 같은 외부 도구와 연결되려면 각 서비스와 상호작용하는 방법이 필요하다. MCP는 이런 연결 방식을 표준화해 LLM이 다양한 업무 도구와 일관된 방식으로 연동할 수 있게 한다.

## 추론 모델을 위한 프롬프트

기존에는 `단계별로 생각해줘`처럼 사고 과정을 유도하는 프롬프트가 자주 사용되었다. 하지만 추론 모델은 내부적으로 추론 과정을 수행하므로, 사고 과정을 길게 요구하기보다 목표, 제약 조건, 필요한 정보, 출력 형식을 명확하게 전달하는 것이 중요하다.

## 정리

LLM을 잘 활용하려면 프롬프트를 한 번 잘 쓰는 것에서 그치지 않고, 반복 가능한 작업 환경을 설계해야 한다. 명확한 지시와 충분한 맥락, 적절한 예시, 필요한 도구 연결이 결합될 때 AI의 답변 품질과 업무 활용성이 높아진다.
